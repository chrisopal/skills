# 事实、完成状态与限制的编辑保真

## 三份内容分开保存

读者正文负责讲解；章内提示负责说明当前操作的限制；实操记录负责记录版本、材料、实际动作和验证方式。三者可以互相引用，但不能互相冒充。

## 修改前后核对

对承载事实或约束的句子记录：主体、动作、对象、时间、数字、条件、范围、归因、否定、完成状态。

举例：
- “未在 Windows 上重走安装向导”不能改成“支持 Mac 与 Windows 的实测安装教程”。
- “在 LibreOffice 渲染中查看”不能改成“已在 Microsoft PowerPoint 中逐页检查”。
- “文件解码通过，听感另行判断”不能改成“音质验收通过”。
- “仅展示定时任务表单，未创建计划”不能改成“已经配置自动执行”。
- “本地运行”不能改成“已经证明没有联网”。

上述例子来自用户来稿中的状态表述，未由本次编辑独立核实。

## 限制放在哪里

| 信息 | 建议位置 | 是否可直接删去 |
| --- | --- | --- |
| 练习应先用合成或获准使用的材料 | 阅读指南及首次相关操作之前 | 否 |
| 某功能需要额外权限或可能产生费用 | 使用该功能之前 | 否 |
| 某扩展路线尚未实操 | 该路线标题附近或章首状态提示 | 否 |
| 具体模型、软件版本、核对日期 | 简短环境说明及详细记录 | 可移位，不可假装无差异 |
| 某轮重跑耗时、文件指纹、截图裁剪细节 | 章末或配套记录 | 可移位，必要信息仍须可查 |
| 同一条一般提醒反复出现 | 留在最合适位置，其他处简要引用 | 可合并重复，不能丢掉例外 |

## 尚未完成的书稿

不能仅靠一篇流畅的前言掩盖教程尚未演示的事实。示范重写只代表文字编辑；出版前仍应在对应章节落实状态标识和资料补充。

如果只能拿到节选，记录“根据作者提供的节选”；不要据此断言整本书的所有案例已经实操，或推断没有记录的章一定未完成。

## 外部核验

需要核验时优先查软件官方文档、发布记录和对应时间的案例证据。搜索结果不是亲测记录，最新版本也不替代历史运行证据。无法核实的事项独立列出，不把整页免责声明塞回前言。
