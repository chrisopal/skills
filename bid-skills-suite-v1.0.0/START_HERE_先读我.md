# 先读我：如何开始用这17个Skill

## 你不需要先部署独立投标系统

把技能安装到支持读取技能目录的通用智能体，或先用“手动读取SKILL.md”的方式验证工作流。项目原件、企业素材和每步结果保存到一个你能控制的项目文件夹。

## 方式一：整套本地目录

解压后保留`skills/`、`profiles/`、`scripts/`和`registry.json`。按宿主文档配置技能发现目录，使其发现`skills/`下的17个子目录；不要把套件根README误当SKILL.md。

如果宿主会把技能复制到独立安装目录，请使用每个技能自带的references、assets和scripts，不要只复制SKILL.md。规则配置放进具体项目的profiles目录作为显式输入。整体工具仍可从解压后的scripts目录运行。

### 本机 Codex 安装

从套件根目录运行以下命令，将17个技能目录链接到 Codex 技能目录。已有同名技能时命令会停止，不覆盖现有安装；链接安装要求保留本套件的原路径。

```bash
mkdir -p "${CODEX_HOME:-$HOME/.codex}/skills"
for skill in skills/bid-*; do
  target="${CODEX_HOME:-$HOME/.codex}/skills/${skill##*/}"
  if [ -e "$target" ] || [ -L "$target" ]; then echo "已存在：$target" >&2; exit 1; fi
done
for skill in skills/bid-*; do
  ln -s "$PWD/$skill" "${CODEX_HOME:-$HOME/.codex}/skills/${skill##*/}"
done
```

重新打开 Codex 会话后，按 `bid-orchestrator` 或目标单项技能触发。技能目录被发现仅证明安装；用真实任务前仍需验证脚本、模型理解与人工确认链。Python 辅助脚本要求3.10+，依赖按`requirements-core.txt`或`requirements.txt`安装到隔离环境。

## 方式二：逐个导入

进入`installable-zips/`，按宿主支持的文件夹或ZIP导入功能逐个导入。每个ZIP只含一个技能目录，名称与SKILL.md的name一致。不承诺所有宿主使用同样的菜单或能够一次批量导入。

源码有修改后，先运行 `python scripts/refresh_distribution.py` 重建本地ZIP和校验清单，再运行 `python scripts/check_suite.py` 确认ZIP与源码一致。

建议先装：总控、资料解析、项目画像、需求、评分、合规和格式提取；完整编标则导入全部17个。单技能也可使用，但必须给它必要资料或等价上游结果。

## 方式三：没有原生Skill安装功能

在同一次任务中提供目标SKILL.md及其必要参考文件，请智能体照流程完成并保存输出。这个方式叫“按技能规程执行”，不应声称已安装原生技能。纯聊天不能可靠地保证持久化状态、脚本运行或自动导出。

## 第一条可以直接复制的指令

遇到扫描文件先配置 [PaddleOCR 服务](docs/OCR_SETUP.md)；准备企业方案、案例和产品资料时使用 [项目知识与 Wiki](docs/KNOWLEDGE.md)。可使用本地文件或宿主实际开放的知识检索工具，不要求另建知识库服务。API Key 放在宿主环境，不保存在项目文件或 Git。

> 请使用投标编制总控技能。先读取我提供的项目文件夹和原件，只完成资料整理、项目画像、需求、评分、资格否决和强制格式提取。不要立即编写整本标书。每项结论保留原文来源，缺附件或有冲突时列待确认。将JSON与可读报告写入项目目录，最后给出需要我确认的事项。

确认理解后，再说：

> 基于已确认的理解结果，继续响应策划、目录规划和企业证据匹配。只使用我提供且授权的企业资料。缺资质、型号、报价或实施资源时保持缺口，不补造。先给方案决策包，待确认后再编写正文。

最终交付前：

> 对当前版本做综合评审。整改采用提案方式，不覆盖我的新修改。评审输入有变更就重核。生成实际Word/PDF后，分别检查文本与逐页视觉；不要代签、盖章或自动递交。

## 初学者的三个确认点

第一，确认招标理解与附件关系；第二，确认方案、证据与所有关键承诺；第三，确认实际成稿和交付范围。期间可以继续细化，但不能用“AI说通过”替代这三个确认。
