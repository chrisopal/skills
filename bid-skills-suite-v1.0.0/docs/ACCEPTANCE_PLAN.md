# 技能套件验收与迭代

## 工程层（本次可执行）

检查17个SKILL.md前置YAML、命名、长度和本地链接；校验17份Schema、17个空模板和17个合成输出；检查样例source哈希、原文quote和上游inputs哈希；执行初始化、来源登记、快照、评分树、目录覆盖、源文件变更与输出打包的正反例测试。文档工具单独做实际生成、转换和渲染检查。

## 模型／业务层（需要实际宿主与项目）

每个技能tests/cases.json提供6类场景，共102条评测描述：正例、缺输入、来源冲突、文档指令注入、跨领域与专项陷阱。这些描述不是已运行的模型测试。评估时保留模型、提示词版本、工具、原件、执行轨迹、输出与人工真值。

关注需求／强制条件／评分漏项、错误提取、原文锚点准确、证据适用、目录覆盖、承诺夸大、文档保真和不必要人工反复。不同指标分别统计，不用一个“通过率”掩盖否决风险。

## 首批真实验证建议

先用一个智能工厂和一个设备供货项目，只验证01—09，确认理解和证据。再将经批准方案展开成正文并完成实际DOCX/PDF检查。规则包扩展到工程或服务时增加相应真实样本，不因结构相同就宣称专业正确。

更换模型、宿主、OCR、字体或模板都应重复相应回归。业务通过需同一版本完整证据，不能把不同代码版本、不同模型运行和不同文件的成功结果拼接。

## 修订方法

把失败原因写回对应技能的常见陷阱或专项手册；重复性计算／检查优先固化为小脚本；如果只改变行业关注点就改领域包。不要把每次单项目特例扩成新技能，更不要把提示词越写越长当作质量提升。
