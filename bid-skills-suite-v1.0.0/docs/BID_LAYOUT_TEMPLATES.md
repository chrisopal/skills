# 投标文件版式模板与来源

检索日期：2026-10-07。模板服务于投标文件编排；不认证法律适用、评分、废标或正式交付。

## 依据与适用范围

投标人按项目招标文件编制并响应实质性要求；招标文件的有效澄清、修改也是组成部分。因此先读原件及补遗，再决定版式，不能用通用模板覆盖固定格式。[《招标投标法》第23、27条，市场监管总局](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/bgt/art/2023/art_1f79dd79321441a0831f3aed697b4535.html)。

GB/T 9704-2012《党政机关公文格式》在国家平台标为推荐性、现行，2025-05-30复审结论为继续有效；它的对象是公文，并非所有投标文件。不要将该标准直接设为通用标书的强制模板。[全国标准信息公共服务平台](https://std.samr.gov.cn/gb/search/gbDetailed?id=lOIe27f77QU%3D&mode=p)。

该公文标准一般采用3号仿宋正文、2号小标宋标题、自然段左空二字，版心按公文行字数组织。它没有建立全国统一的投标文件“小四宋体、1.5倍行距”规则，也不能从它推导出标书一律固定28磅行距。[甘肃省交通建设质量安全造价中心转载标准](https://www.gsjtzj.com.cn/info/1049/1535.htm)。

真实项目的要求会不同：河南一个工程磋商项目的技术暗标规定标题及正文小四宋体、1.5倍行距、四边2.5厘米、左对齐、首行两字符、段前后无空行，并禁止目录、页眉页脚、页码和加粗。这仅适用于该项目的技术暗标部分。[河南政府采购网采购文件，PDF第25页/页脚24](https://xinzheng.zfcg.henan.gov.cn/cmsweb81e27e/nas/webfile2024/jiyuan/rootfiles/2025/04/16/f43a8085b4074168a68327f0566ac8a4.pdf)。

海门2022年一个项目则要求技术标A4横向、正文四号宋体、1.5倍行距，封面一号宋体。这是历史项目样例，说明需按文件部分识别，不是当前通用规范。[海门区政府招标文件](https://www.haimen.gov.cn/hmszsb/fscg/content/2f66b3d4-93e1-4869-81e1-14443fb24335.html)。

未找到适用于所有投标文件的统一字体、字号及段落强制标准。以下参数是可选择的编辑默认值，不是国家规定。

## 通用技术投标候选模板

源文件：`assets/layout-templates/general-bid-v1.json`。它同时含可执行样式、候选章节骨架和逐项响应表；基础生成器可直接读取。普通明标未规定样式时可用于候选工作稿。暗标及固定表不能未经核对直接采用。

| 项目 | 默认值 | 作用 |
|---|---|---|
| 纸张与页边距 | A4纵向，四边2.5厘米 | 正文宽16厘米；客户要求优先 |
| 中文正文 | 宋体、小四/12pt | 标题、表格有独立样式 |
| 西文与数字 | Times New Roman | 客户规定全篇同一字体时同步覆盖 |
| 正文行距 | 1.5倍 | 倍数与固定磅值不能互换 |
| 叙述段 | 首行2字符、两端对齐 | 按12pt计缩进24pt；实际渲染复核 |
| 正文段前/段后 | 0pt/0pt | 连续自然段不插空白段 |

小四是12pt，四号14pt，三号16pt，二号22pt，一号26pt。模板存pt数值；用户字号名转换后再核对实际Word与PDF。字体名称不代表字体已安装或许可已核验。

本机未检测到SimSun：DOCX设置正确，但初次PDF嵌入的是ArialUnicodeMS。另提供`general-bid-macos-preview-v1.json`，将宋体/黑体映射到本机已安装的中文族名宋体-简/黑体-简（Songti SC/Heiti SC），用于macOS候选预览；记录映射并检查PDF字体。实际探针确认使用中文族名后PDF嵌入STSongti-SC-Regular/Bold；英文族名在本机LibreOffice中仍发生替换。跨宿主通用模板仍保留SimSun/SimHei。项目明确要求某个字体文件时不擅自换用；正式交付必须在实际导出环境核验字体与嵌入结果。

## 项目覆盖与交接

06先定位文字、字号、行距、缩进、段间距、纸张、分册、暗标和固定表要求的适用范围。14读取模板，使用`assets/layout-templates/tender-style-override.template.json`记录原文规则ID、页码、覆盖前后值、输入版本/哈希，保存项目`work/effective-layout.json`及最终document-spec。缺失参数使用候选默认并列明，冲突或无法实现的规则保留待处理。

“投标文件全篇宋体、小四、1.5倍行距”不能被擅自缩成“仅正文”：封面标题、副标题、三级标题、表格、图注、页眉页脚等也要核对与覆盖；若原文另列例外，按相应范围处理。不能为了美观放大标题或缩小表格。

`build_docx.py`的`style`支持模板列出的正文、西文字体、缩进、对齐、段前后距、三级标题字号/字体/段间距、标题副标题字号、表格/图注字号和四边页边距。未知字段、无效数字、布尔数字和越界表宽拒绝生成；图片宽度受当前正文宽度限制。页数与图片页高仍须实际渲染检查。

```bash
python scripts/build_docx.py --spec assets/layout-templates/general-bid-v1.json --out /absolute/project/deliverables/layout-template-draft.docx --asset-root /absolute/project
```

基础生成器始终保留工作稿说明和页眉页脚，不是正式标书模板保真工具。暗标若禁止这些内容、要求横向、固定行字数或特殊编号等，必须交宿主可编辑文档工具落实并验证；此时不能用基础脚本输出宣称满足。16正式导出前还要清除模板提示和内部工作标记，核对采纳、固定格式、目录域、附件及签署要求。

## 实际验证

先读回DOCX样式和实际段落：正文2字符缩进，标题/表格/图注不跟随缩进，段前后距与行距正确，没有用空行制造间距。再逐页渲染检查字体替换、断行、孤标题、表头、裁切、空白页、图片和图注。源模板成功加载或结构测试通过不替代最终文件验收。

生成器清除与明确字体竞争的主题字体属性，并同步复杂脚本字号；这是避免模板主题覆盖显式字体的实现约束，仍须验证实际引擎。[Microsoft Open XML字体说明](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/aef3c9a6-5d6c-434b-90b7-85e761fd8e62)。

## 整本目录的实际引擎验证

整本标书采用可更新的TOC/PAGEREF域。更新域后在实际交付引擎保存Word并导出PDF，逐项核对目录和评分索引。原生Word与LibreOffice可以有不同页数，必须分别验证内容完整性；不能将跨引擎页码差异当作内容丢失，也不能交付沿用旧引擎页码的静态目录。标题定位按章节顺序，排除正文中相同名称的引用。
