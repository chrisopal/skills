# 统一产物契约与身份

## 文件约定

所有技能输出采用统一信封加专项data。Schema与模板逐技能自包含。修改需要新revision；artifact_id标识一个业务产物，revision标识其版本。默认简单文件系统只适合单写入者或明确协调的多人流程，不具有数据库事务、多租户隔离或不可篡改审计。

01—14存artifacts，15存reviews，16存deliverables，17存work。原件放inputs，配图放assets，实际配置放profiles。不要让大批内部日志、凭据、聊天和原始资料进入最终deliverables。

## 推荐ID

SRC原件、BLOCK原文块、R需求、S评分、C资格／否决／提交、F格式、Q澄清、DEC业务决策、SEC章节、M素材、SEL选用、D方案决策、CH正文提案、FORM表单、FIG配图、FIND评审发现、ART产物。

目录序号可以变化，稳定ID不要随重排重置。示例为合成演示，真实ID由项目内唯一分配。引用保留source_id、revision、sha256、location、quote、kind；Hash对应实际字节而非模型猜测。

## 状态

| 状态 | 含义 |
|---|---|
| draft | 正在整理，不承诺可用 |
| needs_review | 已形成结果，需要核验／确认 |
| blocked | 缺前置、证据或存在关键问题 |
| ready | 当前职责范围可供下游使用，不等于人工签批 |
| stale（仅总控阶段） | 输入变化，原产物需要重核 |

未知不是空字符串猜值；支持null的字段用null。空数组本身不证明没有要求。无法完整读取原文时保持范围限制，不能把部分解析投射为整体不存在。

## 输入与评审身份

每次技能运行将实际输入文件的相对路径、版本和SHA256写入inputs。通用工具的snapshot对inputs/artifacts/assets/profiles的全部文件清单求指纹；verify会识别新增、删除和内容变化。它是严格的全量一致性检查，不等于最小重评范围算法。

知识原件／宿主检索快照位于 inputs，项目知识索引、提取内容和 Wiki 位于 artifacts/knowledge，均进入既有快照范围。后续产物引用实际采用的知识 source/content 文件和索引版本。知识文件变更需重核；离线哈希只验证已保存的字节，不验证远端仍有权限或未发生更新。

评审引用输入fingerprint。授权记录同时引用实际评审文件SHA256与输入fingerprint，避免用旧授权覆盖新报告。但本地JSON可被编辑，本套件不提供可信身份认证或防篡改签名；真实授权由宿主／人落实。

## 独立评审

用户只给一份外部成稿时，先做原文和成稿来源登记。没有招标原文只可做写作／一致性限定评审，不得输出全面合规通过。无需为了让流程齐全虚构01—14曾经运行；记录实际输入即可。
