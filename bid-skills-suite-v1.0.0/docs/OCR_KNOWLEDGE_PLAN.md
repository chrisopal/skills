# OCR 与项目知识接入实施范围

用户已确认：保留共享项目文件的交接方式，补充扫描件 OCR、本地材料与宿主知识库两种知识来源；架构图和流程图优先 Mermaid / SVG，概念图使用宿主实际开放的生图能力。

## 实现选择

- 原生解析保持默认；显式开启 PaddleOCR 服务后，按页提交需要 OCR 的图像，保存来源、页码、识别状态与质量提示。使用现有 PyMuPDF 与 Python 标准库，不增加强制推理依赖。自建开源服务与带 Key 的服务使用同一已核对协议，云端其他协议不能冒充兼容。
- 项目知识保存在 inputs 与 artifacts 中。上传材料保存原件与提取结果；宿主检索保存本次结果快照、实际工具、权限范围、来源定位和检索时间。建立项目索引并生成可重建的 Markdown Wiki，不创建独立向量数据库。
- 知识台账供素材匹配、方案和写作读取；命中内容保持候选／待核验，证书和业绩仍需原件。总控在继续任务时验证已保存知识的哈希，原件变化使下游重核。
- 图表保持现有产物契约，明确 Mermaid → SVG 的选择和渲染检查；生图能力来自宿主，未开放时只保存图表规格。

## 验证

工程回归覆盖来源保存与过滤、跨项目拒绝、版本与哈希、知识导入及 Wiki 重建、检索命中与空结果、失效来源、OCR 请求协议／缺配置／鉴权／超时／部分失败、独立技能分发一致性。用合成文件运行完整本地命令链。协议测试不作为真实 Paddle 识别质量或 WorkBuddy/Codex 知识库实测。

真实 OCR 服务测试需要已配置的服务地址和凭据；实际宿主知识库测试需要当前会话开放的对应工具和明确资料范围。缺少这些条件时保留 NOT_RUN，不上传真实客户原件。
