# WorkBuddy 安装、使用与实测

本页针对桌面端。本次观察版本为 **5.6.2（2026-10-11）**，菜单可能随版本变化；以当前客户端为准。官方支持本地技能包导入，入口为“专家·技能·连接器 → 技能 → 添加技能 → 上传技能”，导入后在已安装列表核对启用状态。[官方技能说明](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Skills-Market)

## 安装到本地

先按 [README](../README.md) 下载完整 `chrisopal/skills` main。安装 17 个 `bid-*`，建议再安装独立 `enterprise-diagrams`。不要导入套件根文件夹，也不要只复制 `SKILL.md`。

- 界面导入：在套件目录运行 `python scripts/refresh_distribution.py`，逐个上传本地生成的 `installable-zips/*.zip`。独立绘图包按 [enterprise-diagrams README](../../enterprise-diagrams/README.md) 生成。
- 目录复制：技术用户可把完整 Skill 目录放到 WorkBuddy 用户配置目录的 `skills/`。本次 macOS 默认位置为 `~/.workbuddy/skills/`；自定义 `WORKBUDDY_CONFIG_DIR` 时使用实际目录。Windows 以客户端实际用户配置目录为准，README 提供默认路径示例。
- 核对发现：返回“我安装的”，搜索 `bid-orchestrator`、`bid-source-intake`、`bid-visuals`、`enterprise-diagrams`，确认已启用。未发现时核对目录层级、frontmatter 和实际配置目录，再刷新列表或新建任务。不要反复复制出同名嵌套目录。

本次实测使用**完整目录复制**并在客户端列表确认，不把这一结果称为“ZIP 安装实测”。复制不等于通过客户端上传安全扫描；若选择界面导入，以客户端扫描结果为准。

## 新建任务并使用

1. 点击“新建任务 → 选择工作空间 → 打开本地文件夹”，选独立投标项目目录，原件置于 `inputs/`。不要选 Skill 安装目录当输出目录。
2. 使用实际可用的模型；本次为 `Deepseek-V4.1-Flash`。模型选择不等于具备生图、OCR 或知识库工具。
3. 在输入框明确写“调用 bid-orchestrator”，说明项目路径和范围。也可通过 `/` 在当前客户端技能菜单中选择；若自动调用遗漏，明确要求加载 Skill 并回读其规则。
4. 使用 [README 首次指令](../README.md#第一次使用)，先理解，再确认方案、写作和当前版本评审/导出。检查执行记录里是否实际加载 Skill、调用脚本、保存文件，而非只有聊天总结。
5. 给出已准备好的 Python 虚拟环境解释器绝对路径。保持默认权限，按实际提示处理当前目录的必要操作；无需为本套件全局开启完全访问。

工作空间与已安装技能是两个概念：技能保存在发现目录，项目原件与结果保存在工作空间。官方说明工作空间用于任务读写，各任务维护独立上下文；本套件另外以项目文件和输入哈希支持续写。[官方任务入口说明](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Task-Bar)

## 画图与其他宿主能力

- 技术图可说“使用 blueprint，teal 主题，SVG 输出”。`bid-visuals` 保存图任务和章节关联，`enterprise-diagrams` 提供版式；实际渲染后保存 JSON、SVG、收据，再检查图与正文是否一致。
- Draw.io 继续可选，但需本机实际渲染器；Codex 中已安装的插件不会自动成为 WorkBuddy 工具。先运行套件 `diagram_tools.py doctor`，再实际渲染，不能仅靠发现可执行文件宣称所有图型通过。
- 系统界面示意由 WorkBuddy 本次实际开放的原生生图能力执行（可能请求宿主云端服务，本次实际调用了 ImageGen，不能称为全程离线），具体 Skill/工具由宿主发现。缺权限、未开放或生成失败时记录 blocked，不把 SVG、HTML 页面、提示词或 Codex 生成的图片算作 WorkBuddy 原生生图测试通过。
- 本地资料可导入项目知识索引；宿主知识库须真实检索后保存快照。无需为了装 Skill 新建外部知识库，也不假设任意宿主连接器都已授权。
- WorkBuddy 子 Agent 并行能力须实际核对；本次单章测试不验证多章并行。

## 生图后仍要检查什么

不能只数图片文件。对照本章需求逐项回读状态名、角色、字段和异常路径；本轮首张界面图曾把招标要求的六状态换成通用状态名，脚本仍会判定“有1张界面图”。这只能证明文件与关联存在。发现不一致时，在宿主对话中指出图ID/路径、原文要求和具体偏差，要求生成新修订、保留旧图、更新章节关联并重新评审。

## DOCX 评审的当前限制

DOCX 原生解析与核心评审的自动引文核验是两条路径。当前 `review_checks.py` 对 DOCX 来源保留“需宿主解析回读，不能自动标核验通过”的错误；本轮实际触发了该限制。宿主可回读当前原件并记录独立核验结果，但不能删除脚本错误、修改原件类型或仅改哈希来声称自动门禁已通过。来源能力需后续优化，本页不承诺 DOCX 已自动贯通正式评审/交付。
