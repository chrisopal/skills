# 执行复核与HTML报告设计

目标：回答真实招标执行是否按流程、哪些问题已修复；澄清分类确认时点；把已提取数据展示为可读HTML，并使能力可复用。

方案：保留现行JSON信封，不另建正式数据模型。修复初始化模式与冲突ID检查，补语义规程和匿名问题台账。类型由宿主先识别、路由脚本匹配版本化提取模板；范围清楚时生成候选提取，重大歧义与正式采纳范围由真实用户确认。新增标准库HTML生成器读取17当前索引，验证身份/哈希/路径，保存报告与清单。

展示：白色正文、蓝色主色、灰色背景；中文系统字体；左目录与右侧分区。金额/周期用关键指标，评分用层级条，完整需求用搜索与折叠来源，合规按业务阶段分组；长身份哈希放溯源详情。移动端目录收拢，打印内容保持可读。不引入Web框架、远程字体或新依赖。

验证：工程回归覆盖模式、ID、输入篡改、越界/符号链接、注入与同源计数；真实项目原件和报告留本地。浏览器走查三个视口、筛选、来源展开、原件链接与控制台。套件/独立分发一致性检查完成后提交；不把工程通过当成招标业务验收。
