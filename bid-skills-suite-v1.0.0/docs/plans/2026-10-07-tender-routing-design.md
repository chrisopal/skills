# 跨类别招标读取、模板路由与公开语料验证

## 用户目标与本轮边界

用户要求建立适合不同招标项目的大类，获取公开原件，标注并测试，再让首次识别匹配提取模板，提取项目基础信息、评分项、废标／否决项和采购需求。本轮修改独立 Skill 套件，不修改 Bid Agent 应用后端。原件仅本地保存，Git 保存来源清单、标注、模板、工具与可复跑说明。

## 分类决策

采用四种采购工作内容：工程施工、硬件供货、软件开发与系统集成、服务与外包；智慧化是组合项目入口及场景标签，智能工厂／园区／校园不作为互斥大类。分别识别项目标包数量与各标包内部的单类／组合，采购公告的法定货物／服务分类按原文保留，不替代业务分类。

选择理由：单一行业标签容易漏掉混合采购，五个互斥类别会使软件集成和智慧化重叠。四个工作内容可以组合，专业术语再由领域包补充。配置只决定检查项，不能生成客户事实。随硬件附带的固件、安装、质保，以及投标人历史案例，不自行形成额外采购类别。无法确定时保留未知。

## 数据与执行

1. 原件登记与逐页解析继续使用 01 的现有来源身份；OCR 和复杂表格缺口继续保留。
2. `tender_router.py brief` 生成完整原文块、分类约定和模板目录供宿主模型读取。
3. 宿主模型按实际采购范围判断标包和组件，保存带来源位置和引用的分类决定。
4. `tender_router.py route` 核验项目、原件哈希、原文产物哈希、引用和分类一致性，输出冻结的公共提取规则与各标包模板。
5. 02—06 使用该计划，分别产出既有契约的项目画像、需求、评分、合规和强制格式产物。模板不限制全文覆盖，也不覆盖客户强制格式。

脚本不伪装模型分类器，不以关键词命中直接取得分类结论，不执行原件中的指令。分类和抽取是有证据的候选结果，专业审核状态单独保留。

## 公开语料

目标十份真实公开招标／采购文件：四个大类各两份，加两份智慧化组合；优先不同发布单位和排版结构，软件集成为重点。每份保留来源网址、下载日期、原始 SHA256、页数、抽取情况和样本用途。无法免费直接取得的文件不绕过认证，记录后寻找其他公开文件。

标注包括范围分类与四条提取轨道的重点锚点，明确是 AI 核对的候选标注，未经行业专家完整审定；未逐条标注全文时不计算全文召回率。独立模型试跑不得预先获得标注答案。定量统计须区分分类一致性、引用可定位、已标注锚点覆盖与语义复核。

## 验证与交付

工程回归覆盖单类／组合／多标包／未知、错误页码、伪造引用、跨项目、来源变更、路径越界和禁止覆盖。真实样本验证原件可读、标注可回看、模板组合符合采购范围。独立试跑记录实际模型、输入范围、遗漏与未运行项。新脚本和资源同步至需要独立安装的 Skill，运行套件与 ZIP 一致性检查。

本轮不承诺完整 PDF 表格重建、CAD／工程量清单专业计算、真实 OCR 识别效果、所有宿主兼容和最终标书交付验收。发现真实样本暴露的相关可修复问题时，在当前范围内修复并复测。
