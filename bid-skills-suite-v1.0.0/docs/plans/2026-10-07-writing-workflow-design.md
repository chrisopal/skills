# 目录到写作的实际验证

用户已要求补充并测试目录、写作、配图、编辑保存及需求/知识匹配。沿用现有17个技能和项目文件契约，不增加依赖、不改Bid Agent应用。新增工具是可选的本地草稿编辑适配器，不是正式交付或后台编标服务。

## 执行范围

- 06提取强制结构，08输出候选章节和任务卡；按原文保留分册、顺序及条件适用性。
- 07/09/10为限定测试保存策略、真实材料缺口和方案建议。11各生成一章及响应表，未采纳、未证实能力不升级成正式承诺。
- 完整目录映射和实际正文覆盖分开统计。新增可重复检查报告，显示未映射、未写作、缺响应、缺证据、悬空图表和过期输入；不从ID存在推断语义满足。
- 使用已有Python依赖和标准库提供本地Markdown编辑、项目文件保存、历史版本及冲突拒绝。用户偏好存文件；并行参数指导宿主调度，工具不假装拥有模型任务池。
- 原件只读，章节、图表、知识快照和来源关联独立保留。Mermaid优先；无已安装渲染器时保存Mermaid和等价SVG，使用已有工具渲染，明确实际使用路径。
- 工作稿DOCX/PDF用于可编辑性和版面验证，不冒充已审核标书；保存后的输入变化需要重建和复核。

## 界面

采用enterprise-ui-design的平面浅深色、连续章节列表、清晰保存动作及错误反馈。目录、正文编辑、需求/评分与缺口分区展示；未写章节可查看，编辑现有测试章节。正文按Markdown保存，不冒充富文本Word编辑器。手机折成单列；保留未保存文本，冲突时提供重新读取与恢复路径。

## 验证

先运行新增确定性失败用例，再实现工具。回归涵盖错误映射、孤儿/重复响应、输入哈希变化、章节正文修改后追溯失效、图表缺失、知识材料不被自动采纳、并发保存与路径边界。

两份真实项目各保存完整候选目录、一章具体正文及一个图。浏览器验证编辑保存、刷新回读、两端旧版本冲突、设置回读及浅深/宽窄布局；生成并查看实际DOCX/PDF。真实企业材料与宿主知识库联通仍缺输入，使用隔离合成资料只验证本地检索接入，不混入真实项目。
