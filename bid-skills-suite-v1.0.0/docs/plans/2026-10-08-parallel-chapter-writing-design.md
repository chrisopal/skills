# 宿主子Agent并行章节写作

用户已确认按章节派发、独立草稿、协调者合并、失败重试和汇总检查的方案。实现仍归chrisopal/skills套件，不修改Bid Agent应用或安装模型SDK。

总控读取写作设置及宿主实际子Agent能力；并行且能力可用时真实启动最多配置数量的原生子Agent；串行或能力缺失时记录实际执行方式与原因。按任务卡分章，未解决的设计/事实先由协调者确定；工作者仅获得该章所需内容与专属输出路径。

writing_batch.py持久保存批次、源版本、章节上下文及尝试。准备/占位/绑定实际Agent身份/回收/失败/重试/合并分开，运行状态来自实际工具事件。并行槽位受文件锁保护，默认最多两次尝试；恢复时复用已收回任务，不按时间猜测任务成功。

回收校验章节、输入、尝试、非空正文和完整需求集合；合并前回读提案哈希并核对上游/设置/正文基线。协调者复用已有WritingWorkspace.save串行保存，保留历史和审计，生成draft/proposed，不自动采纳。部分合并如实保留检查点；外部修改或未知中断必须先核对，不能无声覆盖。追溯、配图、响应、审核和导出需针对新稿重新核验。

验证：确定性回归覆盖两槽、来源变更、错误提案、篡改、重试上限、保存冲突和恢复；独立单Skill分发检查；青草沙副本9.3与9.4真实原生子Agent并行，回读两稿及合并结果，统一事实/需求逐项检查。原完整167页模拟标书不覆盖；WorkBuddy执行保留NOT_RUN。
