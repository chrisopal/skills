4.1.1 响应概述

平台以事件为主对象，覆盖登记到归档的完整闭环，并以可审计的状态流转支撑统计与导出，设计对齐 R2 的六个状态、R3 的三类角色与最小权限及不少于180天的审计日志。

4.1.2 六状态流转

1. 事件登记：接收既有告警平台经 HTTPS JSON 接口推送或人工登记的事件，登记前完成告警去重与来源追溯。 2. 工单派发：调度员按分类规则生成工单并指派处置人员，派发动作与指派对象写入操作日志。 3. 接单：处置人员确认接单，状态由派发转为接单；超时未接单触发预警。 4. 处置：处置人员记录处置过程与结果，必要时关联佐证材料。 5. 复核：管理员对处置结果与操作日志进行复核，形成通过或不通过的结论。 6. 归档：复核通过后归档，事件计入闭环率统计，并可按时间范围导出。

4.1.3 复核退回与日志保留

复核不通过时，事件由复核状态退回处置状态，退回原因、操作人、时间与前后状态一并写入日志且不可删除；处置人员据此重新处置并再次提交复核，直至复核通过后归档。该机制直接对应 R2 中“复核不通过须退回处置并保留日志”的要求。

4.1.4 角色、权限与审计

系统设置管理员、调度员、处置人员三类角色，并按最小权限分配功能与数据范围：处置人员仅见本人工单，调度员负责派发与超时跟踪，管理员负责复核与配置。操作审计日志覆盖登录、派发、接单、处置、复核、退回与导出等动作，保留期不少于180天，以满足 R3 与实质性响应要求。

4.1.5 统计与导出

提供事件列表、超时预警、闭环率统计与按时间导出四类功能；闭环率按归档数与登记数之比计算，导出按登记时间过滤并记录日志。
