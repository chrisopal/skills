# 12｜商务与资格文件编制

受约束地填报商务和资格文件，保留签署与价格授权边界。

运行条件：需支持读取项目文件；可选脚本需要 Python 3.10+，文档、视觉/OCR 与绘图能力由宿主提供。

## 触发与边界

当用户提出“商务标、资格文件、承诺函、授权书、商务响应表、报价表整理、签署清单。”时使用。不决定价格，不模仿签名盖章，不编造企业资质，不代替法律审核或工程计价。

## 开始前

先读 [共同证据与安全约定](references/evidence-and-safety.md)。仅当需要细化操作时读 [专项操作手册](references/playbook.md)；输出字段与示例参见 [产物契约](references/output-contract.md)。

输入：06固定表格、05资格提交要求、09企业原件与已核验字段、已授权价格及商务条件。

上游技能：`bid-project-profile, bid-compliance, bid-format-extraction, bid-evidence-matching`。独立使用时接收用户提供的等价文件，记录实际输入，不要求虚构完整流程状态。检查原件和产物版本；缺关键信息时给出范围受限的草稿及缺口。

## 执行步骤

1. **步骤1**

   按06逐表建立FORM-ID与字段映射，区分固定文本、可填字段、附件和签署区，不重写原模板条款。

2. **步骤2**

   每个填值关联准确企业素材或人类决策来源；统一公司全称、统一社会信用代码、授权代表与项目名称。

3. **步骤3**

   资格材料按照05规定的投标主体、有效时间和对象核对；提供的证照不能因“格式齐全”自动视为适用。

4. **步骤4**

   价格、数量、币种、税率和舍入由用户明确提供；用Decimal或可靠表格工具校验乘积和合计，不用语言模型心算。

5. **步骤5**

   缺失价格、账号、证书号或日期留null和待填任务；禁止用示例数字、同类企业资料或AI估值填正式表。

6. **步骤6**

   商务偏离保留原条款、响应值、差异和授权状态；涉及责任或合法性的争议转人工专业审核。

7. **步骤7**

   输出需签字、盖章、电子签署或保证金动作清单，不自动执行。签署空白区保留，不能贴生成的印章或签名。

8. **步骤8**

   交付填报草稿和字段来源表，经授权审核采纳后进入14；身份信息脱敏只用于内部演示，不擅自破坏正式模板要求。

## 产物与交接

保存 `12-commercial-content.json`（机器可读）和同名 `.md`（可读报告），使用 [JSON模板](assets/output.template.json) 与 [报告模板](assets/report.template.md)。字段必须符合 [JSON Schema](assets/output.schema.json)。不要把模板空值直接当结果；详细演示见 [合成示例](assets/example.output.json)。

01—14产物放项目`artifacts/`，15放`reviews/`，16放`deliverables/`，17放`work/`。来源原件只读置于`inputs/`；图表置于`assets/`；规则配置置于`profiles/`。路径始终相对用户指定项目根，不写死本技能安装目录。

每个输出记录`project_id / artifact_id / revision / inputs / status`。`inputs`内SHA256从实际输入文件计算。缺依赖、未运行检查和待确认分别保留；不把模型产生结果等同于业务完成。

可选执行本技能目录内的校验器：

```bash
python scripts/validate_output.py /absolute/path/to/12-commercial-content.json
```

脚本只校验结构及部分一致性，不检查所有真实语义与授权。依赖不足可按清单人工检查，但必须写明“脚本未运行”。

## 验收检查

- [ ] 固定条款未改义。
- [ ] 字段值有真实来源或明确空缺。
- [ ] 价格数据经过授权和确定性校验。
- [ ] 商务偏离没有被“优化措辞”隐藏。
- [ ] 签字盖章仍为人工待办。

## 人工确认点

投标主体、价格、税率、付款、保证金、责任承诺及签署须真实授权人确认。

## 常见陷阱

- 身份证号、账号和证书号不能推测。
- 测试报价不得进入正式成稿。
- 含税与不含税金额不能直接混合。
- 扫描签名图片不能当作授权签署。

## 调用示例

> 请用我提供且确认的企业资料填写指定商务资格模板，缺项保留待填，列出需核价、签署和法律审核的内容。

示例原件 `assets/synthetic-tender.md` 和 `assets/synthetic-supplier.md` 全为合成资料，不能用作真实投标证据。场景配置参考 `assets/profile-catalog.json`，所有条目只是待项目核验的种子，不是已通过业务验收的行业规则。

## 失败与恢复

先保存已完成的产物、失败范围和下一步；原件变更或输入哈希变化时重核受影响内容。不要自动覆盖人工新版本，不代签批，不上传资料，不声称已在后台继续运行。测试建议见 `tests/cases.json`；这些是待执行的业务评测用例，不是已通过记录。
