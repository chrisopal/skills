# 明确授权的合成材料闭环测试

仅在用户明确要求“模拟企业材料、测试、不真实投标”等范围时使用。总控建立独立项目目录，保留原招标文件字节，记录用户原话及授权范围；不得改写已有真实项目或候选稿。复制后须重新调用分类路由，绑定当前项目及01原文哈希；01.inputs 的 artifact_id 使用 source-registry 中的 source_id，与 documents 集合一致，不用文件路径代替来源身份。旧路由及旧哈希移入历史目录，不能仅改顶层项目号后继续使用。

## 材料、知识和写作

- 生成虚构主体、人员、资格、社保、财务、查询报告、独立合同和报价。每份文字/图片及最终文档每页显著标明“合成测试材料｜不用于真实投标”，使用 TEST 标识，签署位仅用“[模拟签署标记]”。不模拟具有真实效力的签名或印章。
- 测试参考时点与实际执行时间分开记录。完整年度财务不能由尚未结束的全年数据或中期报告替代；期初现金加三类现金流等于期末现金、资产等于负债加权益、利润口径及报价税额实际核对。
- 实际调用本地知识接入、校验、检索及 Wiki 构建；保存原件/内容/知识条目引用并回读完整原文。不能写假宿主返回或假测量结果。四份独立合同使用四个材料身份，多页/重复扫描不增加独立数量。
- 来源 `kind=synthetic`，接受和确认引用指向真实用户的测试授权，且明确只接受 fixture 使用。09材料、10设计、11章节、12表单、13图及14排版必须传递同一版本的引用；只补最终Word不算跨Skill闭环。
- 所有适用固定形式按原格式填测试值。互斥的身份/签署路径选择一种，另一种明确不适用；条件性证书保持“如有”，成员履历按每人一表生成。源冲突的 `resolution=null` 保留，测试解释另存，不能伪造正式答疑。
- 技术及现场履约继续区分拟执行方案和已测事实。合成数据的工单流转不能证明真实视频算力、接口联通、企业资格或客户验收。
- 正文写实际动作、条件、接口和验收机制；逐项响应矩阵只输出一次。不要把完整响应或纯需求原文重新插入正文，再用同一文字制造段落关联通过。追溯引用应选真正覆盖该条件的正文机制段落，结构校验不能代替逐项语义复核。

## 实际审核与导出

先完成内容和图表，再生成最终Word/PDF，更新并回读目录/评分索引的真实页码。检查并整改实际导出后冻结字节，15输入及16清单另外绑定最终Word/PDF哈希；输入快照只覆盖 inputs/artifacts/assets/profiles，不能代替导出文件哈希。Word打开保存、重新排版或目录更新后必须重新审核。

最少保存以下证据：

1. 知识校验、命中和零命中检索、正文/需求/评分覆盖、独立材料数量、19等项目实际形式数量、报价/税/成本核对。
2. DOCX ZIP CRC、全部XML可解析、关系目标存在、图片完整嵌入且对应正确、表格可编辑、无宏/外链/批注/修订残留；每个标题、书签、目录标题与最终PDF页码逐项一致。
3. 实际Word兼容引擎打开/保存/渲染和内容回读，逐页检查字体、图片清晰度、截断、溢出、跨页和空白页。未实测Microsoft Word或指定字体环境时写明限制。
   宿主导出引擎须实际解析已安装的中文字体；字体配置或字形缺失时停止交付，修正配置后重新导出并查看页面。仅有可提取中文文本不证明字形可见。图片须按可用宽度和高度同时等比缩放，图题、图注与图片同页；分页宜施加在下一实际段落，避免独立分页空段溢出产生空白页。相邻的独立表单之间加入有意义的标题段，实际打开另存后检查是否被合并。最终成稿用读者可理解的序号和章节位置，内部R-ID、字段枚举、脚本名或知识索引路径只存审核记录。
   Microsoft Word与LibreOffice分页可能不同；优先使用可更新的PAGEREF/TOC域并在实际交付引擎更新、保存和导出。缓存页码与最终PDF逐项核对，章节位置须按目录顺序识别，排除正文中的同名引用。兼容引擎回读仅允许目录/交叉引用域结果变化，正文、表格、图片像素与书签必须完整；不得要求跨引擎页数相同，也不得用不同引擎的静态目录冒充原生Word页码。
4. 缺材料、错价、缺图、旧哈希等负向用例实际拒绝；正式 `bidkit.py check-release` 仍应拒绝模拟版本。已测/未测不能合并为PASS。

模拟结论单独保存为 `simulation-review.json`，完成上述实测才可写 `SIMULATION_REVIEW_PASSED`。不要为追求通过而删除强制条件、把设计设为已实现或绕过正式门禁。

现有原生Schema无需新枚举：15可用 `status=ready / release_recommendation=needs_review / human_approval_ref=null` 表示范围内审核产物就绪；16可用 `status=ready / delivery_status=draft_only / signature_state=not_applicable / user_release_authorization_ref=null` 表示本地模拟成稿。12签署任务仍 `pending`，模拟文字不是实际签署。正式发布建议及确认不得写成已批准。

本地测试包只含显著标记的成稿和说明，不混入内部策略或私有凭据；如演练扫描PDF/密码ZIP，实际解码、解密并比对完整内容。用户此授权不包含真实外发、上传、付款、盖章、寄送、开标或提交。报告清楚列出通过的模拟检查及未运行的真实能力，不因没有真实资格而把已经完成的模拟测试误报为仍未完成。
