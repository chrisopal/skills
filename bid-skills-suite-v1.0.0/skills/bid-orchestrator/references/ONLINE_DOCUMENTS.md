# 在线标书协作

飞书文档承载协作正文、多人编辑、评论和历史。投标 Skills 继续管理招标原件、目录任务、需求与评分映射、企业证据、配图源和评审记录。本地 `11`/`13` 是有来源和版本的工作快照；把文件上传到云盘不等于启用了按章协作。

## 接入与授权

先安装投标套件，再在宿主中配置飞书官方 `lark-cli` 及对应 `lark-doc`、`lark-drive`、`lark-shared` Skills。运行 `lark-cli --version` 和 `lark-cli auth status --json --verify` 确认当前身份；授权配置遵守宿主中飞书 Skill 的流程，不把 token 或应用密钥填入标书配置。适配器不安装依赖、不代开权限、不邀请成员，也不在用户身份失效时自动改用应用身份。

默认使用已授权用户身份。应用身份只适用于明确选择该身份且应用可访问的文档；应用创建成功不代表个人账号自动获权。写入正文和上传图片可能需要不同的权限范围，任一步失败都不能显示“整章已同步”。授权过期、缺范围、无文档权限、超时及部分写入分别返回错误，并保留本地候选与审计。

用户指定飞书 Docx/Wiki 链接后，总控识别提供方并执行绑定；腾讯文档和 Office 已登记扩展入口，但当前尚未实现读写，选择时明确拒绝，不伪装接入成功。

## 正常使用

工作台的 **写作设置 → 在线协作** 支持绑定、打开在线文档、核对云端、读取和同步当前章节。绑定后，“保存草稿”先保留本地候选，再同步目标章并回读；失败时显示“本地已保存 · 云端未同步”。页面上的绑定状态来自上次回读，不能当成实时锁定状态。

也可以让宿主执行以下命令；从套件根或已安装的 11/17 Skill 目录运行，`--project` 始终是当前标书项目：

```bash
python scripts/online_documents.py bind --project /project \
  --url 'https://example.feishu.cn/docx/文档token' --identity user
python scripts/online_documents.py push --project /project --section-id SEC-ID
python scripts/online_documents.py pull --project /project --section-id SEC-ID
python scripts/online_documents.py check --project /project --section-id SEC-ID
```

首次写入可以新增章节；已有标题匹配必须唯一。稳定 `section_id` 与远端 block ID 的对应保存在项目 `work/online-document.json`，不能复制其他项目的绑定文件来续写。标题发生变化、映射歧义或遇到不支持的富文本时停止自动覆盖，由宿主对话确认映射或处理方式。

普通段落、列表、内部小标题与矩形 Markdown 表格可以往返；表格写入为飞书原生表格。合并单元格、嵌套表格等复杂结构暂不自动转换。表格列宽不在当前往返保真承诺内；文字或内联格式丢失会阻止该次同步通过。

## 按章分工与接力

1. 团队在飞书授权文档，在目录任务卡中明确负责人和审核人。共享链接的权限由平台执行；原件和企业材料仍需各自有权访问。
2. 接手者先读取当前在线章和必要项目上下文，再写本地候选。没有原件、评分办法或证明材料时，给出缺口，不能仅凭正文继续承诺。
3. 子 Agent 可以并行生成不同章的独立提案；由一个合并者逐章落盘、同步及回读。不要让多个 Agent 同时改总 `11` 或同一在线章节。
4. 已有人工修改触发冲突时，保留候选，先拉取并对话合并。刷新状态不能用来洗掉冲突，整本覆盖不能用来解决冲突。
5. 宿主对话调整目录、正文或图时，继续使用相同章节 ID，更新相关映射和追溯。评论只是协作意见，不能自动转换为正式批准。

当前飞书 CLI 的 `revision-id` 不是已验证的原子条件写锁；因此适配器对已有章的改写返回 `requires_native_merge`。在飞书原生编辑器中合并候选后再拉回，不能强行绕过该保护。当前自动保存只支持新增章和确认未变章节，不能声称已实现任意章节的无冲突自动覆盖。[飞书块更新参数](https://open.feishu.cn/document/server-docs/docs/docs/docx-v1/document-block/patch)描述了操作版本，但未提供用于本适配器的原子比较并交换保证。

## 图片与资源

13 仍负责生成准确配图：技术图可选 Enterprise Diagrams、Draw.io 等，系统界面示意默认调用宿主实际生图能力。在线章节上传使用已登记的本地栅格呈现，保留可编辑 SVG/JSON/Draw.io 源；不能把生成界面称为实际产品截图。

同步必须核对实际正文、图片资源和本地图片哈希。未知图片、资源替换、复杂富文本或锚定评论无法安全保留时，当前适配器会阻塞该章写入/拉取，交给宿主按平台原生方式处理。部分写入、超时或回读不符不自动重放；先回读云端确认哪些已写入，再恢复。

缺图片上传权限时不能用文本占位符冒充已配图。飞书应用需开通 `docs:document.media:upload` 或官方允许的等效权限，并让实际执行身份有目标文档访问权；是否增加应用权限由管理员决定。应用创建文档时若个人授权失败，还需处理成员授权，不能把应用身份成功当作真人已获权。

## 审核、评分与导出

在线绑定项目在评审前重新读取云端，核对已同步正文和图片；评审后再次核对。整本评审要求所有已写章节完成同步。限定 AI 评分只评已同步章，其他评分项保留未评，不能将其小计称为完整得分。

`work/online-review-basis.json` 保存稳定的评审依据，纳入内容快照；文档绑定或正文发生变化会使旧结论失效。只有绑定、只有上传成功返回值、或旧截图均不能证明当前。资格条件、关键材料、废标项以及真实 Word/PDF 导出完整性仍走 15/16 的独立门禁。

## 可移植边界

适配器通过 `fetch` / `update` 的小接口复用已安装 CLI，项目身份、章节映射、冲突与收据逻辑不依赖宿主模型。未来接腾讯或 Office 时必须实现同等正文/资源回读、权限失败和版本保护，并通过相同反例测试；不以“有 API”宣称已支持。
