# 评审报告展示与打印

评审JSON仍是交接数据。HTML用于阅读同一版本的概览、三张逐项矩阵、问题整改、复核记录和范围；展示工具不计算得分、不关闭发现、不执行正式交付门禁。

```bash
python scripts/render_review_report.py --project /project \
  --review /project/reviews/15-review.json --scoring /project/artifacts/04-scoring.json \
  --out /project/reports/review-r1.html
```

`--scoring`可省略；提供时应为评审输入中冻结的确切04产物，路径、哈希、产物ID与版本必须一致，用于显示评分名称、原文最高分及条件。工具先执行既有Schema及状态一致性校验，再检查冻结输入哈希、引用版本、已有项目元数据身份及计分叶子覆盖。旧版、越界、输入漂移、漏行或阻塞与交付建议冲突时拒绝生成；不把这些检查称作业务复核。独立评审允许没有全流程项目元数据，但文件间项目身份仍须一致。

正文统一18px/1.65，文件标题28px、分区22px、标签16px；标签与证据位置不各自发明字号。先展示交付建议与逐项概览，再分别展示评分、合规和材料。仅用颜色辅助状态，不能只用颜色或仪表盘百分比表示资格和得分。主观评分未知保持未知，原文上限与已得分必须分开。

长引文和整改明细可展开，完整条目始终留在HTML中；不截断理由、隐藏阻塞或只留下几个好看的例子。公开演示截图可以截取概览或评分分区，但须标明实际范围，并在完整报告保留全部问题。真实客户信息按授权范围隐藏，合成资料明确标记。

打印使用A4、独立10.5pt正文及9.5pt标签，保留表头重复、标题跟随正文、整行/证据块避免跨页。导出前由宿主浏览器展开所有`details`（打印CSS也显式展开内容），使用`preferCSSPageSize`及`printBackground`。实际PDF逐页渲染检查，尤其长引文、表格跨页、孤标题、遮挡和空白页；页面截图不能代替实际PDF读回。
