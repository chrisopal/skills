# 目录、写作与编辑保存

## 先确定任务范围

`understand`只产生招标理解，不能以理解报告证明写作完成。用户要求继续编写时进入对应业务阶段；用户明确要求补充/测试时可生成限定范围的候选目录、方案和正文，记录测试范围及缺口。无需为已授权测试反复询问，但不能伪造理解确认、方案批准或正文采纳。重大歧义不涉及的章节可先做草稿；涉及的承诺保留未知。

## 06到08：识别和创建分开

06记录客户强制章节、表单、顺序、分册和条件。08先保留这些结构，再在允许位置创建建议子章节。法定代表人身份证明/授权书等有条件的模板保留适用条件，不默认要求两种情况同时提交。招标人侧记录和明确不适用的通用表，不进入投标人必交文件。

每个章节任务卡说明读者、要回答的问题、需求/评分/合规/格式ID、主责范围、输入证据、图表、响应表和验收方法。没有映射的条目必须展示；格式约束未解决的目录保持候选。将页数或标题关键词当作覆盖证据属于执行错误。

目录显示按`parent_id`构建前序树，可展开/折叠并缩进；不要按数组平铺。中文根编号可保留“一、”，数字子级使用1.1/1.1.1等，避免“一.1”。`outline_view.py`提供派生展示值与深度，保留原始number和ID，不改动已绑定08文件。客户自定特殊编号保持原意，缺父级或循环时显示数据错误，不静默平铺。

## 09到11：知识、设计和正文

09从真实本地材料或实际宿主检索快照核验来源、主体、有效性及适用性，再记录候选/采纳/缺失。10记录D-ID设计建议和边界。11逐章读取当前任务卡、设计、选材、原文及写作设置，不凭聊天记忆补企业事实。尚无真实材料时，保存材料缺口；允许有来源的方案建议，不得声明资质、业绩或现成能力已经满足。

11保存章节Markdown、逐项响应、草稿状态及输入版本。可额外保存`artifacts/11-writing-trace.json`：`writing_sha256`绑定当前11文件，`links`逐条含`chapter_id / requirement_id / body_quote`，可附原文sources。`body_quote`必须是当前章节的非空实际段落；正文变更后追溯失效，重新阅读相关段落及原文后才能重建，不能只替换哈希。相同来源出现于多个章节时保留关联，不把原文要求升级为企业能力证据。

## 实际覆盖检查

```bash
python scripts/writing_checks.py --project /absolute/project --out work/writing-coverage.json
```

检查确切的08/11和03/04/05/06/09/10/13输入、项目身份与递归哈希，区分：目录未映射、已规划未写作、缺响应、未展开评分、缺证据、悬空图、段落追溯缺失/过期。报告的`structural_valid`只说明已检查结构，`semantic_acceptance=NOT_TESTED`不会被结构成功升级。整标是否充分响应仍由15逐项内容复核，不能把“已写一个关联章节”称为整项评分满足。

## 编辑器及保存

优先使用宿主实际提供的编辑器和保存工具；记录实际文件、保存版本及重开回读。没有编辑器工具时可打开Markdown，或使用本套件可选的本地适配器：

```bash
python scripts/writing_workspace.py --project /absolute/project --port 8767
```

根据命令实际返回的地址在浏览器打开。此工具只绑定127.0.0.1，提供Markdown章节编辑，不能称为Word富文本编辑或后台模型引擎。目录未写节点、关联需求、评分、材料缺口都来自实际项目文件。用户输入按文本处理，原件内容不能变成页面脚本。

保存使用当前版本和文件哈希；新稿仍为`proposed/draft`。保存后历史正文、审计记录及可读Markdown保留。旧窗口或外部修改产生冲突时拒绝覆盖，浏览器保留未保存文本，由用户/Agent核对后合并。输入原件或目录变更时重新核验依赖，不能只刷新页面绕过过期依据。保存失败显示原因，不显示虚假已保存。派生Markdown或审计写入失败时尝试回滚，恢复失败则明确报告部分写入；这不是数据库多文件事务。

并行策略先确定统一目录、事实、材料和设计，再按独立章节生成候选；每个工作者拥有独立草稿文件，由一个协调者合并。共享11文件的编辑写入串行并有文件锁，不能让两个工作者直接同时改总文件。`work/writing-settings.json`保存语气、目标字数、串行/并行及最大并行数；这些是宿主生成设置，不会自行启动任务池。Agent调用模型前读取设置，记录实际采用；字数不替代需求覆盖。

## 13到14：图文和实际工作稿

08给图表任务，10给节点和边界，11提供对应正文。13默认SVG，用户可选择Mermaid等方式；保存可编辑源及实际渲染文件。显式选择不可用时记录缺口；经用户允许的替代才可执行并如实记录。原招标图只作为原文依据；概念示意不得冒充现场照片、交付设备或证照。图必须有关联章节、图注和方案依据，未知接口明确注明。图变更、正文变更或源版本变更后重新核对一致性。

14使用实际工具构建可编辑工作稿。基础`build_docx.py`接受已有document-spec，并支持`style.body_size_pt / body_line_spacing / body_east_asia_font`及表格`widths_cm`显式列宽；列宽数量与表格列数一致，总宽不超过当前页面正文宽度（四边2.5厘米时为16厘米）。不传style时仍为基础11pt、1.25倍、SimSun工作稿；选择模板时应用其明确参数。先读取06再填样式，客户要求优先。只能直接插PNG/JPEG，SVG/Mermaid须受控渲染。复杂固定表、附件原页、目录域与暗标另行检查，基础脚本不会自动完成这些。

排版模板见14的`references/BID_LAYOUT_TEMPLATES.md`与`assets/layout-templates/`。通用候选样式为小四宋体、1.5倍、首行两字符、正文段前后0、无空白段；只有未规定项才采用。新style支持缩进、对齐、段间距、标题/表格/图注字号及页边距，表宽按当前正文宽度限制。记录项目有效样式及06覆盖；原文的全篇字体要求不可缩成仅正文。模板可加载不代表正式成稿、暗标或复杂固定格式符合。

保存后的章节不自动更新已有Word/PDF。重新生成新版本、绑定当前11/13哈希并核对实际文件。读取DOCX结构和PDF文字不能代替页面渲染检查。限定工作稿保持未正式采纳；16正式导出和递交授权仍按原有规则。

## 配图与生图配置

设置保存于`work/writing-settings.json`，示例为`assets/writing-settings.example.json`。旧文件无visuals时补默认；编辑器可修改并按版本/哈希保存。设置及visuals仅接收列明的字段，未知字段和Key/凭据字段拒绝保存。生图凭据与授权沿用实际宿主；没有工具或凭据时保留缺口。

| 字段 | 默认 | 执行含义 |
|---|---|---|
| visuals.enabled | true | 是否生成可选配图；关闭仍需标出招标强制图表缺口 |
| diagram_renderer | svg | 架构、流程、网络等技术图默认SVG，可选择Mermaid；auto也优先SVG。保留已有明确偏好；显式选择不可用时记录缺口 |
| image_mode | host | 界面示意、概念配图默认由Agent自带生图Skill驱动实际工具；disabled关闭生成式配图 |
| tool / model | auto / 空 | 实际工具名与模型偏好；不得编造固定宿主接口或未返回的实际模型 |
| style | 企业概念示意 | 传入图表规格和实际生成描述，服从06格式/暗标 |
| aspect_ratio | 16:9 | 支持16:9、4:3、1:1；实际工具支持则传参，否则写入生成描述并检查成图比例 |
| max_images | 2 | 本次最多1—8张概念图，不是需要用装饰图填满的数量指标 |

13调用前读取当前设置、图任务和实际工具参数。工具或模型偏好不可用时标明原因；auto可按宿主能力选择，指定偏好不能悄悄替换后声称已采用。保存配置版本/哈希、实际工具、实际模型（未返回则未确认）、采用参数/未支持项及实际文件到13图表specification与执行记录。原文、企业私有材料向外部图像服务传输仍遵守已有授权；配置本身不是传输授权。无自动模型任务池，实际调用由Agent执行。

## Skill驱动的宿主生图

配图方式由用户选择。按“逐图明确指令→已保存的项目偏好→默认规则”确定执行路径；默认架构图等技术图使用可编辑SVG，系统界面示意使用Agent自带生图Skill。未指定偏好可直接执行默认路径，无需重复确认。用户单独选择某张图的方式时，将选择和实际执行记录在该图规格中。

11按章节任务识别需要表达的核心操作，13区分以下图型并执行。用户指定图型优先于旧配置；记录覆盖原因，不能静默将界面图换成流程图。

| 图型 | 实际执行路径 | 必须保留 |
|---|---|---|
| 软件界面设计示意、概念图 | 13发现并调用当前Agent的生图能力 | 实际PNG/JPEG、提示词/规格、章节、功能依据、示意图注 |
| 功能架构、流程、网络等技术图 | 默认SVG，用户可选择Mermaid等方式 | 可编辑源、实际渲染图、节点/边依据及未确认边界 |
| 已实现系统截图、现场和资格证据 | 仅使用授权真实材料 | 真实来源与适用性，不生成替代证据 |

Codex运行时有Imagegen则加载其Skill并调用实际`image_gen`工具。WorkBuddy或其它宿主先查看本次Agent已注册的生图技能、插件或工具，按实际参数调用；这些平台名不是通用API名称。`tool=auto`选择当前宿主的能力；显式不可用偏好、无工具、超时或空结果要报告并保留缺口。模型名仅记录实际响应返回值，未返回则未确认；不根据工具名猜模型。

执行顺序为“图任务/输入与配置→实际工具调用或SVG绘制→文件落盘→文字、尺寸与功能核对→13版本交接→章节预览/报告→重新生成并核验工作稿”。执行记录至少含Skill、宿主、实际工具、配置版本/哈希、实际文件/哈希、模型确认状态和未支持参数。提示词文件、前端按钮或配置保存不等于已生成。

界面图使用示例数据和“界面设计示意，非实际系统截图”，不编造上线或接口连通。实际照片等证据仍按既有传输授权。栅格图保留生成规格以便再生，只有SVG等源可以称对象可编辑。`max_images`限制生成式图张数，SVG/Mermaid技术图另行按章节必要性安排。每张图要在编辑器当前章节、报告与实际Word/PDF中打开核对；原文件保留新版本，未采纳状态保持。

## 两份真实文件的测试门槛

各验证完整候选目录、至少一章具体正文、响应表与实际配图；在真实浏览器编辑、保存、刷新重读，验证旧版本保存冲突及失败文本保留；在两份项目之间切换不混资料。验证设置回读、浅深主题、1440/1920/390布局、缺材料/未写/过期状态。生成实际可编辑DOCX及PDF并检查中文、表格、图和页面；原文规则/数字与写作建议分开复核。明确区分工程测试、当前宿主执行、范围内内容检查和整标业务验收。没有真实宿主检索结果时，协议夹具只能证明接入代码，不证明知识库连通。
