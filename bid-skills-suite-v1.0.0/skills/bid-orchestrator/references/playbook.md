# 投标编制总控｜专项操作手册

## 目标与完成边界

按任务范围调度16个业务技能，传递确切上下文、组织人工确认、识别变更和阻塞。。这里的完成是当前职责产物形成且检查清楚，不是对整个投标项目作通过判断。

## 核心操作细则

### 1. 投标编制总控子步骤1

明确模式：full完整编标、understand仅理解、review_only独立评审、revise补遗修订。没有项目目录时初始化，不自动调用外部服务。

执行记录应说明本步实际采用的文件、定位和决定；没有相关信息就保留未知，而不是套用行业经验。

### 2. 投标编制总控子步骤2

读取registry、各SKILL说明与项目产物；只读取本任务必要资源。核对原件、配置、输入版本与工具权限，不能依赖聊天隐式记忆。

执行记录应说明本步实际采用的文件、定位和决定；没有相关信息就保留未知，而不是套用行业经验。

### 3. 投标编制总控子步骤3

建立依赖图：01→02类别/标包识别与模板路由→03／04／05／06；四轨读取同一原文和路由版本后可并行。07→08→09→10；11／12／13按其输入生成；14→15→16。仅理解到四轨提取、报告和17交接为止。

执行记录应说明本步实际采用的文件、定位和决定；没有相关信息就保留未知，而不是套用行业经验。

### 4. 投标编制总控子步骤4

运行前检查前置。允许不完整资料上的限定范围探索，但标draft或blocked；不能让通用领域默认值补齐缺失事实。

执行记录应说明本步实际采用的文件、定位和决定；没有相关信息就保留未知，而不是套用行业经验。

### 5. 投标编制总控子步骤5

每个阶段开始及结束保存真实状态、范围、输入/输出版本与哈希；交接保存文件、摘要和未解决项。缺失的过去过程不能补造。ready仅表示该产物可继续使用，不代表人工签批或正式发标。

执行记录应说明本步实际采用的文件、定位和决定；没有相关信息就保留未知，而不是套用行业经验。

### 6. 投标编制总控子步骤6

按TENDER_ROUTING执行分类确认：清楚的候选分类可继续理解提取，类别/组合/标包有重大歧义或用户要求先确认时暂停相关分支；正式采纳理解范围、方案证据、关键承诺和成稿交付需要真实用户决定。等待确认时交付当前结果，不能假装继续后台处理。

执行记录应说明本步实际采用的文件、定位和决定；没有相关信息就保留未知，而不是套用行业经验。

### 7. 投标编制总控子步骤7

新增补遗或编辑产物时计算影响范围，将相关下游标stale或待核验；并发产生的草稿需以base_revision合并，不自动覆盖。

执行记录应说明本步实际采用的文件、定位和决定；没有相关信息就保留未知，而不是套用行业经验。

### 8. 投标编制总控子步骤8

结束时汇报本次实际完成、阻塞、待确认、下一步和文件清单；失败与未执行分开。程序校验通过不能替代真实业务验收。

执行记录应说明本步实际采用的文件、定位和决定；没有相关信息就保留未知，而不是套用行业经验。

## 场景差异怎么处理

智能工厂：关注业务范围、接口、数据、部署与验收；工程：关注工作范围、工序条件、资源与专业审查；设备供货：关注型号、数量、规格、交期与证明范围；服务：关注SLA、人员、交付物与考核。只有原文明确要求才进入explicit；场景知识只决定“检查什么”，不决定“客户一定要什么”。

政府或企业采购配置独立于行业配置。规则适用需确认，补遗与原文冲突需保留双方来源，不按名称或文件顺序机械裁决。可将多个领域包并列使用，但同名参数冲突应保持命名空间并发出澄清。

## 错误输出与改正

**错误风险 1：** 17段提示词不会自动形成可靠调度引擎。

**改正：** 返回相关原件/输入，明确本技能职责和未确定字段；保留问题，不以语言修饰替代核验。

**错误风险 2：** 同目录多智能体同时写文件需要额外锁或人工协调。

**改正：** 返回相关原件/输入，明确本技能职责和未确定字段；保留问题，不以语言修饰替代核验。

**错误风险 3：** 独立评审缺原文时不能给全面合规通过。

**改正：** 返回相关原件/输入，明确本技能职责和未确定字段；保留问题，不以语言修饰替代核验。

**错误风险 4：** 不能把“继续”理解为上传、付费、签署或发布授权。

**改正：** 返回相关原件/输入，明确本技能职责和未确定字段；保留问题，不以语言修饰替代核验。

## 缺工具时的降级

没有脚本权限：按输出契约填写并人工核验，声明脚本NOT_RUN。没有联网权限：不获取或宣称最新法规。没有图像／OCR／渲染能力：保留涉及区域待复核；已读文本可作限定范围探索，不作全面合格结论。
