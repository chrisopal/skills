# 08｜标书目录规划与覆盖映射

生成遵守强制格式且可证明覆盖需求与评分的目录，并为每个章节建立写作任务卡。

运行条件：需支持读取项目文件；可选脚本需要 Python 3.10+，文档、视觉/OCR 与绘图能力由宿主提供。

## 触发与边界

当用户提出“生成标书目录、技术标大纲、章节规划、需求到章节映射、强制目录补充。”时使用。不以行业通用目录覆盖客户强制目录，不把整段正文提前当作目录任务。

## 开始前

先读 [共同证据与安全约定](references/evidence-and-safety.md)。仅当需要细化操作时读 [专项操作手册](references/playbook.md)；输出字段与示例参见 [产物契约](references/output-contract.md)。

输入：03需求、04评分、05合规、06格式、07响应策略；02领域配置。

上游技能：`bid-requirements, bid-scoring, bid-compliance, bid-format-extraction, bid-response-strategy`。独立使用时接收用户提供的等价文件，记录实际输入，不要求虚构完整流程状态。检查原件和产物版本；缺关键信息时给出范围受限的草稿及缺口。

## 执行步骤

继续理解结果或执行目录/写作适配测试时，读[写作交接与实际检查](references/WRITING_WORKFLOW.md)。06识别客户结构不等于08已经创建目录；有条件的表单保留条件，不将招标人侧记录或不适用范本列为投标人必交项。限定测试可先保存候选目录，正式冻结仍落实真实确认。

1. **步骤1**

   先复制06中经确认的强制章节、分册及顺序，记录locked=true；必要补充放在允许位置，不能擅自改名或删减。

2. **步骤2**

   没有强制目录时，结合采购对象和07策略提出建议结构，并明确这是proposal而非招标原文要求。

3. **步骤3**

   分配稳定SEC-ID与parent_id，检查无循环、无重复序号、无孤儿；编号与ID分离，目录调整不能改变追溯身份。

4. **步骤4**

   将每条需求、评分叶子项、资格／提交要求映射到一个或多个章节。设置主责章节，避免“每章都提到一点”等同完整响应。

5. **为每章建立任务卡**

   目标读者、必须回答的问题、关联ID、输入证据、所需图表、边界、输出表格、验收检查。

6. **步骤6**

   检查所有强制项和适用评分项是否被覆盖；不能映射的保留unmapped_ids和原因，不随意新增无作用章节凑全。

7. **步骤7**

   从评审视角检查查找路径、重复承诺与内容位置，响应表与详细方案形成互引，不重复生成互相矛盾的描述。

8. **步骤8**

   输出目录树、覆盖矩阵和章节任务卡，人工确认后交09—14；变更目录时列出影响章节与评审失效范围。

## 产物与交接

保存 `08-outline.json`（机器可读）和同名 `.md`（可读报告），使用 [JSON模板](assets/output.template.json) 与 [报告模板](assets/report.template.md)。字段必须符合 [JSON Schema](assets/output.schema.json)。不要把模板空值直接当结果；详细演示见 [合成示例](assets/example.output.json)。

01—14产物放项目`artifacts/`，15放`reviews/`，16放`deliverables/`，17放`work/`。来源原件只读置于`inputs/`；图表置于`assets/`；规则配置置于`profiles/`。路径始终相对用户指定项目根，不写死本技能安装目录。

每个输出记录`project_id / artifact_id / revision / inputs / status`。`inputs`内SHA256从实际输入文件计算。缺依赖、未运行检查和待确认分别保留；不把模型产生结果等同于业务完成。

可选执行本技能目录内的校验器：

```bash
python scripts/validate_output.py /absolute/path/to/08-outline.json
```

脚本只校验结构及部分一致性，不检查所有真实语义与授权。依赖不足可按清单人工检查，但必须写明“脚本未运行”。

## 验收检查

- [ ] 强制节点没有被改名删减。
- [ ] 目录树无循环或孤儿。
- [ ] 适用强制需求与评分有映射。
- [ ] 每个章节有明确任务与证据。
- [ ] 未映射项公开展示。

## 人工确认点

强制目录变更、章节归属冲突及未映射项由人确认，冻结后再展开正文。

## 常见陷阱

- 标题含关键词不代表内容已覆盖。
- 父章节与子章节职责应分清。
- 附表不能因正文已有解释而省略。
- 页数目标不能驱动无意义扩写。

## 调用示例

> 请以客户强制格式为底座生成标书目录，把需求、评分、否决和证明材料映射到章节，并输出每章任务卡。

示例原件 `assets/synthetic-tender.md` 和 `assets/synthetic-supplier.md` 全为合成资料，不能用作真实投标证据。场景配置参考 `assets/profile-catalog.json`，所有条目只是待项目核验的种子，不是已通过业务验收的行业规则。

## 失败与恢复

先保存已完成的产物、失败范围和下一步；原件变更或输入哈希变化时重核受影响内容。不要自动覆盖人工新版本，不代签批，不上传资料，不声称已在后台继续运行。测试建议见 `tests/cases.json`；这些是待执行的业务评测用例，不是已通过记录。
