# 07｜需求澄清与投标响应策划

形成可确认的响应策略、澄清问题和风险决策，避免把生成建议直接写成对外承诺。

运行条件：需支持读取项目文件；可选脚本需要 Python 3.10+，文档、视觉/OCR 与绘图能力由宿主提供。

## 触发与边界

当用户提出“投标策划、澄清问题、响应策略、能力缺口、风险评估、编标优先级。”时使用。不自动决定参投、退出、报价或重大承诺；不联系招标方，不编造竞争情报。

## 开始前

先读 [共同证据与安全约定](references/evidence-and-safety.md)。仅当需要细化操作时读 [专项操作手册](references/playbook.md)；输出字段与示例参见 [产物契约](references/output-contract.md)。

输入：02项目画像、03需求、04评分、05合规、06格式；企业能力与限制的已知资料。

上游技能：`bid-project-profile, bid-requirements, bid-scoring, bid-compliance, bid-format-extraction`。独立使用时接收用户提供的等价文件，记录实际输入，不要求虚构完整流程状态。检查原件和产物版本；缺关键信息时给出范围受限的草稿及缺口。

## 执行步骤

1. **步骤1**

   合并03—06中未解决矛盾与缺口，保持原ID；按是否影响资格、可交付性、价格、周期或得分排序。

2. **步骤2**

   每个澄清问题说明来源、问题本身、决策影响、建议提问措辞和需要的回答，不发送给外部。

3. **步骤3**

   把企业已证实能力、待验证能力、不可承诺能力分开；关键缺口进入阻塞，不能通过修辞隐藏。

4. **步骤4**

   围绕高分项设计差异化响应，说明可提供的机制与证据；没有证据的卖点只保留为待验证建议。

5. **步骤5**

   形成章节优先级、资料责任人与确认点；先处理资格、强制项和高风险，再追求表达与美观。

6. **步骤6**

   拟定假设、约束和备选方案，标明何种用户决策会改变方案与报价。不得把待澄清假设转成客户确认。

7. **步骤7**

   对每个重大决策记录备选、理由、风险和需要的授权，不生成假签批或自动替用户接受风险。

8. **步骤8**

   输出响应策略和决策台账，经人工确认的范围进入08／10；未确认内容继续带标记，正式交付不可直接包含内部讨论。

## 产物与交接

保存 `07-response-strategy.json`（机器可读）和同名 `.md`（可读报告），使用 [JSON模板](assets/output.template.json) 与 [报告模板](assets/report.template.md)。字段必须符合 [JSON Schema](assets/output.schema.json)。不要把模板空值直接当结果；详细演示见 [合成示例](assets/example.output.json)。

01—14产物放项目`artifacts/`，15放`reviews/`，16放`deliverables/`，17放`work/`。来源原件只读置于`inputs/`；图表置于`assets/`；规则配置置于`profiles/`。路径始终相对用户指定项目根，不写死本技能安装目录。

每个输出记录`project_id / artifact_id / revision / inputs / status`。`inputs`内SHA256从实际输入文件计算。缺依赖、未运行检查和待确认分别保留；不把模型产生结果等同于业务完成。

可选执行本技能目录内的校验器：

```bash
python scripts/validate_output.py /absolute/path/to/07-response-strategy.json
```

脚本只校验结构及部分一致性，不检查所有真实语义与授权。依赖不足可按清单人工检查，但必须写明“脚本未运行”。

## 验收检查

- [ ] 每个重大风险有下一步动作。
- [ ] 策略与评分／需求关联。
- [ ] 确认与建议分开。
- [ ] 没有虚构竞争对手信息。
- [ ] 没有未经授权对外联系或商业承诺。

## 人工确认点

参投范围、重大差异、交期价格承诺与风险接受由授权人决定。

## 常见陷阱

- AI认为可行不等于企业资源已落实。
- 风险接受不能覆盖明确不满足的强制条件。
- 澄清问题应影响决策，不是复述原文。
- 不确定项不能在长文写作中被隐去。

## 调用示例

> 基于需求、评分和合规清单，找出需要澄清与决策的事项，提出有依据的响应策略，不替我做报价和重大承诺。

示例原件 `assets/synthetic-tender.md` 和 `assets/synthetic-supplier.md` 全为合成资料，不能用作真实投标证据。场景配置参考 `assets/profile-catalog.json`，所有条目只是待项目核验的种子，不是已通过业务验收的行业规则。

## 失败与恢复

先保存已完成的产物、失败范围和下一步；原件变更或输入哈希变化时重核受影响内容。不要自动覆盖人工新版本，不代签批，不上传资料，不声称已在后台继续运行。测试建议见 `tests/cases.json`；这些是待执行的业务评测用例，不是已通过记录。
