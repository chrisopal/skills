# 需求澄清与投标响应策划｜专项操作手册

## 目标与完成边界

形成可确认的响应策略、澄清问题和风险决策，避免把生成建议直接写成对外承诺。。这里的完成是当前职责产物形成且检查清楚，不是对整个投标项目作通过判断。

## 核心操作细则

### 1. 需求澄清与投标响应策划子步骤1

合并03—06中未解决矛盾与缺口，保持原ID；按是否影响资格、可交付性、价格、周期或得分排序。

执行记录应说明本步实际采用的文件、定位和决定；没有相关信息就保留未知，而不是套用行业经验。

### 2. 需求澄清与投标响应策划子步骤2

每个澄清问题说明来源、问题本身、决策影响、建议提问措辞和需要的回答，不发送给外部。

执行记录应说明本步实际采用的文件、定位和决定；没有相关信息就保留未知，而不是套用行业经验。

### 3. 需求澄清与投标响应策划子步骤3

把企业已证实能力、待验证能力、不可承诺能力分开；关键缺口进入阻塞，不能通过修辞隐藏。

执行记录应说明本步实际采用的文件、定位和决定；没有相关信息就保留未知，而不是套用行业经验。

### 4. 需求澄清与投标响应策划子步骤4

围绕高分项设计差异化响应，说明可提供的机制与证据；没有证据的卖点只保留为待验证建议。

执行记录应说明本步实际采用的文件、定位和决定；没有相关信息就保留未知，而不是套用行业经验。

### 5. 需求澄清与投标响应策划子步骤5

形成章节优先级、资料责任人与确认点；先处理资格、强制项和高风险，再追求表达与美观。

执行记录应说明本步实际采用的文件、定位和决定；没有相关信息就保留未知，而不是套用行业经验。

### 6. 需求澄清与投标响应策划子步骤6

拟定假设、约束和备选方案，标明何种用户决策会改变方案与报价。不得把待澄清假设转成客户确认。

执行记录应说明本步实际采用的文件、定位和决定；没有相关信息就保留未知，而不是套用行业经验。

### 7. 需求澄清与投标响应策划子步骤7

对每个重大决策记录备选、理由、风险和需要的授权，不生成假签批或自动替用户接受风险。

执行记录应说明本步实际采用的文件、定位和决定；没有相关信息就保留未知，而不是套用行业经验。

### 8. 需求澄清与投标响应策划子步骤8

输出响应策略和决策台账，经人工确认的范围进入08／10；未确认内容继续带标记，正式交付不可直接包含内部讨论。

执行记录应说明本步实际采用的文件、定位和决定；没有相关信息就保留未知，而不是套用行业经验。

## 场景差异怎么处理

智能工厂：关注业务范围、接口、数据、部署与验收；工程：关注工作范围、工序条件、资源与专业审查；设备供货：关注型号、数量、规格、交期与证明范围；服务：关注SLA、人员、交付物与考核。只有原文明确要求才进入explicit；场景知识只决定“检查什么”，不决定“客户一定要什么”。

政府或企业采购配置独立于行业配置。规则适用需确认，补遗与原文冲突需保留双方来源，不按名称或文件顺序机械裁决。可将多个领域包并列使用，但同名参数冲突应保持命名空间并发出澄清。

## 错误输出与改正

**错误风险 1：** AI认为可行不等于企业资源已落实。

**改正：** 返回相关原件/输入，明确本技能职责和未确定字段；保留问题，不以语言修饰替代核验。

**错误风险 2：** 风险接受不能覆盖明确不满足的强制条件。

**改正：** 返回相关原件/输入，明确本技能职责和未确定字段；保留问题，不以语言修饰替代核验。

**错误风险 3：** 澄清问题应影响决策，不是复述原文。

**改正：** 返回相关原件/输入，明确本技能职责和未确定字段；保留问题，不以语言修饰替代核验。

**错误风险 4：** 不确定项不能在长文写作中被隐去。

**改正：** 返回相关原件/输入，明确本技能职责和未确定字段；保留问题，不以语言修饰替代核验。

## 缺工具时的降级

没有脚本权限：按输出契约填写并人工核验，声明脚本NOT_RUN。没有联网权限：不获取或宣称最新法规。没有图像／OCR／渲染能力：保留涉及区域待复核；已读文本可作限定范围探索，不作全面合格结论。
