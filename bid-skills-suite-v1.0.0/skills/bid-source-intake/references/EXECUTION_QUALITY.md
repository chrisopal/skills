# 招标理解的执行与语义复核

## 按范围执行

用户仅提供招标文件并要求处理时，可先以understand形成01—06候选结果。初始化使用`bidkit.py init --mode understand`，项目元数据与17的mode保持一致。完整编标需要后续证据、方案、承诺和成稿确认，不为流程齐全生成空的已完成记录。

阶段开始前保存实际输入及running状态；完成后保存产物路径、revision、结果和下一步。17是文件交接，不是后台调度引擎。不得根据最终文件反推不存在的过程记录。首次执行保留模式选择依据；恢复时读现行输入索引，不依赖聊天记忆。

## 原件读取与条款拆分

原生解析可保留全部页文字，但逐页拆条仍可能截断语义。01保留页边界与定位；03以连续章节理解，逐项检查页末与下一页首的接续。跨页条款分别引用各页，不编造单页包含完整原句。

- 清理页眉页脚、章节标题和签署空表，不能让它们并入上一条功能。合同联系人填报等要求可以保留，但应标为商务/交付内容。
- 没有编号的团队、环境、安全、质量、培训等自然段同样处理。分条不得丢共同条件、否定、AND/OR、版本下限、数量、单位和时限。
- conditions填写实际限制；未明示验收依据时acceptance留null，不填“按原文核验”等套话后声称原文明示。
- 对同一修订保留稳定ID；合并、拆分和删除保存旧新ID映射。conflicts只引用现行需求ID。

## 原文与执行说明的权威

所有项目金额、日期、型号、资格和后果从登记原件或有来源的真实用户补充取得。调度消息、前一轮摘要和模型观察可能有误，不能据此伪造“用户说了某金额”，也不能制造并不存在的原文冲突。

引用校验只证明文字出现在来源中。还应确认引用能支持该项判断：仅引“否则不通过”不足以说明哪个资格条件触发；仅引条件也不足以认定明确否决。05须保留适用条件和原文明示后果，中标后违约责任不自动变成投标阶段否决。

## 格式与模板适用性

06先核对投标文件组成条款，再对照格式章节。通用范本中的表格、未选选项或说明不自动成为本项目必交内容；明确mandatory、reference、unknown及依据。未实际生成模板时template_path为null，用原PDF定位；有路径时核对文件确实存在。封面、报价表等若未明示项目适用性，保留待核验，不擅自删除原模板。

## 三层检查与修复记录

分别报告结构/哈希检查、语义与视觉抽查、真实业务确认。程序通过不代表全文语义无遗漏或用户已批准。抽查至少覆盖金额、期限、资格/否决、评分选择项、付款累计节点、跨页条款、服务时限、模板适用性及所有已发现冲突。

将本次问题保存为项目`work/execution-review.md`：问题、影响、证据位置、当前产物修正、套件修复、复测及仍未验证部分。项目原件和客户信息保存在项目目录；套件`docs/KNOWN_ISSUES.md`只保留可复用的匿名问题，不收录客户原件。独立安装没有该套件台账时，以项目执行记录为准。
