# 界面图内容复核与修复

适用于宿主生图产生的系统界面示意。图像已存在或已插入只证明生成与入稿，不证明需求、文字或连线正确。真实系统截图仍须来自授权材料。

## 生成前冻结

从当前需求、方案与正文提取本图要表达的操作。规格记录 FIG-ID、章节、需求来源定位、输入版本与哈希，以及必须逐字一致的名称、数值、角色和有向关系。不要把所有文字都当作状态：指标卡可以表达统计口径，但须解释口径，不能引入与原文冲突的新状态。

例如原文明示六状态“事件登记、工单派发、接单、处置、复核、归档”及“复核不通过须退回处置”，规格须分别写出状态全集与 `复核 → 处置，条件：不通过`。箭头标签正确不证明起点和落点正确。

## 修复策略

1. 实际打开采用版，记录错误所在区域、观察到的文字或起止节点；不以提示词、替代文本或生成器自述代替画面回读。
2. 先做单一目标编辑并另存版本，再复查整张图。局部修复可能使其他文字回退，旧版与新图哈希均需保留。
3. 多次文字回退时，减少表格行数、标签和无关统计。将操作界面与复杂状态图分成两张图：界面仍调用宿主原生生图，流程用已配置的矢量引擎绘制。不要在界面图中保留失效箭头，也不要用矢量流程图抵充必配界面图。
4. 界面聚焦真实操作语义，例如“当前状态：复核”“复核通过”“退回处置”及退回原因。六状态全集与退回路径在配套流程图准确表达；如果任务要求界面自身显示全部状态，则仍须在界面中逐字核对。
5. 若还有不一致，保留 rendered 与具体待整改项；不要选择“最接近”的图片后宣称 reviewed。受影响正文、评分判断及导出应重新核验。

可复用提示词骨架：

> 生成／编辑当前宿主的系统界面设计示意。章节与操作：……。必须准确显示：……。数据全为模拟。聚焦一个操作，减少小字与重复标签。流程关系另见配套矢量图，本界面不绘制装饰性流程箭头。保留“界面设计示意，非实际系统截图”。输出后实际逐字查看，未满足项如实记录。

## 回读和关闭问题

保存本次宿主、实际工具、工具返回的模型（未返回则写未确认）、提示词、输入图与输出文件的 SHA256。内容复核记录写明采用图路径／哈希、核对的原文和正文版本、逐项观察结果、未解决项；在图的 specification 中关联该记录。截图或多模态阅读只证明本次观察，不认证实际系统能力。

检查名称与数值、字段与角色、状态选项、连线起止点／方向／条件、图注及示意属性。再在最终 Word/PDF 的实际版心查看中文可读性、裁切、图注、顺序和正文关联。改图后旧回执失效；仅更新路径或哈希不能冒充重新复核。关闭 FIND-ID 必须引用新图及实际复核结果。

内容复核、A4 排版、评分条件满足和正式交付是独立结论。文件计数、CLI 渲染收据及 Schema 校验都不能代替这些检查。
