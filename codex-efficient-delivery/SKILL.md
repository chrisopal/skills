# Codex 高效交付

优化每个通过验收的交付单元所需的成本与返工，而不是仅减少回答长度。保留必要的调查、实现和验证；不以省 token 为由提前结束已授权工作。

## 先判断是整理需求，还是执行任务

- 用户说“我没说清楚”“先帮我理一理”“帮我问清楚再写提示词”，进入澄清模式，不因提到“开发”“实现”就开始修改业务代码。
- 即使用户没有明确要求澄清，若目标、交付物、范围或关键业务规则存在会导致不同实现方向的歧义，先澄清。不要把口语、错字本身当作必须访谈的理由。
- 需求已经明确且用户要求执行时，直接推进。已确认的任务卡不用重新访谈；常规实现细节由代理决定。
- 用户只要求优化提示词时，交付提示词即可；这不意味着已授权执行该提示词。

## 澄清到可执行

先从当前对话、现有任务卡提取已知事实和用户已作出的决定，用一两句话复述目标。项目代码能回答的问题先做小范围只读核实，不把文件定位、现有技术栈等问题转交给用户，也不在业务目标不清时全面扫描仓库。

只问会改变实现或验收的问题。每轮通常 1–3 个，优先问：给谁使用、要解决什么问题、做完后能完成什么操作、本轮边界是什么。需要业务选择时给出少量易懂选项和推荐理由，允许自由回答；不要要求用户决定类名或内部实现。工具允许时使用异步提问，并继续不依赖答案的只读工作。

根据回答只追问尚未解决的关键分歧，不重问已回答问题、不设机械的访谈轮数。能合理决定的低风险细节列为假设；影响数据模型、权限、兼容性、外部操作或主要交付范围的未知项不得伪装成已确认事实。等待时间不能代替答案。

当以下信息足够明确时停止提问：
- 使用场景与期望结果；
- 本轮交付物、范围及暂缓项；
- 会影响实现的关键约束；
- 可观察的验收行为和必要证据。

## 生成最终任务提示词

把澄清结果整理为一段自包含、可直接粘贴给 Codex 的提示词，不保留访谈流水账。只保留相关字段，不为凑模板添加未知事实：

```text
任务：[一句话交付目标]
项目位置：[已知路径；未知且执行必需时先澄清]
背景与使用场景：[谁遇到了什么问题]
本轮目标：[完成后可观察的行为]
实现范围：[功能及已核实的模块]
暂缓项：[明确排除的工作]
已确认约束：[业务规则、兼容性、权限等]
可自行决定的细节：[低风险假设，必要时列出]
验收条件：[行为及对应测试、API、存储或页面证据]
执行要求：先核对相关实现，复用现有模式；按本轮范围完成修改和必要验证。
遇到会改变主要范围的未知问题再澄清，其余常规选择自行处理。
输出：改动摘要、验证结果、剩余限制；需要跨阶段时补简短交接。
```

提示词应遵守本技能后续的上下文、分工和验证规则；交给无法读取本技能的执行者时，把必要规则简短带入，不能只写“按之前约定”。不要把模型建议写成已经发生的模型切换，不加入未获授权的推送、部署或外部消息发送。

澄清模式下，若用户尚未授权最终范围，先展示完整提示词，再请其确认或修正；说明确认是为了核对刚整理的范围。用户确认后，在当前任务内执行，不重复审批。若用户已明确授权“澄清后自行执行”，关键答案到齐后展示整理结果并直接执行。只改局部需求时更新相应条目，保留其余已确认决定。

“交给 Codex”默认交付可复制提示词；只有用户明确要求新建任务或发到指定现有任务时才使用任务工具。目标不明确时先询问，不能猜测目的任务。发送前应已展示可审阅内容，并具有对应授权；不能声称已发送实际未发送的提示词。

## 判断示例

- “本体这块帮我搞好，我也没想清楚”：复述当前理解，先问使用场景和这轮期望的操作链路，不直接设计整套治理平台。
- “把刚才讨论整理成执行提示词，先别改”：交付整理后的提示词并保留真实待确认项，不执行。
- “按已确认任务卡修复发布接口并运行定向测试”：读取任务卡和相关实现后执行，不重新访谈。
- “前面的范围确认，开始做”：执行已展示的范围，不再询问是否开始。

## 控制探索与上下文

- 优先读当前任务卡、简短交接及相关代码；先定位文件或符号，再读取必要片段。已有结论按漂移风险定向复核，不重复全仓审计。
- 批量执行独立的轻量检索。长日志保存在文件中，读取失败位置和必要上下文；扩大读取范围应有具体疑问驱动。
- 不把所有历史聊天、设计文档或工具输出一次性带入。阶段目标发生变化时建议简短交接并新建任务；不擅自创建任务，也不在本轮未完成时借此停工。
- 允许正常自动压缩，不为保留冗长历史而规避压缩。此技能不自动修改配置、模型或当前任务设置。

## 模型与分工

尊重用户显式模型、推理强度和预算。以下是本工作流偏好，不是价格保证：清晰任务卡的实现优先 Sol / low；本体或跨模块设计优先 Sol / medium；具体难题在充分定位后仍无法收敛，可建议 Astra / medium 处理该问题。模型不可用时使用当前可用的适当模型，不猜测别名或宣称已经切换。用户要求当前价格或额度比较时另行核实。

普通工作由主代理直接完成。仅为实质性、独立且有明确结束条件的子任务分工，最多两个子代理、一个深度层级，遵守环境更低的限制。子代理不再分派任务。

分派时提供目标、文件责任、必要背景和验收条件；能用自包含说明就不继承完整历史。代理完成后结束其职责，不跨无关阶段长期复用。不把并发限制变成依次启动大量小代理，不为状态检查或未变化代码反复启动审查代理。

## 验证与结束

按实际风险选证据：代码改动运行受影响测试；持久化链路验证 API 和存储读回；页面行为验证关键操作。全量检查在项目规则要求或影响范围需要时运行。命令成功、截图或代理总结不能代替对应业务验收。

通过验收后结束本轮。只有新改动、失败或未解决的具体疑点才触发重复检查。不要为节省用量跳过失败修复，也不要无故追加重构、依赖或审查轮次。

最终简述改动、验证证据和剩余限制。跨阶段需要交接时使用以下模板，可直接写在回复中；仅在用户请求或任务需要持久交接时创建文件：

```text
当前目标：
已确认决定：
已完成改动及相关文件：
已运行验证与结果：
剩余问题：
分支或工作树：
下一步：
```

不虚构精确 token 节省比例。若用户提供明确预算，使用可用计量并披露统计边界；没有预算就不自行创建定时任务、持续目标或额度重置操作。
