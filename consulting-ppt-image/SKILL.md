# 咨询型图片PPT制作

## 1. 职责与输入

你负责“怎样呈现”，上游咨询成果负责“讲什么”。使用 `slide-content-pack.json` 固定内容交接边界；与仓库已有PPT技能并存，不覆盖它们的主题或可编辑模式。

优先读取当前内容包、页级清单、最后确认的风格和原图版本；不得靠对话中零散记忆续页。先读 [输入契约](references/content-contract.md) 和 [生产流程](references/workflow.md)。

允许：布局、视觉层级、图形表达、无损原图组装，以及不改变含义的文案压缩草案。
禁止：擅改已批准的结论、数值、时间、架构对象、流程顺序、依赖、引用或审批状态。需要改变时，提交变更清单，取得确认后由上游更新内容包。

只有原始资料时：先提取事实、待确认项和故事线草案，所有页标 `draft`；不得把推测补成事实。用户要求研究扩展才补外部来源，明确区分原资料和外部研究。

## 2. 任务路由

| 用户意图 | 执行模式 |
|---|---|
| 从方案开始做PPT | 内容契约检查 → 故事线确认 → 风格锁定 → 逐页生成 |
| “继续后十页” | 读取全稿清单，按实际 order 确定范围；不重新写目录 |
| “重做21—30页” | 只创建这些页的新版本，保留稳定 slide_id 与其他页 |
| “故事线混乱/展厅重复/工厂拆开” | 全稿审查 → 新旧页映射草案 → 确认变更 → 重新绑定受影响页 |
| “把已生成图片原样合成PPT” | 只按已选版本组装；不生成、不重排、不裁剪、不修图 |
| 要可编辑PPT | 交回可编辑PPT技能；本技能不把单张图片冒称可编辑页面 |

## 3. 关键约束

1. **全稿唯一清单**：每页有稳定 `slide_id`、实际 `order`、章节、唯一 `purpose_id`、核心结论、视觉结构与证据。
2. **章节连续**：同一主体连续讲完；禁止工厂→展厅→工厂的跳回。原理总览与专题细化要说明不同职责，不同义重复。
3. **页数守恒**：批准35页即按35页生产。删重复页不自动凑数；新增、删页或移序先提交差异并确认。
4. **样式锁定**：默认读取 [主题文件](assets/white-inkgreen.json)；白底、墨绿、深灰、浅绿，标题/字体/线条统一。不同布局不等于不同主题。
5. **单页独立生成**：一次图像任务只生成一个完整页面。禁止把十页合成一张图再当交付；联系表只用于内部QA。
6. **事实不漂移**：无来源的百分比、ROI、认证、政策结果、产能和已实现成果不得出现在图中。
7. **案例实名且同源**：企业/园区实体、来源截图和分析必须对应；同集团的不同企业也不能混称。截图不交给图像模型“凭空还原”。
8. **成品版本明确**：生成即单独保存，登记路径、哈希与版本。不以 `imagegen.png`、修改时间或模糊文件名自动挑最终稿。
9. **两次验收**：逐页检查内容和图像；全稿检查重复、断层、顺序与技术逻辑。机器检查不能替代视觉与事实判断。
10. **最终一图一页**：汇总模式每页只能有一张已确认原图，图像字节不变，等比放置，无附加可见对象。

## 4. 顺序工作流

### A. 锁定故事线
- 根据完整资料与决策目标建立页级清单。每页回答一个问题，明确前后承接。
- 逐页定义“一句话结论＋2—4组支撑内容＋视觉关系”。不能用软件模块名代替业务逻辑。
- 运行结构检查。数目、章节中断、重复标题/用途、未知引用或依赖错误必须处理；语义重复仍需人工/模型阅读全文判断。
- 原方案不足时标待确认，不为补足35页编造信息。

### B. 锁定风格
- 使用同一个主题版本；参考已确认页面。已有确认样式时直接继承，不重复索取确认。
- 新项目首次可选架构、流程、场景三类页面验证风格，再批量推进。
- 在 [视觉规范](references/visual-system.md) 中按内容关系选布局：价值链、架构、泳道、案例、矩阵、场景、甘特图；不默认全部卡片。
- 公开版不附客户图片。由用户提供已授权参考页，在私有工作区中按需打开；不复制参考图里的客户事实、数值或概念图作为新项目实景。

### C. 逐页生成
- 调用 `scripts/ppt_pipeline.py plan` 输出每页独立任务。批次是队列分组，不是拼图指令。
- 先查看宿主可用工具及真实schema。支持文本prompt时使用该任务；工具从对话上下文推断指令时，将任务放入上下文。不得臆造参数、模型、路径或图片ID。
- 选择真实图像生成工具。此包脚本不调用模型，也不自带图像服务。没有图像工具时报告缺口、交付文案/清单/任务，不能冒充生成完成。
- 每次只执行一页；结果立刻保存并register，再执行下一页。失败只重试本页，默认最多2次后报告原因。
- 案例或精确图表需保留原始截图/几何关系时，允许在批准前采用“生成视觉＋确定性合成原素材”的流程，并说明采用了合成；用户要求原图汇总时禁止任何此类加工。

### D. 验收与选版
- 用真实图像查看工具逐页读清标题、文字、图例、连线、数字、页码；不要仅凭文件生成成功判断合格。
- 按 [QA清单](references/quality-gates.md) 完成审校。使用 [审校记录模板](templates/slide-review.json)，只有真的检查过才能填true。
- 脚本检查哈希、比例、顺序和状态；“白底、文字正确、不是拼图”等是视觉审阅声明，不能把该声明说成机器识别结果。
- 用户确认某页/某批，或明确授权Agent代审后，记录确认依据并select该版本。没有确认不能把任意历史图片当最终稿。
- 不因用户说“继续”就重置总页数、插入结语或恢复过期版本。

### E. 续做、修改与组装
- 续做先读取manifest，核对已完成、待生成、被替代版本，按当前order解释“21—30”。
- 核心内容/页序变更使用新的内容包版本与显式sync确认；受影响图片被解除最终选版，保留旧版历史。
- 页码烧录在图片中时，改顺序/总页数通常需要重新生成受影响图片。用户只许原样组装时，不悄悄改页码，说明冲突。
- 通过最终audit后运行assemble。它只按manifest中的selected_version取图，不扫描目录排序。
- 用户明确要求某一批的PPT时传 `--range`；这是部分稿，不得称完整35页。
- 交付完整PPTX和必要的独立图片/索引，给出实际生成文件链接；不要把内部QA联系表当主交付。
