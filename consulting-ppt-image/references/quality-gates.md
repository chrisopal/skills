# 质量门禁：可检测与需要判断的部分分开

| 已发生的问题 | 本技能的预防方式 | 检查类型 |
|---|---|---|
| 35页只生成30页 | page_budget与连续order完全一致；完整导出要求每页已选图 | 机器 |
| 同一工厂被展厅分开 | 声明章节順序并拒绝A-B-A | 机器＋全稿审阅 |
| 展厅定位反复出现 | 唯一purpose_id/标题检查；看本页问题及核心结论 | 机器仅查精确重复，语义需审阅 |
| 中间出现结语 | closing只能处在最后一页 | 机器＋审阅 |
| 改版混入旧图片 | 最终只取selected_version与对应内容/主题签名 | 机器 |
| 十页合成一张图 | 一页一任务；视觉检查single_page | 任务约束＋视觉，非自动识别 |
| 背景花纹/蓝绿交替 | 固定主题、同一参考页、逐页对比 | 视觉，配置哈希不证明像素一致 |
| 引用品牌错配 | entity_id一致；查看真实截图与文字来源 | 元数据机器检查＋证据核验 |
| 甘特图日期矛盾 | 上游日期/FS依赖/前置里程碑校验，视觉复核图中坐标 | 机器＋视觉 |
| PPT图片被重新加工 | 嵌入字节哈希与原始已选文件逐页一致 | 机器 |

## 每页视觉检查（review JSON的七项）

1. `single_page`：确为一个完整页面，不是联系表、多页拼图或缺角截屏。
2. `text_fidelity`：标题、正文、术语、数值、单位、日期与批准内容一致，无乱码。
3. `visual_style`：纯白外背景、墨绿主题、统一字体/页码/图标，无装饰角标。
4. `layout_readable`：主体层次、箭头、文字可读，无重叠/截断/歧义。
5. `evidence_and_labels`：案例截图同源；概念、建议、演示值和来源标注正确。
6. `page_number`：烧录页码与当前order/总页数一致。
7. `no_invented_facts`：未把视觉模型补出的数字、工艺、产品或认证当事实。

不能不看图就把七项全部设true。脚本仅校验审阅声明结构与图片哈希，不保证声明真实。

## 全稿审阅

只读标题能否形成一条连贯的判断链？每章是否先全景后专题？总览的核心对象是否在专题中有承接？技术底座是不是意外多画了一套？工厂透明制造的数据形成与展厅的数据展示是否清楚分工？路线图的能力阶段与甘特图的时间是否相容？结尾是否留下明确决策与行动？

## 完整交付

输出前要求：最终审计通过、来源缺口已处理或经用户明确披露接受、所有图片选版有依据；PPT页数正确且每页只有一张图片。局部批次可以单独导出，但必须标明是部分稿。

不存在“只要装上SKILL就百分之百不犯错”的保证。脚本可拦截可枚举的生产错误；内容判断、图像质量、证据真伪仍需要审校。
