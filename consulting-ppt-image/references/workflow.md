# 可恢复的生产流程

## 1. 开始前

读取brief、源文档、内容包、上一次确认信息。使用已有文件读取工具；对含图表/截图的资料直接查看页图，不能只看抽取文字。跨会话要从可访问的文件恢复，不从记忆猜路径。

尚未形成故事线时输出 `storyline-proposal.md`，逐页写“回答的问题—核心结论—内容范围—与前后页关系—来源—待确认项”。确认后生成内容包。任何无证据的商业假设都明确标为建议。

## 2. 阶段门禁

- G0 内容与故事线：总页数、章节、页级任务、事实与责任边界明确。
- G1 视觉样式：颜色/字体/留白/图形语言锁定；示范页得到实际确认。
- G2 每页图像：真实打开结果，核对7类视觉检查项，登记唯一版本。
- G3 整套叙事：按当前顺序通读标题和内容，消除重复、跳回、缺失、提前结束。
- G4 交付文件：按已选图片顺序组装，检验页数、每页单图与图像哈希。

## 3. 分批不分裂

批准35页后，可以生成1—10、11—20、21—30、31—35。每批仅是相同清单的切片，不是重新生成一个10页或30页的独立方案。示例中“工厂17—25、展厅26—30”必须保持连续；其他项目范围按本项目清单，不硬套这些页码。

任务队列中必须包含前页和后页标题、所属章节、当前总页数、已锁定主题、该页唯一任务。只画当前页面，不能将上下文也画成同一张多页合辑。

## 4. 修改与版本

用户说“换前十页”，先确定明确的十个逻辑页及用户指认的版本。不能从文件名“更新版/最终版”判断，也不能扫描所有PNG取最新10个。

内容变更：先生成diff，标记保留、移动、合并、删除、新增，记录确认。上游发布新版内容包，调用sync。旧图保留，但签名改变的页解除最终选版。标题/页码修改属于图片变化，需要登记新版本后复核。

配色或字体变更：作为独立主题版本，新建批准后的生产项目；旧主题图不能混入。不能直接编辑style-profile.json绕过主题锁。

“不要做任何加工”：进入assemble-only；不校色、重绘、裁边、补页脚或统一页码。发现错误时说明具体页并等待授权修订，不能同时声称原图未改且已修正页码。

## 5. 崩溃恢复

每张结果立即复制到 `renders/Sxxx_vNNN.png` 并写manifest。后续会话读取manifest，从未生成或未确认页面继续。网络/生成工具失败不修改其他页。

文件版本不可覆盖。脚本是单写者工具，不支持多个进程同时改同一manifest；并行生产应由单一协调者串行登记结果。
