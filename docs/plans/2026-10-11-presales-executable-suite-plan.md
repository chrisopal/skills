# 售前技能套件可执行落地计划

依据已确认的通用 B 端流程设计和 2026-10-11 模拟验证，用户授权继续实现、验证并推送。

## 范围

以 `presales-solution-skills/` 发布10个可独立发现的技能，安装后仍保持兄弟目录引用。语义工作由调用技能的 Agent 完成；Python 工具负责原件快照、结构化交接、哈希依赖、审核有效性、PPT输入白名单及文件验收。不引入新模型服务、任务平台或PPT引擎。当前默认接入用户指定的本地 `ppt-master-plus`。

## 已观察到的失败基线

前一轮独立初审发现现状/目标混淆、提交时间遗漏、方案到页面缺少ID及版本链，见 `2026-10-11-presales-ppt-master-plus-validation.md`。本轮技能的结构化字段和语义核验必须覆盖这些真实失败，而不只检查文档标题是否齐全。

## 文件责任和顺序

1. 主代理：技能入口、共享契约、PPT适配说明、模板、完整安装/调用文档、独立前向测试与交付整合。
2. runtime 子任务：标准库CLI及先失败后实现的测试；只管理确定性的状态与证据，不替模型作语义或视觉判断。
3. packaging 子任务：只读原文提取和无覆盖安装器及测试；缺少解析能力时产生显式读取缺口。
4. 待接口齐备后，在独立目录按新Skill从混合原件走到内容包、真实PPT交接、实际文件审核；复用已验证且内容未变的渲染资产需明确说明，不能冒充重新生成业务内容。
5. 根据发现修复，运行全套适用检查，安装到本地技能目录，核验相对引用和文件hash，提交并推送相关源码/文档。生成文件仅留本地。

## 验收

- 10个技能可被单独调用，入口包含适用请求、输入、执行、输出、完成条件和异常去向。
- 安装冲突不能覆盖用户现有技能；新安装和重复同内容安装均可验证。
- 提取保留原文定位和hash；图片/扫描材料未核验不能标完整读取。
- 内容包必需字段、稳定ID、精确依赖与独立内容审核可检查；原件或中间成果变化使下游及旧审核失效。
- PPT交接不泄漏内部台账字段，保留逐页事实锁与可见限定；缺审核/旧审核/阻塞发现不能输出正式制作包。
- 实际PPT缺页、页序错、输出文件或渲染证据被修改可检出；结构通过与Agent目视判断分开。
- 至少一条完整本地项目执行记录；负向测试覆盖哈希失效、无效审核、输入缺失、路径越界、PPT篡改。
- 报告安装技能、代码验证、语义前向验证、真实文件生成/复用、业务批准分别是什么状态。
