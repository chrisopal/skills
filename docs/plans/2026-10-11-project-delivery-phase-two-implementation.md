# 项目交付 Skills 第二批实施计划

按已批准设计第二批执行：新增实施设计、UI/字段/权限、接口/迁移、工作包、测试/UAT、上线回滚、培训运维移交 7 个 Skills；质保收尾和外部系统适配保留第三批。

## 产物与责任

- 专项 Skills/模板独立编写，复用第一批来源、需求主账、版本与变更机制；蓝图保留业务确认主责，详细设计通过精确引用关联，不复制需求主账。
- 运行工具增加 7 类产物和可解释门槛，绑定需求、设计、构建、实际运行/复测、回滚恢复与接收证据。结构检查不认证证据真实性，也不执行生产操作。
- 资源/成本主账增加可选人员周期容量、分配和逐项剩余工作、同一采购部分发生/承诺余额、独立付款条件；兼容原有台账，禁止重复计算。
- 可视化沿用 Enterprise UI Design 蓝色规范；仅扩展真实产物名称和字段显示，不新增假操作。

## 分段验证

1. 设计段：结构、需求覆盖、字段权限状态、接口映射/迁移对账，缺字段与断引用应拒绝；未知第三方条件保留阻断。
2. 工程与质量段：工作包映射至计划；构建与测试精确对应；未执行不能通过，关闭缺陷必须同构建复测，UAT 有条件确认不能当通过。
3. 上线移交段：就绪与实际执行分开；失败/回滚失败保留问题；恢复证据及培训能力验证/运维接收独立检查。
4. 经营段：超负荷、未知费率、外包替代、部分发生和付款不重复计算。
5. 衔接演练：本地模拟软件集成项目运行真实工程检查，保存原始输出并登记，覆盖七类新产物；模拟审批与生产上线明确隔离。
6. 全量回归、Skill 元数据、模板覆盖、Office 导出/回读和新增文档实际渲染；安装回读后提交并推送。

## 验证边界

自动化证明版本绑定、计算和可检测门槛；独立业务阅读检查结论是否被原始材料支持。没有真实客户合同/权限/环境，不能声称客户验收或生产上线。演练文件留在 output/，只提交可复用源文件、模板、测试和文档。
