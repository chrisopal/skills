# GTM 推广与商机关联

## 范围与决策

新增 opportunity-gtm 入口，复用现有 Python/SQLite/本地 HTTP 工作台。先以国内 B2B 企业、中国省级行政区划与城市点位沙盘实现；国家/行业不硬编码。真实推广要客户提供产品、目标客户、区域、周期；未提供时仅使用标明的工业视觉质检演示。公开研究与模拟跟进分开标注。

考虑过三种结构：纯报告缺少持续跟进；独立营销系统重复主账；选择同一数据库的 GTM 计划记录＋共享商机引用。保留市场候选与销售商机边界，不把搜索结果当成需求、触达或客户认可。不新增依赖、地图服务、账号或自动营销发送。

## 输入输出与业务路径

产品/卖点证据、ICP/角色/排除条件、区域、截止日和预算（缺失保持未知）→ 搜索任务 → 来源事实 → 企业/区域、展会论坛及渠道候选 → 适配理由/可解释优先级 → 分角色、分渠道话术草稿 → 跟进事实 → 显式关联同客户商机 → 按区域/渠道/活动分析。

官方站点优先；每个发现保留 URL、访问日期、摘要及推断。活动时间、地点、届次、主办方与报名情况分开，不将历史活动作为未来可参会项目；未知日期不排序成近期。话术不得虚构痛点、关系、案例效果、承诺或个人联系方式。发送、报名和费用支出沿用用户具体授权，Skill 本身只准备资料。

## 数据与接口

GTM 单独计划状态存在 gtm_campaigns，复用现有事务、request_id 去重与 revision 乐观锁，不修改商机评分/阶段。所有变更用 gtm-manage 包络：campaign_id、request_id、expected_revision、actor、operations。create_campaign 初始 revision0；upsert_source/target/event/message 更新候选；record_touch 追加不可覆盖跟进；link_opportunity 只关联存在且同企业的商机，要求有效 qualified 跟进事实。link 不替商机建立确认事实或推进阶段。查询动态读取原商机当前阶段、评分、签署状态及金额口径。

GET /api/gtm/campaigns、GET /api/gtm/campaign/{id}、POST /api/gtm/manage 与现有 HTTP 安全边界一致；CLI gtm-query/gtm-manage/gtm-brief。gtm-brief 根据产品/ICP生成可执行检索任务，Agent 使用现有搜索能力采集并回写带来源记录；HTTP 不假装后台已有搜索引擎。

## UI Blueprint

/GTM 独立专业面，与商机工作台互相导航。计划选择与产品/ICP概要 → 紧凑漏斗 → 地理点位沙盘＋选中对象详情 → 企业/展会论坛/渠道/话术/跟进/分析页签。来源与推断可展开；筛选区域、对象类型、关键词并联动地图和明细。地图使用有来源的中国省级行政区多边形与Mercator投影，保留34省名称、港澳台及南海附图。全国→省份→城市逐级导航；475个下辖单位标注按省展开，不将全量名称挤在全国地图上。城市中心明确近似；台湾市县点位来源缺失保持提示；未知对象位置留在列表，允许缩放与重置。本地地图数据与独立地图显示模块随安装器分发，运行不调用外部地图服务。地图可键盘选择，明细列表提供等效路径。

真实表单：创建计划（产品/目标客户/区域）、登记跟进（对象/活动/渠道/结果/证据/下一步/负责人/期限）、关联商机（现存ID＋qualified依据）。候选/话术通过Agent检索与CLI回写；页面提供检索任务而非假搜索按钮。失败保留输入，冲突提示刷新；空、加载、部分数据、无坐标、过期活动、校验与成功状态都可读。无生产鉴权则不制造权限页。

企业蓝色扁平主题复用已有变量；浅/深主题，桌面地图/详情双栏，390px单栏；表格独立滚动。控件有标签、焦点、实心/边框动作；真实指标不以装饰图填充。研究适配分与商机判断雷达保持不同含义。

## 分析口径与验证

漏斗按目标企业去重，以截至日已经发生且有证据的跟进统计；计划不算触达，未来跟进不算实际。活动关联是已记录来源而非因果归因。缺成本不视为零；不同币种不合计；签约金额只统计已登记的签署事实，线索/报价/合同/回款分开。评分分项0–5缺项保留未知与覆盖率，不伪造赢率。

验证：事务回滚/请求重放/并发冲突；来源和引用校验；日期/费用/坐标/评分与去重；同企业关联、跨计划/跨企业拒绝和商机动态回读；安装与原110项回归；独立现实任务前向验证。真实浏览器走创建/筛选/地图选中/跟进保存刷新/关联/分析，检查1366/1440/1920/390及亮暗截图、错误、键盘与console。公开研究只证明公开事实，模拟互动不代表实际推广成效。
