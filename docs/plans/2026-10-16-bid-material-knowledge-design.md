# 企业材料知识接入与章节引用

状态：用户已确认设计；本次按以下范围实现并验证。

## 目标与边界

附件、文字、目录及指定知识库统一进入项目知识索引，保留原件、结构、来源位置、版本和解析缺口。按企业资质、合同业绩、人员社保、知识产权、体系产品检测、财务信用、技术参考、历史模板分类。分类和字段提取不认证真实性，也不把候选材料自动采纳为投标证明。测试使用明确标识的模拟企业材料。

## 决策

- 原件、结构化内容、可重建 Markdown Wiki 分别保存。只合并成一份 Markdown 无法保留原件与复杂表格；完全依赖远端检索无法复现采用的版本。
- 延伸既有 knowledge.py，不新增向量数据库或企业资产平台。检索由本地词面搜索或宿主实际授权工具承担。
- 指定知识库采用配置、检索任务、结果快照的宿主工具交接；配置成功不等于授权成功，导入快照不伪装成已执行远端调用。
- 章节参考包与引用单独落盘，绑定正文、原文位置和文件哈希。新增材料只提示相关章节重核，不直接覆盖正文；原有全项目交付快照仍按现行门禁失效。
- Wiki 可重建，人工说明和选材决定保留在独立记录。内部知识链接不进入正式标书，原件附件按既有导出流程处理。

## 实施与验证

1. 多格式解析与结构保留：PDF/DOCX/PPTX、文字和图片；不支持、OCR不足、疑难表格明确列出。
2. 导入分类、字段与模拟标识、目录批次结果、分类 Wiki。
3. 指定知识库连接和宿主实际检索交接；范围不符、失败、空结果分别保存。
4. 章节参考包、引用绑定、增量影响和写作/评审校验。
5. 单元回归、两个既有招标项目的隔离验证、实际 Markdown/Word/PDF 回读及分发检查。

不以协议模拟证明真实第三方授权、资料真实性或正式投标评审通过。企业原件与项目快照不提交到公开 Skill 仓库。
