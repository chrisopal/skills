# 飞书章节协作验证（2026-10-16）

范围为投标套件 1.20.0：复用已安装飞书 CLI，增加在线文档适配器、工作台入口、在线评审依据及独立分发。未修改 Bid Agent 应用、模型供应商、数据库、部署或项目依赖。

## 首轮可用行为（1.20.0）

- 指定飞书 Docx/Wiki 文档，显式选择用户或应用身份，绑定当前项目。腾讯文档和 Office 可识别但拒绝未实现的读写。
- 按稳定章节 ID 新增正文、回读、拉取在线修订；保存本地候选后失败会显示云端未同步。平台管理成员、编辑权限和历史，不扩大原件或企业材料访问权。
- 远端人工改动、同名标题、已映射子章节、未知图片、部分成功、写入后读取失败和本地并发变化均停止自动覆盖或重放。刷新、重新绑定不清除未知写入。
- 原 CLI revision 参数没有提供本适配器可依赖的原子条件覆盖。已有章修改返回 `requires_native_merge`，在飞书原生编辑器中合并后拉回；不声称已完成任意章节的无冲突自动替换。
- 模拟评分和核心审核重新核对云端。整本要求全部已写章同步；限定评分仅使用已同步章，文档或正文变化使旧报告失效。

## 平台授权与未测项

首次测试时用户身份刷新授权过期，显式使用应用身份；应用图片上传及创建文档自动授予个人访问权因缺对应权限失败。用户随后亲自完成授权，重新核验用户身份具备文档创建/读写、图片上传/下载及成员授权范围，并用用户身份另建文档完成三图补验，未修改旧应用身份绑定。此结果不证明应用身份的权限问题也已解决；本轮未修改后台应用 scope、邀请人员或更改文档分享设置。

首轮时真人双账号接力与并发编辑仍未验收。当前无腾讯/Office 实现；该轮没有重跑 WorkBuddy 模型执行、Windows、多进程压力、整本生成及当前 Word/PDF 导出保真。工程测试和局部云端成功不能替代这些验收。
