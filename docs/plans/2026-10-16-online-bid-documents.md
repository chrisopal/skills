# 在线标书协作接入设计与实施

用户已确认以在线文档为协作正文主版本，先接入飞书，保留腾讯文档和 Office 扩展边界。范围为现有投标 Skills，不修改 Bid Agent 应用。

## 决策

- 正文、人类共同编辑、资源和评论由在线文档承载；本地 11/13 为可核验工作快照，原文与评分依据继续保留项目身份和实际哈希。
- 单独的文档连接器承载识别、绑定、按章读取/写入、配图和版本核对。优先复用已安装 CLI/Skill，无新增依赖；腾讯与 Office 明确为未实现适配器，不能显示已接入。
- 正文写入使用章节最小范围和远端版本。在线协作不消除 AI 旧稿覆盖风险；人类修改导致冲突时保留本地候选，先拉取/合并再写。
- 实测发现 CLI 旧 revision 仍可能成功写入，不能充当原子条件写锁。因此当前自动化只新增章或确认未变章；已有章修改必须在飞书原生编辑器合并后 pull。保留未来原子合并能力接口，但不启用未经验证的自动覆盖。
- 保存、读取和评论回查均留收据；部分成功、超时或回读不符不自动重放写入，不标已同步。重新读取并确认结果后才能恢复。
- 新评分和审核前检查云端与本地快照一致；评分后再查远端，以便识别模型阅读期间的变化。正式资格、材料、废标和导出门禁保持独立。
- 项目上下文和材料访问权限与正文访问权限分别验证。成员授权由平台控制，本轮不邀请真实成员、不公开分享、不复制凭据。

备选：只上传整本 Word 会损失按章更新和人工修改保护；自建实时协同增加账号、服务与同步维护成本。私有 Git 可选作备份，不作为用户协作入口。

## 实施与职责

1. 新增在线文档连接器和错误/冲突测试，使用 Feishu CLI 的真实 XML、资源与版本契约。
2. 在本地工作台写作设置增加绑定、打开、读取和保存状态；绑定模式保存后尝试安全推送目标章节，已有章要求原生合并，失败保留候选并显示未同步。
3. 在 AI 评分/核心审核链路加入云端当前性检查；沿用本地证据和快照，不从评论推断正式批准。
4. 更新 11/13/15/16/17 规程、独立分发及 README。说明自动配置边界、首次授权和各平台真实支持情况。
5. 隔离复制青草沙和东台样本，真实验证章节写入、图片、接力修改、评论审核、模拟评分与冲突保护；应用身份和角色模拟与真人多账号验收分别报告。

## 验收

单元与 loopback HTTP 回归、独立 ZIP 同源、CLI 实际收据、飞书正文与图片回读、云端更改导致旧评分失效、真实浏览器浅深色及窄宽视口。所有生成物和云端身份只留本机验证记录，仓库仅提交源、测试和说明。

本轮不把导出 API 存在、应用身份操作或模拟专家分数称为 Word/PDF 保真、真人协作或官方评标通过。若用户身份过期，先使用明确标注的应用身份创建隔离文档，保留用户授权待验边界。
