# Enterprise UI Design：逐流程 UX 审查增强

用户已确认：补充逐流程操作体验、易用性与异常恢复；验证后同步本机并合入 main。

## 范围与设计

- 保留 v1.3 的 Token、布局、品牌/风格轴、已有组件和三个审查结论；不改参考页面 UI 或宿主业务契约。
- 在现有流程规范/模板上补全用户任务、操作负担、异常恢复与跨角色交接。用独立流程范围账登记入口、目标、角色、主线/适用异常分支与预期结果；步骤关联现有 surface/state。
- 在现有 audit_ui.py 增加 journeys 检查，报告增加独立 ux 结论与逐步骤观察。旧页面覆盖检查保持兼容；声明 journeys 的范围同时执行流程检查。拒绝漏项、重复/未知步骤、缺证据、未验证、未解决阻断及伪造用户测量。
- 指标记录观察方法、参与者类型与样本边界；脚本只能验证账结构，模型走查不等于真人测试、客户验收或真实业务保存。
- 学习 UI UX Pro Max 的 UX 规则正反例、Product Design Audit 的逐步证据、Impeccable 的认知负担与错误恢复；不复制源码、不新增依赖、不自动安装外部工具。

## 执行与验证

1. 冻结旧版，进行真实任务前向基线评估；先写流程检查器的拒绝/兼容性回归并观察失败。
2. 完成规则、引用、模板与最小检查器；覆盖主线、恢复、交接、N/A、异常输入及独立 UX 结论。
3. 使用同一业务材料进行独立前向试用；复核问题和未知边界。执行全部回归、CLI 正反例、Skill 校验、语法、链接、生成一致性和字节回读。
4. 备份已安装副本并比对源基线后同步；只提交本次源码和文档，更新 STATUS，fast-forward main、非强制推送并核对远端 SHA。保护已有 WIP；生成证据留本机。

## 取舍与简化

复用一个入口、流程规范、流程评审模板及审计命令，不建设新模式/框架或另一套视觉系统。正常业务、恢复与交接依实际合同适用；不强制最少点击数、向导、画像或虚构量化阈值。仅新增确有需要的机器可读范围模板与独立测试。
