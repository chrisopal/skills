# 企业业务场景与组件选型

按用户任务选择组件组合，再映射到宿主已有组件。这里覆盖通用企业页面，订单阶段条只是一个专项样例。没有对所有场景都最好的组件：首选模式不合适时，在 Blueprint 写明任务、数据或容器方面的具体理由。

只读取当前任务需要的指南，不要将所有模式塞进同一页面。

| 项目排程、预约、负载、分析 | 甘特图、日历、资源日历、看板、进度条、KPI、常用统计图 | [计划与数据可视化](planning-and-visualization.md) |
| 记录检索、比较、批量处理和录入 | 标准表、选择表、展开表、树形表、分组表、编辑表/网格、主从、比较/交叉表 | [表格与数据工作区](tables-and-data-workspaces.md) |

## 容易混淆的选择

| 要表达的区别 | 选择规则 |
|---|---|
| 状态 / 顺序进度 / 历史 / 日期排程 | Badge表达一个状态；Steps表达阶段顺序；Timeline表达已发生事件；Gantt表达时间区间和依赖 |
| Tabs / 步骤条 / 视图切换 / 锚点 | 同级内容用Tabs；顺序任务用步骤；同数据不同展示用分段切换；连续长文定位用锚点 |
| 抽屉 / 弹窗 / 独立页 | 临时详情或轻编辑用抽屉；短聚焦决策用弹窗；复杂持续工作用独立页；必须同时对照时用非模态侧面板/主从 |
| 树形表 / 分组表 / 展开行 | 真实父子层级用树；按属性分类用分组；单行补充信息用展开，不混造层级 |
| 表格 / 看板 / 卡片 | 多字段精确比较用表；状态队列用看板；图像或摘要识别优先时才用卡片 |
| 进度百分比 / 阶段序号 | 仅真实且定义清楚的完成量可换算百分比；第三阶段不代表完成60% |
| Toast / 就地错误 / Dialog | 短暂结果可用Toast；需要处理的问题就地持续展示；必须做明确决策才用Dialog |

## Blueprint 与复用契约

每个主要任务写一张决策卡：**角色和任务 → 业务对象/数据范围 → 采用的组件组合 → 操作/保存模型 → 关键状态 → 窄屏与键盘路径 → 可观察验收**。用[组件评审模板](component-review-template.md)记录，不只列组件名称。

- 优先复用宿主组件清单、业务词汇和语义Token。参考不同设计系统的原则不意味着混装多套库。
- 页面布局为任务服务：阅读限宽，数据比较合理利用宽度，专业画布明确滚动边界。组件不会自动修复信息层级与留白，结合[空间规范](spatial-system.md)。
- 数据、权限、完成规则和保存范围来自业务契约。组件只表达真实能力，不为填满UI虚构百分比、指标、操作、通知或成功状态。
- 同时检查默认、加载、空、错误、无权限、部分完成等适用状态，及长内容、浅深、桌面/390px、键盘与放大。仅存在某组件不能作为通过标准。
- 检验分为选型、业务事实与行为、任务理解、视觉构图及交互。自动化验证范围/回读/焦点/溢出；模型截图评审记录可定位问题；真人任务观察单独标注。三者不能互相冒充。
- 缺少真实运行证据时交付设计建议与未测项，不声明宿主已实现。可运行的[订单阶段样板](../assets/reference-order-flow/index.html)仅验证一种模拟组合，其余专项是设计与验收规则，未声称都有可运行组件。

## 官方设计依据与适配边界

查阅日期：2026-10-18。以下概括官方原则/组件用途；本指南的场景组合、默认布局、验收矩阵属于面向本 Skill 的设计判断，不声称是所有设计系统共同要求。

| 来源 | 采用的依据 | 本 Skill 中的落点 |
|---|---|---|
| [NN/g 十项可用性启发式](https://www.nngroup.com/articles/ten-usability-heuristics/) | 系统状态可见、使用业务语言、减少记忆负担、让重要内容保持突出 | 当前阶段与下一步可见，技术标识按需查看；分别验证状态、理解与视觉 |
| [Ant Design 亲密性](https://ant.design/docs/spec/proximity/) | 距离和分组表达信息关系 | 状态与动作靠近，组内/组间留白有层级；保留已有 Token |
| [Ant Design Steps](https://ant.design/components/steps/) | 有顺序的复杂任务可分步；提供横纵方向、节点状态及可选交互 | 订单采用连线阶段概览；只有真实导航需求才启用节点点击 |
| [Carbon Progress indicator](https://www.carbondesignsystem.com/building-blocks/core/components/progress-indicator/guidelines) | 区分完成/当前/未来步骤与活动/非活动路径；横纵方向按使用环境选择；默认可不交互 | 节点和连线同时验收。Carbon强调线性任务，不把动态分支强塞入单线指标 |
| [Carbon Tabs](https://www.carbondesignsystem.com/building-blocks/core/components/tabs/guidelines) | 同级内容组织与线性进度表达是不同任务 | 不用 Tabs 代替进度；需要同时比较的内容不用反复切Tab |
| [Ant Design Timeline](https://ant.design/components/timeline/) | 按时间排列事项并建立视觉联系 | 审批/交接事实采用事件时间线；阶段预测与历史事实分开 |
| [SAP Fiori Wizard Floorplan](https://www.sap.com/design-system/fiori-design-web/v1-142/ui-elements/wizard) | 引导复杂创建/编辑；简单或用户熟悉的日常操作不宜增加不必要步骤 | 复杂受理用向导；熟练高频短表单保留直接编辑。该链接为版本化设计指引，不是当前宿主API |
| [Element Plus Steps](https://element-plus.org/en-US/component/steps.html) | Vue组件支持阶段状态、描述、横纵方向；simple模式会忽略部分布局能力 | 宿主已采用Element Plus时可映射；需要说明文字/纵向时先核对组件模式，不盲目复制参数 |

各专项指南另附甘特、表格、抽屉、表单、图表和键盘语义的对应官方资料。

公开Skills的比较、已吸收方法与未采用规则见[外部Skills参考](external-skill-references.md)。它们补充选型与检验方法，不覆盖宿主产品规则或上述官方组件语义。

### 按宿主实现，不混装组件库

- Ant Design 已有项目：优先核对当前安装版本的 Steps / Timeline / Table / Form 等；在线最新 API 不能直接当作旧版本可用能力。
- Element Plus 已有项目：使用现有 Steps / Timeline / Table / Form 及其主题接口；不能因为设计参考来自Ant就引入第二套框架。
- Carbon / SAP Fiori 项目：沿用对应设计系统的进度、页面模式与可访问性实现；跨系统借鉴需映射语义。
- 自研组件项目（包括本次 LIMS）：先查组件清单，复用按钮、反馈、详情、列表等稳定积木；缺失阶段组件时再提取小而专用的 ProgressSteps。阶段业务事实由所属领域提供，公共组件只渲染明确状态。

参考库是设计和实现依据，不是审美自动合格证。是否清晰仍要用真实任务、长内容、浅深主题与窄容器走查。
