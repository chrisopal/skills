用于表格、甘特图、Tabs、抽屉、表单、反馈、图表等。流程还需[流程评审模板](task-flow-review-template.md)。这不是勾完即可合格的评分表。

- 版本/提交/构建、环境、数据来源与采集时间：
- 现有组件库/版本/组件清单、相关业务/API/权限契约：
- 本次实现/修改范围；已有能力与未实现建议分别列出：
- 参考依据：产品Blueprint/已批准设计/官方设计原则；无参考图不能给像素相似度：

从相应指南挑选适用ID：PLAN/VIZ、TABLE、NAV/SURFACE、FORM/FEEDBACK，以及阶段指南。未实现的功能不测作已通过；不适用写业务理由。

至少覆盖主任务、与该组件相关的一种异常、真实长内容；按范围验证桌面/390px、浅深、键盘、放大和低高度。明确列出哪些组合实际打开、哪些只有静态检查。

## 构图与可理解性走查

对填充真实或明确模拟数据的截图检查：

1. 首先看到什么？是否对应当前任务与主对象？
2. 分组、对齐、留白是否表达真实关系？是否层层卡片或同权重按钮掩盖重点？
3. 关键身份、范围、时间、单位、状态、动作能否直接找到？
4. 长文本、更多列、更多Tab、打开抽屉后是否仍可读可操作？
5. 交互后是否知道结果、失败原因和返回路径？

逐项记录具体答案、截图位置与问题，不只写“好看/一致”。模型启发式走查与真人任务观察分开标注；自动无溢出不等于可理解或有审美层级。

## 问题与结论

| ID | 严重度 | 实际证据与任务影响 | 修复条件 | 复验结果/未测范围 |
|---|---|---|---|---|
|  |  |  |  |  |

- 严重度遵循[Audit规则](audit-and-refine.md)：P0为流程不可用、关键操作不可达、焦点困住、越权/数据丢失或重大错误操作；P1为有实质影响的状态/范围误导、响应式、共享组件或设计规范缺陷；P2为非阻断的层级、密度与一致性改进。按实际影响判断，不按控件名称机械分级。
- 分别结论：**选型合理性 / 业务事实与行为 / 视觉构图 / 键盘与响应式**。
- 总结论：Pass（适用项有证据且无未解决阻断）、Conditional（关键项已验证，仅非阻断遗留或明确在范围外的缺口）、Not ready（约定范围有阻断或关键验证未完成）。Not ready须区分“已证实缺陷”和“缺少证据”；逐项保留Unverified，不把未测试当作发现缺陷。样板通过不能升级为宿主实现通过。
- 交付说明：已设计、已实现、浏览器已验证、业务E2E已验证、已发布分别报告。保留未测项，不用综合分数冲掉P0/P1。
