# 统一详情布局：先决定信息，后决定栏数

适用于独立详情、列表侧栏、抽屉、弹窗、审批面板、Tab 内只读分组和动态证据。与 forms-and-feedback 的 READ-01～07、spatial-system 和 notice-economy 配合使用；不替代业务契约。

## DETAIL-D01：全量入口清单先于迁移

从路由、菜单、组件调用、条件渲染和动态表单入口交叉盘点，不只匹配 Detail 文件名。每项记录业务对象、入口、源码、承载方式、内容类型、布局变体、原问题、改动、实现状态、运行状态和证据。已有共享组件消费者也必须进入清单；继承样式不等于逐页面浏览器通过。代表性页面验证后继续完成全量清单。

## DETAIL-D02：默认阅读顺序

1. 对象身份：列表返回独立于对象区。集中显示可识别的业务名称、必要的归属或真实状态；业务编号/版本作为清楚标注的辅助身份。桌面将同一对象的操作放在标题旁，窄容器放到标题下，允许换行并保留操作顺序。只读对象可以没有主操作。
2. 必要上下文：操作限制、历史冻结、数据性质，只在影响判断时显示一次，靠近相关内容/操作。
3. 关键摘要：当前任务最需判断的结果、条件、阶段或核心属性；无摘要价值则省略，不强加 KPI 卡片。
4. 主体字段：按业务含义分组，对齐标签和值；长叙述、备注与技术校验信息分开。
5. 辅助信息：人员、来源、时间、归属、设备；宽容器可侧栏，窄容器顺序排列。
6. 关联与历史：按任务选择紧凑表格、列表或由真实事件生成的时间线。各版本的状态、时间、文件及操作随对应版本展示。
7. 追溯：可选来源与校验信息放在业务正文和版本历史之后。已有同级页签可把追溯放在最后。默认收起低频信息，保留有清楚名称、可用键盘开合的入口。影响当前操作的风险仍靠近对应操作。

不同状态概念分别绑定真实字段，例如设备的使用状态与校准状态、任务的检测与复核状态。若业务必须同时展示编号与名称，采用清楚标注的「名称 · 编号」关系；判定、版本和归属留在各自语义位置。

## DETAIL-D03：内容驱动的布局变体

| 变体 | 内容与组合 | 禁止 |
|---|---|---|
| A 普通对象 | 对象与状态 → 对象操作 → 核心事实 → 按需追加关联，如设备校准或样品保管 | 每字段一张卡；无内容空侧栏 |
| B 结果/记录 | 结果值与单位突出；判定及判定条件邻近；依据/原始数据在主体；来源/人员/设备为辅助；紧凑版本表 | 前端重算判定；用本版填历史；只放绿标不给条件 |
| C 流程/任务 | 当前阶段、办理内容、动作及限制在前；保留专业工作区 | 将可办理界面改为只读；步骤条替代实际办理内容 |
| D 文档/预览 | 模板名称与当前操作 → 业务信息 → 映射、正文或预览 → 版本历史 → 可选追溯。下载、导出、以此版本编辑等动作随目标版本 | 为侧栏压窄正文；冻结文件引用当前可变草稿；把编辑入口标作只读查看 |
| E 窄幅容器 | 紧凑单栏或少列；沿用关闭/返回/确认位置 | 仅按视口判断，宽屏小弹窗仍双栏挤压 |

变体是组合指引，不是万能组件中的业务类型开关。通用组件负责布局；数据、业务计算、权限及流转由业务模块负责。

## DETAIL-D04：默认组件规则

先检查现有组件清单；优先修复详情容器、描述列表、分组和主题默认值，再迁移私有字段布局。字段用 dl/dt/dd 或已有 Descriptions；标签位置同组一致，标签宽度有上限，值不被宽网格推远。短组有阅读宽度；备注独占整行；长编号可换行，完整校验值在准确命名的可访问展开区。SHA-256 不能叫“内容摘要”。

身份、提示、摘要、主体、辅助和历史各由一个容器管理留白。短字段在窄幅下优先保留清晰的标签和值两列，长值可换行，长标签或更窄容器按实际可读性改为上下排。行分隔线轻于面板边框，长说明单独占行。专业表单、表格和预览沿用各自的阅读或编辑方式。

外框与标题底色共用同一圆角轮廓。独立的标题底色贴合外框时，核对内角与外角扣除边框后的关系。返回栏与面板留出组间距，避免两条边线重合，同时保留焦点轮廓和浮层空间。

图标按识别需要用于少数标题、返回或动作。事实行依靠标签、对齐和文字层级即可。操作组使用宿主的按钮边界和危险语义。参考图的配色、插画、设备状态栏、收藏和更多菜单须有已确认的品牌或业务契约才采用。

## DETAIL-D05：权限与来源不变量

自审受限等必要限制应醒目，明确“仅查看”，禁止同时提供无权动作。限制原因只能由真实权限/业务结果确定。拥有办理权限的角色仍可办理。原始读数与格式化结果不同时展示为两个同名结果；不同精度有业务价值则清晰命名，完全相同可按需读取，不能丢失原值。

版本表至少按实际契约显示版本、提交/审核标记、结果/状态、来源、人员、时间和真实详情入口。没有历史提交事实时不能把非当前提交版本写成“未提交”。展开绑定所选版本自己的冻结数据、来源、人员和时间。

追溯首选可读名称、业务编号、适用范围及准确版本。缺名时显示缺失状态，底层审计标识由接口和审计证据保留。技术校验值只放在所属版本的可选区域。当前名称可标为当前资料，冻结历史沿用当时的证据。

来源链接须对当前角色可用，并打开所示对象或版本。实际点击后检查目标版本及只读状态。没有精确的历史入口时保留冻结摘要，当前办理入口明确标为当前。时间线来自真实事件及其人员、时间，不从单一当前状态倒推。

## DETAIL-D06：迁移完成条件

每种变体实际浏览器验证后推广全部适用入口，并逐项记录原来→怎么改→现在、截图/测量与未测分支。覆盖明暗/跟随系统、桌面/390px/窄抽屉及弹窗、长字段、缺省/空组、加载/失败/无查看权/只读/可操作、单多版本与键盘。表格/文档仅自身可滚动；整页不得异常溢出。检查共享样式未破坏列表、录入和设计器。代码通过、浏览器模拟契约通过、真实后端业务链通过、部署分别报告。

核对列表返回能否恢复筛选、分页、选中及焦点。用实际边界、字段轨道和动作换行定位共性差异，逐个记录调用方是否采用了正确变体。代表截图保留主题、视口和来源，未经运行的分支保留待验证状态。

## 字段容器与留白的实现契约

字段组件的百分比宽度必须包含调用方增加的内边距/边框（如使用 border-box）；不能只用长词换行掩盖盒模型溢出。正文、标题与操作的内边距各有一个责任方，嵌套反馈组件的透传插槽也要核对实际四边留白。真实页面同时检查长模型标识、URL、校验码和普通业务字段，不凭短值夹具通过。
