# 从真实缺陷前置设计契约

适用：已有企业应用的缺陷驱动设计，尤其是配置型表单、工作队列、目录列表和持续详情任务。这里补充跨页面、跨版本的业务语义检查；既有组件、空间、文案和提示规则继续有效，不另建视觉体系。

来源：LIMS 飞书内容问题表 2026-10-21 快照 rev698，指定视图 72 行、has_more=false；含 71 条非空问题及 1 条空行。项目内原件为 `artifacts/governance-20261021/issues.ndjson`，分析为 `docs/engineering/2026-10-21-ui-defect-lessons.md`。下列 record_id 是可追溯案例，不是所有项目的领域规则，也不代表问题已验收。

## Blueprint 增量

只为范围内相关对象补充：显示名/稳定标识、事实来源与版本、配置生效时点、对象粒度、动作资格、查询/导出范围、详情入口与返回上下文、错误恢复目标。按实际契约填写，不用当前 UI 表现反推正确需求。

## 应用边界

- LIMS 的 `reczz28Px8pN8f4S` 明确要求持续详情迁至独立页面，后续 `reczz28PyB8QcGKM` 仍报告报告列表右侧展示；这是该项目的明确偏好与待复测路径，不是所有企业产品禁用抽屉。其他项目仍按 [导航与任务载体](navigation-and-task-surfaces.md) 选择。
- 复杂表单案例只支持已声明的重复明细、多级表头等能力；人工接受当前优化不等于支持任意嵌套/合并。涉及新结构应先确定数据契约和真实样例。
- 新反馈 `reczz28PxwSVJlux` 涉及期间选择和图表表达：先核实指标时间口径、支持的范围及可用数据，再选择图表；不能为了丰富界面加假图。`reczz28Py81qLd8G` 要求列表显示负责人，先核实事实来源和列表投影，不能只加空列。
- 此处 L1 指可机械执行的静态/文件/台账结构检查。L1 能检查规则引用、证据路径与版本字段，不能证明姓名正确、表单按修订生效、对象范围合理、按钮真正可用或视觉清晰。设计审核、真实浏览器业务回读与人工接受分别给结论。

复用既有 [任务流审阅](task-flow-and-hierarchy.md)、[表单与反馈](forms-and-feedback.md)、[提示准入](notice-economy.md) 的台账；将适用 EUI-F ID 加入契约来源，不另建一套重复门禁。
