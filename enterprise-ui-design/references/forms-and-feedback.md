# 表单、选择、上传与反馈

围绕输入目的、字段关系与失败恢复设计，不能让用户先学习后台数据结构。通用控件负责交互，必填、计算、权限与状态迁移仍由业务契约定义。

## 输入场景选型

| 场景 | 推荐组合 | 使用边界 |
|---|---|---|
| 少量相关字段的日常修改 | 单页分组表单＋就地校验 | 不为“流程感”强制向导；不要一个字段一张卡片 |
| 复杂、低频、有前后依赖的申请 | Wizard＋阶段保存/校验＋最终摘要 | 返回保留数据；步骤不是审批进度，未知业务分支不能靠前端猜 |
| 多个对象重复输入同一结构 | 重复分组或编辑明细表＋增删行 | 每组身份、范围、错误清楚；复杂嵌套转逐对象详情 |
| 选少量互斥选项且需看到差异 | Radio；适合短标签时可用分段选择 | 多选用Checkbox；长内容勿挤进紧凑分段按钮 |
| 选较多已知对象 | Select/可搜索Combobox＋身份摘要 | 远程查询显示加载/无结果/失败；同名对象有可辨次要信息 |
| 从层级分类中选择 | Tree select/Cascader | 层级真实、路径可查；不能用深树掩盖没有搜索的庞大目录 |
| 立即生效的二元设置 | Switch＋明确状态 | 若要统一提交，按表单语义说明；高影响变更需要真实权限/后果反馈 |
| 金额、测量值、数量 | 数值输入＋单位/精度/范围 | 允许的负值、小数、空值由领域规定；不能格式化时静默截断重要精度 |
| 选择日期、时间或区间 | 日期/时间选择器＋可输入格式 | 时区、含结束日、跨日、禁用日期与业务规则一致 |
| 上传附件/图片/批量导入 | 上传列表＋逐项状态＋校验结果 | 选中文件、上传完成、服务端处理完成不同；失败支持逐项重试/移除 |
| 阅读审核材料并决策 | 文档预览＋范围/版本＋审核动作 | 未加载完/缺必需证据不能伪装已审核；大文档用工作区而非窄弹窗 |

## 表单构图与状态

- 标签持续可见，不用placeholder代替标签。标签、控件、单位、提示与错误归属于同一个字段；组间距离表达业务关系。
- 默认值有依据；可选/必填约定一致。只读值与禁用控件不同，用户仍应能阅读必要值与原因；不要用低对比度隐藏关键信息。
- 联动显隐、清空、保留策略写入Blueprint。上游选择变化导致下游无效时明确提示，不静默提交隐藏的旧值。
- 校验时机兼顾效率：在用户完成相关输入后提示，提交时给可定位的错误摘要；不要初次打开就把未触碰字段标成错误。
- 页面顶部/底部主动作明确提交哪个范围；按钮loading阻止意外重复请求但不锁死恢复。保存后显示真实结果并回读，自动保存也要有状态与失败恢复。
- 草稿、已保存、已提交、已审核是不同状态。跨Tab/向导返回/关闭保护跟随同一保存模型；服务端错误与权限变化不能只靠前端禁用处理。

## 只读详情与空状态构图

以委托/订单详情的结构化阅读方式为参照，按当前对象、任务与资料关系分组，不复制示例业务字段。Blueprint 列出每组事实、标签/值、阅读顺序和展示责任：主体身份、当前任务、业务明细、资源/依据、结果、历史按实际业务取舍。不能把所有事实拼成连续段落、分隔符串或一排标签。

- 只读表单表达信息关系，不是禁用的编辑表单。复用宿主 Descriptions 或语义等价的 `dl`/`dt`/`dd`；标签持续可见，未知、未填写、零值与不适用按契约区分。不要用 disabled input 降低可读性。
- 短字段按可用宽度排响应式网格，同组标签和值有稳定对齐线；390px 自然减列，长名称/单位/日期不遮挡。结论、备注和说明等叙述独占整行，与短字段分开；校准 `dd` 默认缩进，不压缩文字硬塞列数。
- 表格用于跨记录比较，时间线用于历史，编辑器用于专业操作。只在阅读型事实中采用字段组，不机械把这些组件、动态表单或报告正文改成 Descriptions；必要详情可在行展开/独立区块呈现。
- 区块先有标题/适用范围，再是内容或局部状态；必要错误与恢复位于受影响区域。标题、状态、内容和动作保持层级；空/错误不能成为贴着外框的普通一行文字，也不再叠加解释同一事实的横幅。
- 空态在**所属内容区**水平居中，纵向在该区可用空间中平衡；使用宿主 Empty/Result 的适当 padding/最小高度，紧凑子区块按内容留白，不强制全视口居中或巨大固定高度。标题和工具栏保留原对齐；不要把整个面板一起居中。加载、有数据与失败切换时沿用同一边界，恢复按钮可见、焦点不裁切。
- 初次无记录、筛选无匹配、无权限、对象不存在、读取失败和加载中分别由真实契约判定。无记录只给有权限且有接口的创建入口；筛选无匹配才提供清除条件；不存在允许返回，失败提供实际重试/恢复。工作队列为零仅表示没有当前待办，不能推出报告或历史对象不存在。

## 详情阅读的默认 recipe

适用普通业务详情、版本资料和审核摘录。结构化 form 指可读的字段关系，不要求渲染成编辑控件。先在 Blueprint 标明每块的 `subject / readingPriority / fields / widthPolicy / stateOwner / actionScope / spacingOwner`，映射已有 PageHeader、Descriptions/DetailList、Section 与 ActionGroup；这些是责任名，不是新组件 API。

1. **页头先认对象，再认状态与当前动作。** 标题与当前对象状态放在同一个可换行的身份组，用行内间距保持邻近；页级操作可作为另一个整体靠右，但状态不能被 `space-between` 推到另一端。版本选择器负责切版本：选项可显示各版本状态；选定后同一范围的当前状态由一个位置主呈现。正文另有子对象状态时标明对象，不能把不同范围误删为重复。只读/完成页无需虚构主按钮。
2. **字段组有阅读宽度，列数由内容决定。** 先用宿主 Descriptions/DetailList；按空间规范将普通资料组限制到合适的 form/reading 宽度，额外空间留在组外，不能把两个短字段拉到面板两端。每项保留相邻标签与值；同组标签列按实际标签确定并对齐，值列允许收缩和换行。短字段按可用宽度排布；长名称、结论、备注独占整行。390px 或侧栏挤窄后可减列/上下排标签和值，不强制所有详情两列。
3. **业务正文先于追溯细节。** 名称、范围、结论/内容优先；摘要应是真正的人类可读摘要。hash 按实际用途称“文件校验码”或“内容校验码”，算法已知才写算法名，不能标成“内容摘要”。默认放入键盘可达的“技术详情/校验信息”展开区，保留完整读取与必要复制；校验本身就是当前任务时可直接呈现。编号、版本、页码等业务定位仍按需要可见，不能一起藏掉。
4. **摘录按身份 → 位置 → 正文 → 动作阅读。** 例如“尺寸检验要求”为内容标题，`片段 C1 · 第 3 页` 为次级定位，正文单独成段，片段操作归于该片段。没有真实标题时用准确的“片段 C1”，不编造摘要。整体批准/提交归对象级决策区，不能紧贴最后一张摘录卡造成“只批准此片段”的错觉。长正文、最后一项、空态及错误出现时都保留内容到动作的分区距离。

### 组件默认责任与实施顺序

| 已有组件/容器 | 默认负责 | 能力不足时 |
|---|---|---|
| PageHeader 的身份组 | 标题/状态邻近、换行；操作整体对齐 | 扩展已有身份/状态插槽或布局变体，页面传业务状态及权限；不每页用远端绝对定位修补 |
| Descriptions / DetailList | 标签/值关联、标签列、值换行、长字段跨行和组宽策略 | 在现有组件增加明确的阅读宽度/字段跨度能力并验证已有消费者；不复制一套页面 dl CSS |
| Section / Stack | 内容与决策区之间的 `layout-group-gap` 或 `layout-section-gap`，以及容器 inset | 由直接父布局承担一个 gap；若动作在组件 footer 中，则由组件 footer 的 padding 承担，不两处叠加 |
| ActionGroup | 按钮内部 `layout-action-gap` 与换行 | 组内 gap 不能代替正文→动作组距离；不得依赖调用页临时 margin 才不贴边 |
| 技术详情与摘录组件 | 展开/复制/焦点、身份与定位层级、正文完整访问 | 优先补现有组件的明确能力；共享层不存在时建立最小语义封装，避免万能布局引擎 |

Blueprint 指定内容→动作距离的唯一 owner 与 token，并检查最后一个正文边缘到第一个动作可见边缘的实际距离。页面只组合业务组和选择已有变体；共享组件默认应能在无页面补丁时保持关联与留白。只有业务特有关系才留在页面，并记录理由及作用域。详细阅读区不因容器更宽就拉散；表格、时间线、画布保留其原任务布局。

### 正反例：判定依据是关系与任务

| 反例（即使无溢出仍失败） | 正例（需浏览器验证） |
|---|---|
| 标题在左、唯一“已发布”在最右；选择器、页头、正文重复同一版本状态 | 标题旁一个当前版本状态；选择器区分版本，选项状态仅承担选择依据；切版本时标题/状态/正文同步 |
| `dl` 两列铺满宽屏，短标签与值拉远，备注挤在半列 | 有界字段组、稳定标签/值线，短字段在组内紧凑排布，备注跨行；大屏空白留组外，窄屏顺序不变 |
| 64 位 hash 叫“内容摘要”，比正文更显眼 | 可读正文优先，“内容校验码”在技术详情完整可查；展开、复制与焦点路径真实可用 |
| `C1`、页码、标题、正文、批准都同一字重，批准贴最后摘录卡 | 标题明确、定位次级、正文完整；片段动作留在片段，整体批准位于有分区间距的决策区 |

不把这些示例的字数、列数、按钮数量或顺序当成所有页面的固定模板。静态标签、CSS gap 和 checker 通过只证明局部条件，不能代替实际截图及阅读/操作路径。

## 反馈组件选型

| 用户需要知道什么 | 首选 | 避免 |
|---|---|---|
| 哪个字段有问题 | 字段旁错误＋必要摘要/定位 | 仅Toast提示“校验失败”，或只用红框 |
| 当前区块不可用/前提未满足 | 区块内Message bar/Alert＋真实恢复操作 | 每个区块重复全局警告，或把持续问题藏进Tooltip |
| 短暂且不需处理的结果 | Toast/轻量状态反馈 | 唯一的重要失败、必须阅读的结果、长审核原因不能瞬间消失 |
| 请求尚未返回 | 局部Skeleton/加载指示＋合理取消/恢复 | 虚构数字、不断闪烁重排；小动作导致整页遮罩 |
| 操作量可计量 | 进度条＋真实完成/总量 | 未知总量用不定进度；上传100%不代表服务端处理完成 |
| 没有记录、没有匹配、无权限或加载失败 | 对应空/结果状态＋可用动作 | 四种状态统一写“暂无数据”；无权限给创建按钮 |
| 需要用户决策 | 就地决策区或确认Dialog | 为每次普通操作弹窗；失败重试默认重复不可幂等动作 |

反馈与范围相邻，重要状态有文字并可被辅助技术感知；使用适当的live region，避免每次刷新都打断用户。显示业务可理解原因和真实处理路径，不暴露堆栈/SQL/内部技术术语。

## 可观察验收

| ID | 检查动作 | 通过条件 |
|---|---|---|
| FORM-01 | 不读说明填写一份真实任务数据 | 标签/单位/必填/顺序明确，业务术语一致，无多余输入 |
| FORM-02 | 输入边界值、空值、长文本和错误格式 | 按领域规则处理，不截断有效精度，错误靠近字段且可定位 |
| FORM-03 | 改上游选项、添加重复行、前后切步骤 | 联动与范围正确，数据不串组、不暗中丢失/提交旧隐藏值 |
| FORM-04 | 保存失败、重复点击、权限变化、离开重进 | 无假成功/意外重复提交，草稿与恢复符合真实契约 |
| FORM-05 | 上传一项成功一项失败、取消/重试/提交 | 逐项状态真实，处理未完成不当作就绪，失败文件可定位 |
| READ-01 | 查看每个详情分组，按标签定位主体、任务、资源与结果 | 字段归属有业务依据，语义标签/值可辨，不靠连续文字猜关系；必要未知和审计信息仍可访问 |
| READ-02 | 桌面/390px、长字段与浅深主题对照 | 短字段网格重排，标签/值对齐，叙述独占整行，无禁用输入伪装或值截断 |
| READ-03 | 逐页检查表格、历史和专业编辑区域 | 按比较/历史/操作语义保留组件，未为统一外观机械改成只读字段；相关详情入口可达 |
| READ-04 | 切换对象/版本并检查页头、选择器、正文状态 | 标题/状态同组邻近，同一范围有明确状态 owner；版本、状态及正文一致，只读页无虚构主动作 |
| READ-05 | 大屏、侧栏展开、390px 查看短/长字段 | 字段组按任务限宽，标签/值邻近且稳定对齐，短值不两端拉散、长叙述整行，完整内容可访问 |
| READ-06 | 查找业务摘要及技术校验信息，键盘展开/读取/复制 | 命名区分叙述与校验码，业务重点在主路径，必要追溯内容仍完整可达，真实校验任务可例外直显 |
| READ-07 | 阅读多条/单条/长摘录后寻找片段与整体决策 | 标题、定位、正文、动作层级和范围清楚，内容→动作唯一空间 owner；末项/空/错误状态不粘连 |
| EMPTY-01 | 分别触发无记录、筛选空、无权限、不存在、失败与加载 | 文案和动作匹配真实状态，零待办不暗示报告/历史不存在，无重复说明或假恢复 |
| EMPTY-02 | 量所属内容区与空态边界，桌面/390px 查看浅深截图 | 空态在内容区居中且有上下/左右 inset，标题/工具栏/错误/恢复层级清晰，无贴边或全屏撑高 |
| EMPTY-03 | 加载→有数据/空/失败、重试成功及角色切换 | 边界和阅读起点稳定，过期提示清除，必要风险/权限/恢复保留且键盘可达 |
| FEEDBACK-01 | 空结果、初次无数据、失败、无权限分别触发 | 文案/图形/操作匹配实际状态，恢复入口确实有效 |
| FEEDBACK-02 | 仅键盘、浅深、390px和放大操作 | 标签/错误/焦点可见，选择和上传可用，消息不遮挡主要操作 |

用[组件评审模板](component-review-template.md)登记功能、构图和证据范围；不能以“所有控件已渲染”代表表单可用。

## 设计依据

查阅：2026-10-18。

- [Ant Design Form](https://ant.design/components/form/)：表单布局、校验、联动与动态字段的能力参考；规则映射到宿主版本。
- [SAP Fiori Wizard](https://www.sap.com/design-system/fiori-design-web/v1-142/ui-elements/wizard)：复杂输入的引导式流程及简单/高频任务的适用边界。
- [Fluent Message bar](https://fluent2.microsoft.design/components/web/react/core/messagebar/usage)：消息按受影响区域放置，与字段错误、空状态等反馈分工。

上述组合与验收属于本 Skill 的业务适配，不要求跨库拼装控件。
