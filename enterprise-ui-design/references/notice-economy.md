# 提示信息的必要性、去重与生命周期

适用于新设计、前端开发和最终审核；范围跟随用户请求，包括相关子页面、Tab、弹窗、抽屉、流程和动态消息。默认不加解释性提示。只读审核不授权修复；若用户要求先审核、确认后修复，先交付清单和约束，到确认处停止代码修改。

## 设计：每条提示证明当前用途

Blueprint 为拟常驻说明记录：用户任务/对象/角色、事实来源、影响的决策或操作、显示条件、解除条件、负责展示的组件、同义组、反馈通道。删掉不影响当前决策、准确填写、风险判断或恢复的说明。不用功能介绍、点击教学或实现解释填空；先让标签、状态、单位和操作本身清楚。

- 必需保留：当前校验/错误和恢复、缺少前提、真实不确定性、未保存输入、不可逆后果、当前权限隔离、正式/草稿与登记/实际执行的边界。
- 通常删除：标题/按钮的同义解释、没有当前待办的权限声明、正常路径的系统自我介绍和“暂无额外内容”等无增量区块。
- 需要但低频的定义、操作方法和长依据按需查看；不得把所有说明移入 Tooltip 或给每个字段加信息图标。关键风险、阻塞和恢复保持就地可见。
- 保留业务数据、客户正文、历史证据；管理员实际需用的技术配置保持准确。不要按禁词或字符串数量判断冗余。

## 开发：一个事实有明确的展示责任方

同一上下文以“对象 + 事实/错误原因 + 版本或作业 + 当前状态”识别同义重复。并看状态徽章、步骤条、摘要、Banner、字段帮助、页脚与弹窗，不能只逐组件审核。

| 情况 | 处理 |
| --- | --- |
| 同屏多处完整解释同一状态/限制 | 选一个完整解释位置；其他必要定位只留短状态或入口 |
| 页面与当前弹窗收到同次操作错误 | 当前交互面负责展示；背景不重复播报，关闭后按未解决问题决定保留 |
| 多个字段错误 | 就地错误可保留；摘要给数量/定位，不复制全部错误段落 |
| 多个对象共受同一限制 | 在共同范围说明一次，行内保留各自状态；独立风险不强制合并 |
| 独立详情或不同决策需重申关键风险 | 可以分别保留，记录任务与后果依据；不是全站字符串只能出现一次 |
| 一次操作成功 | 轻量反馈；持久状态由对象本身承载，避免长期成功横幅叠加 |
| 异步作业/重试/切对象、Tab、机构 | 绑定对象/作业/版本；终态替换或撤下旧消息，迟到响应不能串上下文 |
| 历史/只读/预览模式 | 不提示执行不存在的保存、添加或发布；按真实不可编辑原因反馈 |

复用宿主反馈/字段/状态组件；业务层决定显示条件，通用组件不自行添加无关教学。优先修消息所有权和状态映射，不为去重引入消息总线、新依赖或万能上下文。不要用CSS隐藏、弱化对比度或缩小字体减少信息负担。

## 最终校验：可观察的准入规则

| ID | 检查 | 通过依据 |
| --- | --- | --- |
| NOTICE-01 | 默认/有数据/无数据及所有相关子上下文 | 每条常驻说明有当前用途；无必要就不展示 |
| NOTICE-02 | 宿主、详情、步骤、摘要、弹窗同时核对 | 无重复完整解释和同次错误双重播报；独立决策例外有依据 |
| NOTICE-03 | 只读、预览、历史和不同权限 | 没有不可执行指导、泛化权限噪声或错误归因 |
| NOTICE-04 | 提交→处理→成功/失败→重试及上下文切换 | 无过期、相反或串对象消息；不把上传成功当作处理完成，不把提交当作签发 |
| NOTICE-05 | 修正字段错误、恢复请求、关闭重开 | 失效错误撤下，当前错误/风险和恢复入口仍可见 |
| NOTICE-06 | 浅/深、桌面/窄屏、键盘 | 主要任务可见，必要提示可读，按需帮助可达，焦点和播报不退化 |

沿用[业务文案清单](business-copy.md)逐项记录 DELETE/MERGE/ON_DEMAND/CONDITIONAL/KEEP、必要性、同义组、出现/解除条件、展示责任方与实际证据。条件/权限/消息生命周期变更补行为回归；单纯措辞不写镜像字符串测试。

源码审查不等于运行验证。实际触发不了的服务端错误、作业终态或角色分支标未测，不拿关键词清零、Banner数量、截图数量、构建通过冒充验收。语义重复由上下文审查和具体用例证明，不宣称已有自动工具能全部判定。
