# 企业 SaaS 的任务与信息体验

用于工作台、业务表单、对象列表和详情的设计与审核。目标是让操作者找到对象、判断当前任务并完成下一步；视觉精致来自稳定层级、准确状态和顺手操作，不来自渐变、装饰卡片或虚构的 AI 功能。

与[任务流程](task-flow-and-hierarchy.md)、[表单与反馈](forms-and-feedback.md)、[提示治理](notice-economy.md)共同使用；保留宿主产品的信息架构、组件与真实业务契约。

## 依据与适配边界

| --- | --- | --- |

| [Linear display options](https://linear.app/docs/display-options) | 个人显示偏好与工作区默认设置区分，可恢复默认 | 将个人视图、团队共享视图和组织默认值分开标记；权限与持久化按宿主契约实现 |

| [Shopify Polaris React tables](https://polaris-react.shopify.com/components/tables) | 数据比较表与对象索引表承担不同任务 | 比较指标使用数据表；寻找、选择和进入对象使用索引列表/表，行身份与入口清楚 |

下文的组合、Blueprint 字段和 SAAS 检查是本 Skill 的实践适配。专家密度、证据流和 AI 边界是这里的设计约束，不将它们包装成上述来源的原话或普遍效果结论。

## 先选任务关系，再选页面外观

| 用户当前任务 | 首选组织方式 | 首屏必须看到 | 何时换用其他方式 |
| --- | --- | --- | --- |
| 从待办中决定先处理哪一项 | 任务索引 → 选中摘要 → 详情/办理 | 对象身份、任务、状态、期限/优先级的真实依据、下一动作 | 工作量少时可直接列表；不要为了三栏布局制造摘要与详情重复 |
| 熟练地连续登记或调整配置 | 分组单页/紧凑设置＋就地反馈 | 当前输入范围、相关只读事实、保存动作 | 有真实前后依赖且低频时才考虑分步 |
| 完成低频且有依赖的申请 | 分步输入＋必要的最终核对 | 当前步骤、已完成范围、返回与保存方式 | 独立字段不拆成强制步骤；审批状态另行表达 |
| 核查一张带多条明细的单据 | 单据摘要＋可比较明细＋局部编辑 | 主对象、明细范围、差异和提交范围 | 长篇解释或复杂子对象进入详情，不挤进每行弹出层 |
| 阅读材料并作出审批/复核决定 | 对象摘要＋材料/证据＋决策区 | 待决问题、相关版本、阻塞、可执行动作 | 大文档使用工作区；小范围属性修改才用抽屉 |
| 寻找、选择或批量管理对象 | 对象索引表/列表＋筛选与选择工具 | 身份、区分同名的事实、选择范围、进入入口 | 要横向比较度量时使用数据表，不能把全部行都做成卡片 |
| 比较指标或诊断差异 | 数据表＋必要汇总/图表 | 口径、单位、比较维度、数据时间 | 需要办理对象时保留到详情的明确入口 |
| 查询历史与判断信息可信度 | 结论/当前状态＋按时间排列的证据 | 当前事实、来源、相关时间、可追溯记录 | 无历史契约则不制造时间线；未知来源明确留空或标未知 |

选型依据是频率、依赖、并行比较和后果，不是字段数量或流行布局。允许组合，但每个区块都要有独立任务；避免摘要、卡片和详情重复同一组事实。

## 对象、任务与下一动作

- 页头回答“正在处理谁/什么”，工作区回答“当前要做什么”，动作区回答“接下来可以做什么”。状态与对象相邻；不要让用户从导航菜单猜业务阶段。
- 将任务命令、筛选查询和视图工具分组。主要命令位置稳定，打印/导出等辅助操作按真实任务降级；只读页面不制造主按钮。
- 下一动作绑定当前对象、角色、状态与前提。缺少前提时给真实原因和可用路径；没有权限、没有接口或尚未实现的操作不能做成可点击假入口。
- 列表选择、详情打开与编辑保存是不同范围。切换对象要保持选中关系、可预期的返回位置和未保存输入保护；不能让迟到响应覆盖新对象。
- 可降低导航和工具的视觉重量，但标签、入口与焦点仍可辨。不要用隐藏边框、淡文字或只在 hover 出现的命令换取“干净”。

## 渐进展开与熟练操作

- 默认展示当前办理所需字段和判断事实。附件明细、历史、少用设置可按需展开；关键风险、错误、阻塞与恢复路径保持就地可见。
- 展开入口说明对象和范围，例如“变更记录 4”，不用大量“了解更多”。展开后保持键盘可达，关闭后焦点有归属。
- 专家任务允许高密度列表、键盘操作、批量编辑和紧凑设置；能力必须由真实组件和业务契约支持。紧凑密度不缩小必要文字、命中区或错误反馈。
- 新手与专家不必拆成两套页面。优先利用稳定分组、可选说明、列显隐与密度设置；引导只在需要时出现，不强制熟练用户反复走向导。
- 响应式按内容依赖重排：列表与详情可转为前后导航，表单减列，主要动作仍可达；不能在窄屏简单隐藏业务事实。
- 核对页用于检查将提交的范围、关键答案与后果。局部“修改”指向具体字段/步骤；回到核对页时反映修改后的值，不要求重复填写。

## 状态、证据与持久化诚实

- 区分输入已改变、本地草稿、服务端已保存、已提交、处理中和业务完成。显示方式可轻量，但每个状态必须有实际依据与失败恢复。
- 自动保存须说明实际保存范围和失败状态；本地存储不能叫“已同步”。请求结果未知时核实结果后再重试，不能直接宣告失败或成功。
- 采用“列表 → 摘要 → 详情/证据”的读取层次：列表帮助取舍，摘要帮助判断，详情承载依据。不要在三处复制完整字段和长解释。
- 时间按含义标记：业务发生、记录创建、最近同步和数据截至时间不能混用。只展示当前判断所需的时间与来源；详细审计记录可展开。
- 来源链接、版本与证据归属于具体事实或结论。旧记录保留其历史身份；新状态不能覆盖历史证据并伪装成当时已知。
- 明确区分零值、未填写、不适用、未知、未加载和读取失败。“零待办”只说明当前队列为空，不说明历史对象或报告不存在。
- 初次无记录、筛选无匹配、无权限与读取失败使用不同反馈与可执行动作；不要以“暂无数据”遮盖全部情况。

## 个人视图、团队默认与 AI 辅助

- 视图说明归属：临时筛选、个人已保存视图、团队共享视图、组织默认。改个人列宽/排序不能静默覆盖团队设置。
- 保存视图前明确名称、范围与权限；离开重进验证真实持久化。若宿主只有临时状态，就按临时状态设计并命名。
- 恢复默认、修改共享视图、删除视图的含义分别准确；保留可恢复路径须以实际能力为准，不伪造撤销按钮。
- AI 仅在真实能力存在时进入任务流。建议与已确认事实区分，提供可用来源/依据、影响范围、接受及撤销/恢复路径；不能假装建议已经执行。
- AI 生成后仍按普通表单检查字段与业务规则；来源不可得时明确说明，不能捏造引用。不得为“现代感”添加空聊天入口、星光图标或假摘要。
- 若没有可验证的来源、接受或恢复契约，先记录缺口和设计限制；不要用模拟按钮暗示产品已具备完整辅助能力。

## UI Blueprint 增补

沿用现有 Blueprint，不另造主账；每个适用页面/旅程记录以下决策。

| 记录项 | 最小内容 |
| --- | --- |
| 当前任务 | 角色、对象、目标、进入条件、下一动作、完成依据与阻塞 |
| 任务构图 | 矩阵中的选择、频率/依赖依据、列表/摘要/详情各自负责的事实 |
| 信息层次 | 默认可见、按需展开、必须就地可见；每项的当前决策用途 |
| 保存与视图 | 数据/选择/提交范围，临时/本地/服务端状态，个人/团队归属及恢复能力 |
| 证据与状态 | 事实来源、时间含义、版本、未知/失败映射和历史保留方式 |
| 密度与重排 | 专家操作、键盘路径、桌面/窄屏关系及不可隐藏的信息 |
| AI（如适用） | 真实接口、来源能力、建议/执行边界、接受和撤销/恢复合同 |
| 验证范围 | 用例、角色、数据与截图/回读证据；原型、运行验证与真实用户观察分别记录 |

## 可观察检查

| ID | 检查动作 | 通过依据 |
| --- | --- | --- |
| SAAS-01 | 从入口定位一个对象并开始办理，切换到另一个对象 | 身份、任务、状态和下一动作清楚；动作资格真实，无串对象响应或未保存输入丢失 |
| SAAS-02 | 以熟练用户完成常用任务，再走依赖申请的返回/核对 | 构图有频率与依赖依据；不强制无意义向导；必要事实可达，修改保留输入与返回位置 |
| SAAS-03 | 保存、失败、断开/重进、结果未知和完成后回读 | 草稿/保存/提交/业务完成准确；范围、持久化和恢复与真实契约一致，无假成功 |
| SAAS-04 | 从队列经摘要追到证据，分别触发零值、空、未知与失败 | 三层信息分工明确，来源/时间/版本可辨；空态和恢复匹配事实，不把未知当零或历史不存在 |
| SAAS-05 | 调整并保存个人视图，以另一角色查看团队视图并恢复默认 | 归属、权限与影响范围准确；个人改动不意外传播，重进与恢复结果有实际证据 |
| SAAS-06 | 桌面/窄屏用键盘完成任务；存在 AI 时检查来源、接受和恢复 | 导航/动作位置可预测，信息重排且焦点可见；AI 建议与事实/执行区分，能力缺口明确标未测 |

不适用的检查写明理由；触发不了的角色、服务端分支或 AI 能力标“未测”，不能用静态截图补成通过。
