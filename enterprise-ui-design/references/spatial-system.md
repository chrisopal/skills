# 空间、布局与对齐 · v1.2

Create、Upgrade、Audit 共用本规范。目标是让不同页面具有一致的空间秩序，同时保留业务需要的密度与专业工作面。这里的数值是本 Skill 的起点；接入现有设计系统时，优先映射其合理 Token，不为一个数值差异重写组件。

Profile、主题和密度是三条独立轴：Profile 只覆盖声明的语义视觉值，主题提供明暗背景与前景，密度只覆盖控件、面板和表格间距。默认级联为 Enterprise 基线 → theme → optional Profile → density；Analytics 的浅色组合回退 Enterprise，不把移动断点自动当作 compact。Portal、Teleport、Dialog 和菜单必须继承同一组 `data-ui-profile`、`data-theme`、`data-density` 属性。

## 1. 先确定四层空间责任

| 层级 | 负责 | 不应重复负责 |
|---|---|---|
| 应用框架 Shell | 导航、顶栏、工作区边界及全高关系 | 在主工作区外再套一圈页面 padding |
| 页面 Page | 内容宽度、两侧留白、标题与区块之间的节奏 | 再给每个直接子区块重复页面留白 |
| 区块 Section / Panel | 有业务意义的分组、必要表面、内部 inset | 给已有面板留白的子分组再套同样 inset |
| 组件 Component | 字段、单元格、按钮和图标内部空间 | 用额外 margin 修补父级布局问题 |

同一个空间关系只设一个负责人：兄弟间用父级 `gap`；容器边缘到内容用该容器 `padding`。避免父 `gap` 与子上下 margin 同时承担同一段间距。组件库已经提供内边距时，先消费或映射它，不继续套一层补偿容器。

检查浏览器默认样式产生的隐含空间，例如 `dd` 缩进、列表和标题 margin；只在对应组件内校准，不用全局重置破坏专业内容。空的错误/帮助/状态节点不应无意参与 Grid/Flex gap；需要预留反馈空间时应有明确理由。

嵌套本身并非错误：带独立边界的子面板可以有 inset；单纯的语义分组通常只需要标题、gap 或分隔线。每增加一层表面，都应能说明它表达了什么边界。

## 2. 内容宽度按任务选择

| 内容 | 默认策略 | 大屏与窄屏行为 |
|---|---|---|
| 数据列表、跨列比较 | 在工作区内流式铺开 | 保留字段可读宽度；横向溢出仅在表格容器内 |
| 概览 / 运营页 | 可限宽到 `layout-content-overview-max`，1440px | 额外宽度成为外侧留白，不把少量指标无限拉散 |
| 详情、文档阅读 | `layout-content-reading-max`，960px | 限制阅读宽度；宽表可另设溢出区，不压缩整页字号 |
| 编辑表单 | `layout-content-form-max`，800px | 短字段不无条件铺满；列数由实际可用宽度和标签长度决定 |
| 画布、编辑器、图谱 | 沿用专业工作面的宽高和滚动 | 统一外框与工具栏，不套阅读限宽 |

这些最大宽度不包含页面两侧 inset。已有产品按内容区左对齐或居中时保持原约定；同一页面族不可任意切换。中文长文还需单独限制正文行长，不能将详情容器的最大宽度直接当成正文最佳行长。

断点决定全局导航结构；组件能否排成两列，要看它实际得到的空间。侧栏、详情面板展开后，即便视口仍是桌面尺寸，筛选条和表单也可能需要换行。优先使用 Grid/Flex 自适应，已有容器查询能力可复用，无需为了本规范升级框架。

## 3. 对齐线：区分容器边缘和内容起点

每个页面 Blueprint 指出主要对齐线，不要求所有元素都贴同一条线：

- **页面线**：页面标题、一级区块外边缘、页级操作区域遵循同一内容边界。
- **内容线**：同一表面内的标题、筛选字段、正文或表格首列内容起点协调。表格边框贴面板边缘时，首列 inset 应与工具栏内容 inset 协调；必要时只调整首末列。
- **字段线**：同一表单组采用一致标签布局。长标签允许换行；错误信息出现后，同一行控件仍按标签/控件的结构对齐，不能简单按整个字段盒子居中。
- **行内线**：标题与状态按文字基线或有意的视觉中心排列；图标与文字按组件内部规则对齐。行高与字形可能需要光学修正，不用任意负 margin 掩盖问题。
- **数据线**：文字列按阅读方向对齐；可比较数值右对齐，必要时使用等宽数字；单位、日期、空值的展示规则一致。
- **操作线**：同一记录的操作作为整体对齐，组内固定 gap。页面标题和页级操作可以两端排列；不可把一行内每个按钮逐个两端拉散。

空状态、加载状态和数据态共用容器边界，不能出现有数据后宽度和起点突然变化。图表轴标签、缩进树、分组行、拖拽手柄等可以有明确局部偏移，记录它们对齐的是外框还是内容。

## 4. 间距层级与语义 Token

保留 4px 刻度；4/8 用于细部，12/16/20 用于组件和分组，24/32 用于区块与页面。不要把每一层都统一成 24px；相关对象靠近、不同任务适当分开。

| Token（均带 `--ui-`） | 标准 | 紧凑 | 空间责任 |
|---|---|---|---|
| `layout-page-inset-inline` | 32px | 不变 | 桌面页面左右留白 |
| `layout-page-inset-block` | 24px | 不变 | 页面上下留白 |
| `layout-page-inset-narrow` | 16px | 不变 | 窄屏页面留白 |
| `layout-section-gap` | 24px | 不变 | 一级区块之间 |
| `layout-group-gap` | 16px | 不变 | 同区块内不同语义组 |
| `layout-panel-inset` | 20px | 16px | 面板边缘到内容 |
| `layout-field-gap` | 20px | 16px | 表单字段之间 |
| `layout-action-gap` | 8px | 不变 | 同组操作之间 |
| `layout-icon-gap` | 4px | 不变 | 图标与短标签 |
| `density-control-height` | 34px | 28px | 控件视觉高度的适配起点 |
| `density-cell-padding-block` | 12px | 8px | 表格单元格上下内边距 |
| `density-cell-padding-inline` | 16px | 12px | 表格普通列左右内边距 |

只读文档的章节可使用现有 `space-8`（32px）以强化阅读节奏，选择后同类章节一致。数值真值在 [tokens.json](../assets/tokens.json)，不是在页面中再声明一套相似变量。

标准/紧凑由根属性 `data-density="standard|compact"` 选择；不与浅/深主题绑定。紧凑只减少适合密集操作的内部空间，不缩小正文、不消除分组层级、不因手机屏幕小就自动进入紧凑模式。触控与可访问性需要更大的实际点击目标时，独立扩大命中区域或沿用组件库触控配置。

控件高度必须检查实际渲染值。只减少 `min-height`，但仍保留更高的行高、padding和边框总和，紧凑控件不会变矮；通过组件库 size 配置或协调内部尺寸解决，不截断文字。多行输入不套单行控件固定高度。

兼容：v1.0 的 `page-padding`、`panel-padding`、`control-md` 等保持不变；新增布局采用语义 Token。迁移一个页面族时明确选用新合同，不让同一间距同时受新旧两套规则控制。CSS 只提供变量，不自动重排已有页面。

## 5. 正向构图要求

- 标题、数据、动作形成可扫描顺序。通过字号/字重/间距区分层级，不把所有文字都加粗。
- 留白表达关系：组内比组间近，主任务周围保持可辨认的空间；不靠空白填充把关键操作推到首屏之外。
- 只在需要独立边界时增加表面。背景、轻边框与分隔线应有各自用途，不默认“一个字段组一张卡片”。
- 强调色主要服务当前操作、选中与真实状态；主按钮的数量和位置与任务优先级一致。
- 桌面大屏保持信息关系，窄屏保持任务顺序。少数据时不拉长字段填满宽度，多数据时不通过压小字号容纳。

## 6. 页面模式

### 列表

页面标题/主操作 → 筛选 → 表格工具栏（需要时）→ 表格 → 分页。筛选、表格与分页是同一数据任务，可共享一个表面；不为每条横栏增加独立卡片。筛选字段有可读标签与合理宽度，按钮组整体换行。标题长文案、筛选多行、操作列两按钮和长数据都需验证。表格容器有可访问名称，需要时可用键盘滚动。

### 详情与表单

标题和状态靠近，元信息与正文分组；低频 ID 用 details 等可访问入口保留。详情与编辑使用协调的内容边界。两列表单仅在字段宽度足够时使用；长文本占整行。字段错误不覆盖下一字段，表单操作不漂移到与正文无关的位置。

详情的字段组与空态按[只读详情与空状态构图](forms-and-feedback.md#只读详情与空状态构图)执行。Blueprint 标出标题、状态、内容、恢复操作各自的 inset 责任；实测首末字段/空态到四边的距离及标签/值对齐，不以声明 padding 或空态组件已渲染代替。空态只在所属内容区居中，标题与工具栏保持内容线；对加载、有数据、空与失败分别检查，不能用空表替代有数据构图。

### 弹窗 / Drawer

标题、正文、底部操作共享设计好的内容线，关闭按钮可按其命中区域有意偏移。只让明确的正文区或整个浮层承担滚动，不同时叠加多个不必要滚动区。低高度、放大及窄屏仍能到达关闭与提交，焦点顺序与视觉顺序一致。

## 7. 轻量接入示例

这是 app-owned 布局示例，类名不是强制 API。先复用项目已有 Page/Stack/Inline 等组件；没有对应能力时，再在共享层增加少量布局规则，不引入另一套组件框架。

```css
html[data-ui="enterprise"] .work-page {
  min-width: 0;
  padding: var(--ui-layout-page-inset-block) var(--ui-layout-page-inset-inline);
  display: grid;
  gap: var(--ui-layout-section-gap);
}
html[data-ui="enterprise"] .work-panel {
  padding: var(--ui-layout-panel-inset);
}
html[data-ui="enterprise"] .work-panel__group {
  display: grid;
  gap: var(--ui-layout-group-gap); /* 复用父面板 inset，不再添加一圈 padding */
}
@media (max-width: 767px) {
  html[data-ui="enterprise"] .work-page {
    padding: var(--ui-layout-page-inset-narrow);
  }
}
```

可运行的复用源：[reference-workbench/index.html](../assets/reference-workbench/index.html)。在 Skill 根目录执行 `python3 -m http.server 8765 --bind 127.0.0.1`，打开 `/assets/reference-workbench/`。数据为本地模拟，存储和筛选用于验证布局及操作路径，不代表接入业务系统。不要为了迁移现有项目而直接复制它的业务内容。

## 8. 验收：量化布局，目视判断构图

1. 标注视口、侧栏/辅助栏状态、页面类型、密度、主题及实际数据状态。沿用目标项目必要尺寸，默认检查 1366/1440/1920/390px，并检查断点附近。
2. 截图前读取实际 computed padding/gap/max-width 及关键容器的 bounding boxes。检查留白由谁产生；不能只搜索源码中的 `24px` 就判合格。
3. 检查页面线和内容线、首末列、字段/错误提示、换行后的操作组以及嵌套 inset。有意的缩进和光学校准单独记录；允许字体、边框和亚像素舍入，不设跨产品统一像素误差门槛。
4. 检查长中英文、长状态/姓名、200% 缩放或等效窄可用宽度、低高度浮层、多行筛选、无结果和实际数据。空表截图不能替代有数据检查。
5. 标准/紧凑 × 浅色/深色不相互覆盖。页面无意外横向溢出；宽表内部滚动，焦点和关键操作可达。
6. 用同状态前后截图判断层级、节奏和整体构图。自动几何检查证明尺寸和溢出；截图差异工具辅助定位；审美判断必须明确人工/模型目视范围。有参考图才声明对参考的相似度，无参考图时只给规范符合性结论。

## 9. 参考依据与本地决策

查阅日期：2026-10-17。借鉴方法，不复制品牌、强制栅格列数或整套组件。

- [Atlassian Grid](https://atlassian.design/foundations/grid)：区分顶层栅格与内部间距，按内容选择固定/流式网格。
- [Atlassian Spacing](https://atlassian.design/foundations/spacing)：间距刻度、接近性和层级；它以 8px 为基础并包含细分值，本 Skill 保留现有 4px 刻度。
- [Carbon 2x Grid](https://www.carbondesignsystem.com/building-blocks/foundations/2x-grid/overview)：关键对齐线、固定/流式区域和纵向节奏。
- [Ant Design Layout](https://ant.design/docs/spec/layout)：区分固定导航和伸缩工作区，交付 gutter 与内容边界。

本规范的 32px 页面 inset、20px 面板 inset、三个内容最大宽度和两种密度是兼容既有 Skill 的本地默认，不是这些系统共同规定的标准。
