# 统计视图设计决策

用于指标首页、运营工作台、质量/设备分析、项目经营报表等真实业务统计。该参考补充[计划、进度与数据图表](planning-and-visualization.md)的选型规则：先冻结统计口径，再决定视觉表达；美观只能提高可读性，不能改变分母、粒度或数据来源。

## 1. 统计视图契约

在 Blueprint、接口契约或数据字典中记录以下字段；缺少其中会改变解释的字段时，统计视图标记为 `BLOCKED` 或按真实能力显示缺口，不用占位数字补齐。

| 契约项 | 必须回答的问题 | 界面可观察结果 |
|---|---|---|
| 指标与对象 | 统计什么对象、事件或测量值？是订单、样品、设备、任务还是金额？ | 标题和数据表字段使用业务名，不把内部字段名当指标名 |
| 统计时间 | 依据哪个时间字段，起止边界是否含当天，使用哪个时区？ | 过滤器、轴标签、导出/明细范围与请求一致 |
| 粒度 | 每日、每周、批次、实验室、设备或单条记录？ | 同一粒度内不重复聚合；粒度在标题、轴或帮助信息可见 |
| 单位与精度 | 件、小时、元、%、浓度或无量纲？小数位和四舍五入规则是什么？ | 轴、图例、Tooltip/数据表和 KPI 使用同一单位及精度 |
| 分母与分子 | 百分比、率、达成度的分子/分母来自什么集合？分母是否排除未知？ | 百分比旁能找到总量/分母；分母为零或未知不显示伪造 0% |
| 来源与时效 | 哪个 API/查询字段提供数据，截止时间、刷新状态和权限是什么？ | 显示“截至/更新时间”；失败保留旧值时明确旧数据，不冒充最新 |
| 缺失与异常 | `null`、零、无记录、非法值、重复记录、离群值如何区分？ | 零有零值表达，缺数有缺失表达，异常有标记或说明，不静默修正 |
| 选择与范围 | 用户选择的图类、筛选、排序、分组是否有持久契约？ | 支持的显式图类选择被保留，切换到数据表后范围不丢失 |

生产统计只能消费现有真实业务数据或其已批准的聚合接口。模拟数据、随机数、示例填充行、自动生成的“趋势”只能用于独立演示并明确标识；不能进入生产路径、截图或回读证据。

## 2. 先按决策任务选图

一页可以只包含一种图和一张数据表；不为“丰富”强行堆叠全部图类。每个图旁保留同范围的数据表或可访问明细入口，除非产品契约明确不允许查看明细。

| 业务组合 | 视觉配方 | 必须显示的口径 | 不得这样做 |
|---|---|---|---|
| 趋势：期间内看完成量、合格率、响应时长 | 折线＋时间轴＋末端/选中点标签；多序列共用单位和刻度，系列不超过可读数量 | 时间字段、粒度、单位、缺失期间、分母（率类） | 无序类别连线；把缺数补成零；把计划线当实际值；双轴掩盖量级差异 |
| 对比：实验室、设备、部门、品类之间比较 | 柱状/横条＋排序规则＋数据表；长类别名用横条，负值穿过零线 | 对象范围、单位、排序、零基线；必要时显示目标和实际的定义 | 用面积、3D、气泡大小替代长度；截断零基线却不提示；把多个单位放同一轴 |
| 组成：样品类型、状态、费用构成 | 少类别环图显示总量＋中心总数，或堆叠/100%堆叠条形按时间/对象比较 | 可加总的类别、总量、分母、未知/其他项 | 类别重叠仍加总；大量小项塞入环图；不同分母并排比较；用颜色隐藏未知 |
| 分布：检测值、耗时、金额、批次测量 | **真实直方图**：数值轴＋明确 bin 边界/宽度＋频数或占比；必要时另给中位数/分位数摘要 | 有效样本数 `n`、单位、分箱规则、范围、缺失/无效数、百分比的分母 | 用“每个类别一个柱”的柱图冒充直方图；按视觉需要改 bin；把类别标签放在数值轴上；把无效值悄悄丢弃 |
| 关系：温度与故障、金额与周期 | 散点/热力图，图例标明聚合或密度；用明细/筛选入口追查 | 两个变量的单位、粒度、样本范围、聚合方式 | 把相关写成因果；颜色梯度没有刻度；不同粒度点混在一起 |
| 监控与追查：异常数、及时率、待办量 | 少量 KPI（值＋单位＋时间）＋一张相关趋势/对比图＋明细入口 | 截止时间、目标来源、阈值、分母和权限范围 | 没有真实目标就画达标环；把阶段序号当百分比；用卡片数量制造“仪表盘” |

### 2.1 图类选择和小样本优先级

- 用户明确选择了已支持且契约匹配的图类时，少量记录、长尾类别或单个点不应自动改成另一种图。保留该图类，标明 `n`、稀疏/单点状态，提供数据表或“建议切换”操作；切换必须是可见选择。
- 数据不足以支持该图类的统计语义时，仍保留用户选择和原因，例如“直方图需要数值测量，当前字段为分类状态”，再提供真实可用的表格/条形图入口。不得把不支持能力伪装成空图或成功生成。
- 无记录是“暂无数据”，全量为零是“有数据且为 0”；缺失期间不补点。只有一个有效观测值的直方图可显示单个 bin 和 `n=1`，若产品约束要求最小样本量，则显示该约束及原始值入口。

## 3. 视觉配方与信息层级

按既有 Token 和宿主组件实现，以下是语义配方，不是新增颜色/尺寸体系：

1. 标题行：`指标名 + 范围/粒度`；右侧放更新时间、过滤摘要和“数据表/明细”入口。
2. 口径行：单位、分母、有效样本数或分箱说明只在影响决策时显示，可放键盘可达的帮助/详情中；不要重复一段解释性副标题。
3. 绘图区：只保留必要网格线、零线、刻度和标签；数据标签用于少量关键点，密集数据通过表格和 Tooltip 补充。
4. 语义映射：同一业务状态/系列跨页面保持同一 Token；系列颜色与成功/警告/错误状态颜色分离。浅色和深色都要有足够对比，并用线型、图案或文字补足颜色差异。
5. 结构边界：图、图例、空态、失败态和数据表属于同一统计模块但各自拥有内容边界；相邻卡片不能靠绝对定位填洞，长图例应换行或进入具名滚动区。

柱/条形图从零起点；确需截断时在轴旁明确范围和原因。折线图保持时间顺序，缺失点留空或断线。环图中心显示总量/分母，而不是只显示百分比。直方图的柱宽表达连续区间，柱之间不留表示分类间隔的空白；bin 边界、范围和 `n` 可读。

SVG 图表不能把固定设计宽度（例如 600 单位）直接压缩进窄容器，导致坐标、图例或数据标签横向变窄。应按最终容器宽度同步 `viewBox` 或等效绘制尺度，并等比换算时间坐标；响应式重排须保留原时间间距、缺失期间和断线位置。设计评审要看最终渲染后的文字包围盒、比例和边缘裁切，不以 CSS `font-size` 或源码声明文字可读代替。

## 4. 状态、响应式和数据表

| 状态/环境 | 设计决策 | 可观察断言 |
|---|---|---|
| 加载 | 骨架只表达结构，不填预测数字或随机走势 | 真实响应前看不到业务数值 |
| 零、缺数、无记录 | 零画在零线/显示 0；缺数断开或标记；无记录显示短空态并保留范围 | 用户能区分三者，且数据表不会凭空出现行 |
| 异常/离群 | 保留原始值，使用异常标记、范围说明或详情入口；不无提示裁剪/封顶 | 图和表中的原值一致，异常可追查 |
| 无权限 | 统计和明细均不泄漏；显示无权限状态 | 不通过图例、总量或下载接口泄漏聚合结果 |
| 刷新失败 | 保留旧数据时同时显示旧更新时间和刷新失败；没有旧值则显示失败态 | 不把旧值标成最新，重试后回读新状态 |
| 390px | 标题、口径、图例和表格按顺序可达；图表可在具名容器局部滚动，数据表不被卡片裁切 | 无页面级横向溢出；焦点不落入不可见图例/关闭面板 |
| 桌面/浅深主题 | 同一数据、范围、排序和图类保持一致，仅布局与 Token 适配 | 关键标签、零线、选中/警告状态在两主题均可读 |

图表与表格必须共用同一个已应用筛选、权限和数据快照。切换视图或改变窗口宽度后，数据集合、排序、选中对象和分页不应悄悄改变；数据表需要完整列名、单位、全部行/分页和键盘可达的排序。下钻后返回要恢复时间范围、分组和图类选择。

## 5. 可执行验收清单

在[组件评审模板](component-review-template.md)中记录以下断言；对应真实浏览器证据和数据回读由 `ui-regression-acceptance` 的[统计视图检查](../../ui-regression-acceptance/references/statistical-view-checks.md)执行。

| ID | 检查动作 | 通过条件 |
|---|---|---|
| STAT-D01 | 逐项读标题、过滤、更新时间、单位、粒度、分母、`n` 和来源 | 口径能在 UI 或契约绑定的详情中找到，并与真实请求一致 |
| STAT-D02 | 用趋势、对比、组成、分布各一个真实业务样本复核图类 | 每个图类服务对应决策；直方图使用数值区间，不把柱图当直方图 |
| STAT-D03 | 注入/准备真实零值、缺数、无记录、异常和长类别 | 零/缺数/无记录/异常不混淆；不补假数据、不静默裁剪 |
| STAT-D04 | 选择支持的图类后缩小样本，再切数据表并返回 | 小数据保留显式选择；图表、表格和筛选范围一致，返回上下文保留 |
| STAT-D05 | 在浅/深主题与桌面/390px 读取图、图例和表 | 关键差异不只靠颜色；无页面级溢出，局部滚动和焦点可用 |
| STAT-D06 | 刷新成功、刷新失败、无权限、无数据后回读 | 状态语义不同；权限不泄漏；旧数据标旧；真实数据表与 API/明细回读一致 |
| STAT-D07 | 将含坐标、图例、长标签和缺失期间的 SVG 置于桌面与 390px，读取最终渲染尺寸 | SVG 不被横向压扁；最终比例/文字包围盒可读且无边缘裁切；时间间距和缺口与原数据一致，不以 CSS 字号声明代替检查 |

## 设计依据

- [Carbon 数据可视化总览](https://www.carbondesignsystem.com/building-blocks/data-visualization/overview)：按表达目的选择图表，并保持图例、标签和交互可解释。
- [Carbon 坐标轴与标签](https://carbondesignsystem.com/data-visualization/axes-and-labels/)：轴、单位、刻度和标签共同承担数值解释，不能只靠图形形状。

上述资料只支持通用表达语义；本参考的真实数据、业务分母、权限、响应式与回读要求仍以宿主产品契约为准。
