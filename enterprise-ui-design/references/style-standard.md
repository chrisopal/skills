# 企业工作台 UI 规范 · v1.1

**定位：克制、扁平、统一、信息清楚的企业工作台。**

本规范来自 MBC 设计参考及 MateClaw 企业主题的实际适配，包含实施时补充的浅色/深色对比度修正。它不绑定产品、框架或组件库，可用于 React、Vue、Angular 及其它前端。

相同风格不等于相同业务界面：保留目标项目的名称、Logo、路由、菜单、权限、数据流和成熟交互，不复制 MateClaw/MBC 的业务内容。聊天、图谱、工作流画布和媒体预览保留专业布局。

本 Skill 的 `assets/tokens.json` 是机器可读真值，`assets/tokens.css` 是框架无关变量起点；实现时按目标项目的主题系统映射，不能盲目覆盖全局样式。

## 目录

- 约束级别与视觉原则
- 颜色、排版、圆角、间距、布局和层级 Token
- 组件、响应式、深色模式和无障碍约束
- 新建项目、存量升级与验收边界

## 1. 约束级别

- **必须**：跨项目不变的风格、行为保护和验收要求。
- **默认**：推荐的视觉数值；可因实际窗口、文字长度或组件库限制调整，但同类组件应统一。
- **例外**：需要说明原因、影响范围及验证结果，不把一次例外扩展成全局规则。

## 2. 视觉原则

### 必须

1. 普通交互只使用一套蓝色体系，灰阶负责信息层级。
2. 优先用间距、对齐、字号与细边框区分结构，不靠卡片层层嵌套。
3. 普通页面与面板使用纯色背景，不做渐变、玻璃模糊、发光或厚重阴影。
4. 主内容是状态、数据和操作；工作台不放无助于操作的营销 Banner。
5. 保留一个明确的页面级主操作，其余动作降低视觉权重。危险操作不能伪装成普通主操作。
6. 不使用整张卡片降低透明度来表达“次要”，以免连带文字和按钮失去可读性。

### 允许的例外

- 品牌 Logo 可以是经确认的 3D 图形；材质自身的明暗可以保留，但不额外添加 CSS 光晕、呼吸动画或漂浮。
- 图表、语法高亮、状态和数据可视化可以使用语义颜色，不强制变成全蓝。
- 聊天输入区可用 8px 圆角，圆形头像/状态点保持圆形，开关可保留其原生形状。
- 图片、文档和生成内容应保持真实颜色，不受工作台主题滤镜影响。

## 3. 颜色与语义 Token

| 用途 | 浅色 | 深色 |
|---|---|---|
| 品牌蓝 / 导航指示线 | `#1677FF` | `#1677FF` |
| 可读链接、选中文字 | `#0966D9` | `#80B5FF` |
| 实心主按钮 | `#0966D9` | `#1558B0` |
| 实心按钮悬停 | `#0754B5` | `#1A65C8` |
| 实心按钮文字 | `#FFFFFF` | `#FFFFFF` |
| 页面画布 | `#F5F7FA` | `#101722` |
| 面板 / 侧栏 / 顶栏 | `#FFFFFF` | `#182230` |
| 主要文字 | `#0B1220` | `#EDF2F9` |
| 次要文字 | `#526075` | `#B8C5D8` |
| 辅助文字 | `#68758A` | `#9AAAC0` |
| 默认边框 | `#D9DEE7` | `#35445A` |
| 轻分隔线 | `#E7EAF0` | `#2A384B` |
| 选中浅底 | `#EDF4FF` | `#1B304D` |

**必须区分以下三种角色，不能只定义一个 primary 后到处复用：**

- `--ui-brand`：品牌识别与指示，不保证适用于所有小字前景。
- `--ui-action-text`：浅/深背景上的可读交互文字。
- `--ui-action-solid` + `--ui-on-action`：实心按钮的背景/文字配对。

同样，`--ui-inverse-surface` 必须配 `--ui-on-inverse`。深色模式下，浅色提示面不能继续使用白色文字。hover、active、disabled 和 focus 也要逐一检查，不能只验证默认状态。

`border` / `border-subtle` 是装饰分隔线，不承诺满足控件识别所需的对比度；当边框是输入控件唯一的识别线索时，使用 `border-control` 或经过验证的等效样式。Token 不是任意配色都合格的保证：辅助文字放到不同画布后仍需测量，不足时提升到 `text-secondary`。

颜色优先通过语义 Token 消费。页面组件中不新增任意十六进制值；品牌资产、图表系列与经过记录的语义例外除外。状态必须配文字或图形，不仅靠颜色。

## 4. 字体、尺寸与密度

| 项目 | 默认 |
|---|---|
| 正文 / 表格内容 | 14px，行高约 1.57 |
| 表单标签 | 13px |
| 表格标题 / 辅助信息 | 12px；11px 仅用于低频元信息，不用于主要操作 |
| 页面标题 | 24px，字重 600；紧凑二级页可 20–22px |
| 模块标题 | 16px，字重 600 |
| 普通字重 | 400；强调 500/600，不把全页文字加粗 |
| 控件高度 | 小 28px / 默认 34px / 大 40px |
| 控件圆角 | 4px |
| 面板 / 弹窗圆角 | 6px |
| Tag 圆角 | 3px |

默认字体为 Inter + 系统中文字体回退，不强制新装字体包或外部字体网络依赖。数值/标识符可以使用等宽字体；指标值建议启用等宽数字，不把普通正文全部改成代码字体。

间距使用 4px 基数：4、8、12、16、20、24、32、40px。34px 控件、36px 导航项等明确组件尺寸是有意例外。不要用零散的 13/17/27px 间距去补偿结构问题。新布局按 [空间、布局与对齐](spatial-system.md) 选择有用途的语义 Token；保留旧 Token 值供已有项目兼容。标准/紧凑密度独立于浅/深主题，不自动随手机断点切换，不缩小正文字号。

## 5. 页面框架

- 侧栏默认 220px，折叠 56px，与窗口边缘相接；白色/深色面板底加一条右边框。
- 顶栏默认 48px，用于面包屑、工作区/组织上下文及已有的公共工具。
- 不为了“像后台”而新增未实现的搜索、通知、租户切换等假按钮。
- 导航项约 36px 高，14px 文字、16px 图标；选中状态为浅蓝底、蓝字和左侧 2px 指示线。
- 页面、区块和组件的留白责任、内容限宽、关键对齐线及密度以 [空间合同](spatial-system.md) 为准。新布局桌面页面上下24px/左右32px、窄屏16px；面板标准20px/紧凑16px。v1.0的 `panel-padding: 16px 20px` 保持兼容，不与新增语义面板 inset 叠加消费。
- 滚动责任明确：页面、表格或专业画布各自拥有滚动区。Grid/Flex 子项使用合适的 `min-width: 0` / `min-height: 0`，不要直接用全局 `overflow: hidden` 掩盖溢出。
- 尽量减少同屏滚动容器数量；保留必要的导航、表格和聊天历史独立滚动。

## 6. 页面与组件模式

### 登录

桌面可采用 42% 深色品牌区 + 58% 表单区，表单最大宽度 360px、控件 40px。品牌区只写真实产品定位与能力，不复制本规范来源项目的名称。移动端改为紧凑品牌区与单列表单，保证小屏或横屏下可以滚动到提交按钮。

### 工作台

按主要任务组织页面标题、待处理事项、必要指标和明细，不强制每个工作台都出现指标或趋势。指标使用紧凑、平面、细边框容器；不要重复展示同一个指标来填满布局。右侧辅助栏仅在确有上下文或快捷操作时出现。

### 列表 / 表格

标题和主操作 → 筛选工具条 → 连续的表格 → 分页。筛选条与表格视觉连接，不再各套一层厚卡片。表头使用浅灰/深灰底、12px 字号；新布局单元格使用 `density-cell-padding-block/inline`，标准上下12px/左右16px，紧凑上下8px/左右12px。首末列与工具栏内容起点按空间合同协调，现有组件库合理尺寸可映射保留。标识符可用等宽字体；数字列统一对齐，时间/状态格式统一。表格溢出留在表格容器内。

### 表单 / 详情

字段始终有可辨识标签，不用 placeholder 替代标签。长表单分为少量有意义的组，以轻分隔线而非多层卡片区分。错误提示靠近字段，保留原有校验与提交行为。只在字段确实不适用时禁用，并说明原因。

### 按钮 / 标签 / 状态

实心蓝主按钮、边框次按钮、文字轻操作形成三级。按钮默认 34px；移动触控可增加点击区域，不必把整个后台都改成大按钮。Tag 为小圆角浅底。状态采用圆点/图标加文字。危险操作使用语义危险色与原有确认流程。

### 弹窗 / Drawer

遮罩使用中性墨色透明层，禁止暖棕/橙色蒙层。弹窗 6px 圆角，Drawer 靠边时可直角。浮层才使用轻阴影。标题、关闭、正文与底部操作区清楚；保证长内容滚动、键盘操作和关闭后的焦点恢复。

### 聊天 / 工作流画布 / 预览

只统一外层颜色、边框、工具栏和输入控件，不改流式渲染、画布定位、缩放、编辑器、代码高亮或文档原貌。绝不能用 `button`、`svg`、`canvas`、`div` 等宽泛选择器批量覆盖专业内容。

## 7. 动效、响应式与可访问性

- 常规状态过渡约 150ms，只改变颜色、边框、展开与关闭；不添加卡片上浮、缩放或呼吸效果。
- 保留 loading 的必要反馈，并遵循减少动态效果的系统偏好。
- 默认参考断点为 768px 和 1024px；目标项目已有合理断点时优先沿用，不强制重写。
- 按用户指定或目标项目相关视口验证；未指定时默认检查1366、1440、1920px和390px。桌面数据页不出现页面级横向滚动；手机表格允许容器内滚动。默认矩阵不扩大用户明确限定的任务范围。
- 关闭的移动导航不能继续被键盘访问；展开、关闭及焦点恢复行为须可验证。
- 本规范采用普通文本对比度至少 4.5:1、重要控件边界/状态至少 3:1 的验收阈值；异常状态、hover 和 dark 也要检查。
- 可见键盘焦点不能被删掉；纯图标按钮提供可访问名称。检查屏幕放大与长中英文文案。

## 8. 接入其它前端

### 步骤

1. 先找目标项目已有的主题 Token、组件库 Provider 和公共页面框架。
2. 建立本规范语义 Token 到现有 Token 的映射，不让业务页同时使用两套主色。
3. 保留旧主题，增加一个范围清楚的 profile/根属性，先迁移共享层和样板页。
4. 完成组件库主题映射，再修正经截图确认的页面例外。不要直接复制 MateClaw 的页面选择器到别的项目。
5. 覆盖登录、列表、表单、弹窗与一个专业工作面，完成检查清单后再扩展。

### 框架无关起点

把 `tokens.css` 放入目标项目并导入一次。按目标项目已有主题状态设置根属性，例如：

```html
<html data-ui="enterprise" data-theme="light">
```

深色可使用 `data-theme="dark"`，也兼容已有的 `html.dark`。二者只选一种作为主题状态来源，避免出现 `.dark` 与 `data-theme="light"` 相互矛盾。

该 CSS **只提供变量，不会自动把整个应用变成企业后台**。下面是 app-owned 按钮的接入示例，不是通用全局覆盖：

```css
html[data-ui="enterprise"] .app-primary-button {
  min-height: var(--ui-control-md);
  padding: 6px 14px;
  border: 1px solid transparent;
  border-radius: var(--ui-radius-control);
  background: var(--ui-action-solid);
  color: var(--ui-on-action);
  font: inherit;
  font-weight: var(--ui-weight-emphasis);
}
html[data-ui="enterprise"] .app-primary-button:hover:not(:disabled) {
  background: var(--ui-action-solid-hover);
}
html[data-ui="enterprise"] .app-primary-button:focus-visible {
  outline: 2px solid var(--ui-action-text);
  outline-offset: 2px;
}
html[data-ui="enterprise"] .app-primary-button:disabled {
  background: var(--ui-disabled-bg);
  color: var(--ui-disabled-text);
  cursor: not-allowed;
}
```

### 不同组件体系怎么适配

| 目标体系 | 实施方式 |
|---|---|
| Element Plus / Element UI | 映射已有 CSS 变量或主题文件；检查主按钮各状态及弹出到 body 的组件，不只改 primary 一个值。 |
| Ant Design / Arco | 使用当前版本支持的主题配置与组件级配置，区分链接和实心按钮配色；不替换路由与业务表单。 |
| Tailwind / shadcn | 将现有语义 Token 映射到本包变量；按项目当前版本配置，不为适配风格升级框架。 |
| 自研 CSS / CSS Modules | 导入变量并在公共组件层消费；保留模块封装，只添加明确的适配入口。 |
| Shadow DOM / 独立微前端 | 显式传入主题变量及状态；单独验证作用域和浮层，不假设变量跨边界自动继承。 |

根属性放在应用容器内时，Teleport/Portal 到 `body` 的弹窗可能拿不到 Token；应把变量作用域放到共同祖先，或在浮层宿主同步主题。不要用“全局所有元素覆盖”修补这个问题。

## 9. 不能因为换风格而改变的内容

- 登录、鉴权、权限、API、数据结构、业务校验和状态机。
- 已有路由、深链接、缓存/KeepAlive、工作区隔离与用户偏好。
- 成熟组件库、包管理器、应用框架和依赖版本，除非用户另外批准。
- 用户数据、模型凭证、业务文案含义和品牌资产。

UI 规范不是权限授权，也不能替代业务验收。旧主题回退开关应在迁移期保留，发布切换由项目流程决定。

## 10. 完成标准与维护

使用 Skill 入口直接链接的 `references/checklist.md` 逐项验收，报告实际改动、截图覆盖、命令结果、旧问题和未测试范围。代码通过不等于视觉通过，截图通过也不等于业务 E2E 通过。

`tokens.json` 是颜色/尺寸真值；修改后运行 `python3 scripts/generate_tokens.py`，再运行 `--check` 和 Skill 的 Token 回归检查。生成CSS只声明作用域变量，不覆盖业务组件。品牌替换不应偷偷改变规范主色；若要改为另一套品牌色，应作为新的明确变体记录，不覆盖兼容基线。不要把一次项目特例追加为全局规则；命名项目的兼容说明放在 [project-exceptions.md](project-exceptions.md)。

本规范由 `enterprise-ui-design` 的 Create、Upgrade 与 Audit 三种模式共同消费，无需访问来源项目源码。
