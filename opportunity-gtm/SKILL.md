# GTM 市场推广

先确定产品能解决什么、卖给谁、在哪推广。维护推广计划和公开研究，实际跟进形成有效线索后交给 [opportunity-orchestrator](../opportunity-orchestrator/SKILL.md)。同一计划可包含多个企业和商机；公开候选不能直接当成采购需求或销售阶段。

## 产品与目标客群

从客户输入提炼：主打产品/服务、应用场景、价值主张、可证明能力及案例；目标行业、企业类型/规模、地域、使用人/技术评估/采购角色和排除条件。推广周期、预算、团队及已有渠道有则记录；缺失不阻断研究，也不编造收益或费用。缺少产品或目标客群时先补最关键项，再推进不依赖它的工作；演示必须明确模拟。

输出产品—场景—角色—价值—证明—下一步矩阵和待验证假设。优先区分终端买家、系统集成伙伴与渠道伙伴，不把同行一律当客户。分群确有差别才拆计划，不按公司数量机械新建Skill。

## 有来源的目标发现

读[研究与话术](references/research-and-messaging.md)，调用当前可用搜索/网页阅读工具；安装了 agent-reach 时按其路由选择后端。`gtm-brief`只生成检索任务，不能把它的结果冒称已搜索。官网、主办方、协会/园区和官方名录优先，搜索摘要仅作发现入口。

1. 企业：确认主体、行业、基地/城市和产品应用；给出适配理由及未知需求。集团和子公司保留主体差异；同一企业不因多次搜索重复计数。
2. 区域：按客户集群、应用场景、团队可达性及渠道覆盖解释优先顺序；只有已登记点位/证据才绘图，不声称掌握全量市场或市场份额。
3. 展会/论坛：核验届次、日期、地点、主办方、观众/议程及参与条件。匹配制造/使用场景和目标角色，注明不适配部分；往届内容用于线索研究，不能挪作未来日程。日期未知保持未知，报名/费用另核。
4. 渠道：协会、产业园、集成商、代理商、行业媒体及线上社群，根据可核实业务和准入条件选择；记录合作方式与下一次验证，不编造私有名单或联系人。

每条来源保留URL、标题、发布者、访问日期、事实摘要；推断写在对象适配理由。来源过旧、冲突或访问失败时保留限制，活动临近使用前重新核验。分项优先级仅衡量研究适配，缺项显示未知与覆盖率，不当赢率。

## 推广策略、话术与跟进

按分群选择动作：定向拜访、样件评估、技术交流、展会预约、论坛议题、伙伴联营或行业内容。输出具体受众、渠道、消息、证据、行动号召、负责人、期限和需要核实的资源，预算未知则给比较与待询价，不报确定投入产出。

为本次渠道编写可直接修改的开场、价值、证明、CTA及异议回应；首次接触不假装了解客户内部痛点。产品资料没证明的精度、节省比例、交付期限和案例名称不能补造。保留“需要样本验证/需确认”的条件，避免重复轰炸或将未回复当拒绝。

话术是草稿。实际发送、报名、付款及外部联系遵循用户的具体授权，不从“制定推广计划”推导发送授权。

实际发生后追加跟进：企业、关联活动/渠道、日期、结果、证据、下一行动/负责人/期限、实际费用与币种。计划、已联系、已回应、会议、有效线索、不适配分开；未来记录不进入截至日的实际指标。历史不覆盖，错录须在后续记录解释并保留审计。

## 沙盘与商机关联

读[数据与运行契约](references/data-contract.md)，以下RUN为总控 `scripts/run.py`绝对路径；DB、输入输出放用户项目目录。

```bash
python3 "$RUN" gtm-brief --input /absolute/project/brief.json
python3 "$RUN" gtm-manage --input /absolute/project/gtm-change.json --db "$DB"
python3 "$RUN" gtm-query --campaign-id "$CAMPAIGN" --db "$DB"
python3 "$RUN" serve --db "$DB" --port 18771
```

打开本机 `/gtm`：产品/客群及检索任务 → 区域/类型筛选沙盘 → 对象和来源 → 话术 → 跟进 → 商机关联及分析。城市中心坐标必须标近似；未知坐标留在列表，不猜厂区位置。中国行政区划沙盘显示34个省级边界与名称，点击省份显示下辖城市/单位标注，再点击城市筛选推广对象；全国/省市选择框和名录提供等效入口。底图与475个下辖单位点位为本地可复用数据，保留来源和采集日；台湾市县点位在当前来源缺失，保持明确提示。地图高亮代表已登记对象覆盖，不是全量市场或市场份额。

有真实需求材料时使用现有 `analyze` 创建/更新明确采购项目；analyze命令返回保存收据与摘要，完整事实使用query/detail回读；回读企业主体与商机编号，凭本企业已发生的有效线索跟进显式 `link_opportunity`。同企业允许多个采购项目；链接不改变阶段、评分或签署事实。后续客户调研、方案评审、报价谈判和签署由原总控及子Skill处理，沙盘动态回读结果。模拟计划中的互动只能作为演练展示，公开企业研究本身不是其参与证明。

## 分析与完成

分析页随省市、区域、类型和关键词筛选同步展示企业、活动/渠道、跟进、关联商机与费用，并保留全国漏斗和全国指标对照。跟进、商机和费用按目标企业所在地归属，活动按举办地展示；跨区域活动不重复归入举办地费用，只看活动时企业指标为零。计划与未来跟进单列。

汇报截至日、研究覆盖/缺口、分区域/渠道/活动的企业去重漏斗、跟进结果及下一行动。成本按币种分组，缺失不等于零；没有可靠收入/成本和归因窗口时不算ROI。活动来源是记录的关联，不证明因果效果；签约金额只来自有效签署记录，不能当回款或收入。历史截至日约束推广记录，关联商机状态为当前回读，不能冒称还原历史商机快照。

回读当前计划revision、来源、跟进、关联和实际页面，分别报告研究、草稿、模拟验证、实际推广和签单的证据。首次做少量高质量企业、一个渠道动作和一个有效线索交接，验证主线后再扩大覆盖。
