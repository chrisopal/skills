# 售前、投标与宿主集成

## 售前

在当前宿主技能目录查找 presales-orchestrator，按其实际 SKILL.md 执行。仓库源为 presales-solution-skills/skills/presales-orchestrator。商机总控交付：opportunity_id、需求及证据、受众/目的、范围、当前方案版本和允许动作。

售前负责混合材料→需求→澄清→脑图→资料匹配→方案→逐页内容→PPT→真实文件审核。商机子 Skill 不复制这些工具。返回成果 ID、版本、hash、原始证据、审核结论、客户反馈、条件和未解决项；登记 solution 产物及关联行动。

PPT 生成、内部审核、客户认可和正式外发分别记录。方案做好不自动表示方案获得客户认可，也不自动推进正式商机阶段。

能力不可用时整理 handoff：商机及版本、任务/授权范围、输入证据、要求输出、完成条件、尚缺信息。保留 blocked 的具体原因，不虚报已生成方案。

## 招投标

只有采购路径确为招投标时调用可用的 bid-orchestrator。输入招标原件/补遗、响应范围、企业真实材料、截止时间、责任人及授权；取回实际响应版本和审核记录。资格、评分、否决条件只在适用路径检查，不能把完整投标门槛加到普通直销商机。

报价/投标登记只证明对应文件与提交记录。中标作为里程碑记录，不代替合同签单。新补遗或报价范围变化后重新检查受影响的方案、报价与谈判事项。

## 宿主与存储

默认共享运行层在本地 SQLite 保存同一商机。合同和附件仅在用户授权项目目录读取/归档，不自动上传。actor 是业务记录，不是身份认证；多用户权限、审批系统、电子签署和外部 CRM 同步由宿主提供。

接入 CRM 时指定唯一权威库和同步方向；不要让 SQLite 与 CRM 各自推进正式阶段。当前 Feishu/CRM/Postgres adapter 是扩展入口，本套件不宣称已实现外部连接。

HTML/Markdown 是派生视图。静态视图支持真实链接与原生展开，写操作通过 CLI/宿主执行；无操作连接时不能渲染假的新增、编辑、签署按钮。

## 已实现的本地桥接

共享 CLI 已提供 `presales-export`/`presales-receive`，用实际售前 runtime API 初始化新项目、保存白名单交接和回收当前审核过的 DELIVERY；步骤与限制见[操作指南](workbench-presales.md)。PPT继续由已有制作 Skill 生成，商机套件没有第二个 PPT 渲染器。已实现本机 `serve` 表单；静态报告仍只读，跨用户认证、真实审批、客户发送和电子签署仍由宿主负责。
