# 商机推进与跟进

读取兄弟 [opportunity-orchestrator 的共享契约](../opportunity-orchestrator/references/lifecycle-contract.md)，回读同一商机当前版本、客户事实、行动和证据。输入为商机 ID、当前跟进记录、客户反馈、责任人与时间约束。

## 处理

1. 区分业务需求负责人、技术评估者、采购、预算审批者和最终决策者；只登记材料中出现的真实人员与职责。不能把职位直接等同实际决策权。
2. 识别当前阶段阻塞、客户强制事件、已知竞争者和我方证据缺口。竞争判断标注来源及推断程度，不虚构客户偏好和竞争报价。
3. 将策略转成可执行行动：title、owner、due_date、预期结果及要解除的阻塞。未知负责人和期限列为待补充，不编造承诺。
4. 执行后记录真实结果、客户反馈与证据；只有已完成的行动才提交 complete_action。发出邀请不等于交流完成，发出方案不等于客户认可。
5. 新反馈否定原事实时增量分析并登记新的事实版本；保留旧证据和差异，重新评估相关阶段条件。

## 输出与保存

输出推进策略、决策链差异、明确行动、未解决事项和证据引用。通过 manage 的 add_action / complete_action / confirm_fact 保存，随后读回 lifecycle。只要产生行动，就明确其负责人及期限；缺少业务信息时交付候选行动和待补充项。

完成条件是推进计划与事实一致、行动能被执行、已执行结果已回读；建议列表生成不代表行动完成。用户已授权的准备工作继续执行；客户沟通和外发按本次具体授权办理。

## 竞争版本

竞争线索使用共享 `record_competitor` 操作：稳定 `competitor_id`、定位、优势、弱点、应对、来源状态和证据；更新同一 ID 保留版本历史。价格只作线索，保留币种与 `reported` 状态，先核对范围及税费。评分变化需另行绑定依据执行分析，竞争台账更新不会自动提高或降低评分。见[操作指南](../opportunity-orchestrator/references/workbench-presales.md)。
