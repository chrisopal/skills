# 00｜总控编排

## 目标

把 PPT 优化组织成可追踪、可授权、可回滚的工作流。总控 Agent 不直接“凭感觉改稿”，而是调度定位、叙事评审、视觉评审、设计系统、执行和校验六类能力。

## 必需输入

- 原始 `.pptx` 文件。
- 用户已知的场景、观众、目标和品牌要求；没有时允许推断。
- 当前优化等级，未指定时默认 L0 评审。

## 工作目录

建议每个项目使用独立目录：

```text
project/
  source/original.pptx
  review/
  approval/
  pilot/
  execute/
  validation/
  deliver/
```

## 编排步骤

1. 校验文件可打开，复制源文件并计算 SHA-256。
2. 运行 `create_review_bundle.py`。
3. 生成 `deck_context.json`。
4. 并行执行叙事评审和视觉评审，合并为 `review_report.json/.md`。
5. 生成建议版 `change_manifest.json`，等待明确授权。
6. 根据授权生成 `style_tokens.json` 和逐页 `refinement_plan.json`。
7. L2/L3 先做样板并记录确认结果。
8. 执行全局规范化，再做逐页精修。
9. 每轮修改均渲染、抽查；最终逐页检查。
10. 运行 `validate_pptx.py`，处理所有 P0 和未接受的 P1。
11. 输出优化版、报告、变更记录和前后对比。

## 总控决策表

| 条件 | 动作 |
|---|---|
| 用户只要评审 | 停止于 REVIEWED，输出报告 |
| 用户授权 L1 | 可跳过样板，但必须保存源文件和执行日志 |
| 用户授权 L2/L3 | 必须制作样板 |
| 内容授权不明确 | 只做视觉建议，不改文字 |
| 配图授权不明确 | 只做裁切/对齐建议，不替换 |
| 复杂 SmartArt/嵌入对象 | 标记人工复核，采用保守策略 |
| 渲染失败 | 不得声称完成视觉审计或最终验收 |

## 质量门禁

- `REVIEWED`：定位、叙事、视觉三类结果完整。
- `APPROVED`：授权文件合法且无互相矛盾的规则。
- `PILOTED`：至少覆盖一种普通页和一种复杂页。
- `EXECUTED`：所有修改均有日志和页码。
- `VALIDATED`：P0 为 0；未接受的 P1 为 0；内容保护规则通过。

## 不允许的捷径

- 只基于文本解析，不看页面渲染图。
- 只基于缩略图，不读取文本和对象结构。
- 在没有风格系统时逐页随意调整。
- 用图片覆盖原页面来“保证效果”。
- 为了统一颜色而破坏警告、状态、流程或数据语义。
