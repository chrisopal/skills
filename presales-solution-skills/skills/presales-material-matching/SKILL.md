# 售前材料与能力匹配

先读[成果契约](../presales-orchestrator/references/artifact-contract.md)。输入为需求/页面任务以及用户已提供或授权读取的材料库。

## 执行

1. 先核对主体、产品版本、发布日期、授权用途和适用条件，再看内容相似度。公司包、产品包、行业包和项目专用包按需组合。
2. 每项MAT给source_id/locator/evidence_ids、owner/product/version、capability_class、conditions/use_scope、match_status/reason及requirement_ids。
3. 能力区分standard/configuration/custom/third-party/roadmap/unsupported/unknown；路线图不能写成本期交付。已有截图不自动证明当前版本或本客户已可用。
4. 对关键结论返回最小可用摘录及真实素材位置；缺材料列明需核验内容。跨客户案例没有使用范围依据时仅保留内部候选。
5. 登记materials，inputs绑定实际使用来源和需求。页面精确选材时复核版本及限定，不凭旧匹配结果永久复用。

## 完成与异常

每项用于方案的能力有依据和适用边界，候选/核实适用/不可用分开。矛盾材料交澄清，不能按最新上传直接覆盖。模板只提供视觉身份，不是公司资质、客户事实或产品能力证据。
