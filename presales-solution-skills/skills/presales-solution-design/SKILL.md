# 售前方案设计

先读[成果契约](../presales-orchestrator/references/artifact-contract.md)。输入为需求、脑图、澄清、适用材料与约束。

## 执行

1. 按重点REQ建立SOL对象，明确response_mechanism、material_ids/evidence_ids、prerequisites、scope_in/scope_out、validation_method与unknowns。提到需求关键词不等于给出响应机制。
2. 解释业务如何流转、谁操作、数据从哪里来、产品做什么、人做什么；复杂项目才增加集成、数据、安全或部署专项，不固定堆叠技术章节。
3. 把标准/配置/定制/第三方依赖/暂不支持分开；未知接口画候选虚线及条件，不能画成已打通的实线。核对外部系统责任与权限前提。
4. 对可选路径说明取舍和何种新增证据会改变选择；给实施阶段、客户配合及每阶段可观察结果，不无依据填工期或资源数。
5. 价值说明对应客户目标。无基线先定义采集与比较方法；有估算则保留数据来源、公式、假设及敏感条件。
6. 登记solution，inputs绑定所用需求、脑图、澄清、材料。形成需求响应视图，逐项标满足/部分/未知/不适用及理由。

## 完成与异常

核心需求有具体机制与可核验方式，跨页共用的版本/范围/术语有单一来源。关键能力无证据转选材或澄清；不靠文案补足事实。需要正式咨询诊断或实施设计时指出新增范围并交既有能力，不能把当前售前草案称为实施承诺。
