# 项目收尾与质保

先读[共享产物契约](../delivery-orchestrator/references/artifact-contract.md)和[收尾复用说明](../delivery-orchestrator/references/reuse-closure.md)。输入是有效的合同义务、验收/确认、成本与付款条件、风险问题、培训运维移交、访问与资产记录、客户模板以及项目配置；输出收尾报告、质保台账、遗留义务、资产交还记录、复盘和归档索引。

## 四个独立结果

严格区分四个结果：行政结项说明项目管理资料、成本和内部工作可以收束；质保移交说明尚未结束的质保义务已经交给明确主责人、接收人和支持路径；质保结束说明合同或有效变更约定的质保期及其开放事项已经有实际关闭依据。全部义务解除还要求移交遗留义务实际关闭、资源交还与归档期限明确；不适用质保也须有合同/有效变更依据。验收、行政结项、质保移交、质保结束和全部义务解除分别记录，不能用签署验收或关闭文件替代其他门。

每条剩余义务使用稳定 `id`，绑定合同/变更来源、范围、owner、due_date、当前状态、移交对象、处理路径和 evidence_refs。没有主责人、接收人、期限或可回读证据的事项保持 `open` 并说明阻塞原因；整个产物可标 `status=blocked`。不得把口头承诺、空白模板、演练签收或“已通知”写成完成。质保缺陷保留与验收版本、问题、变更和修复/复测证据的关联。被拒绝、带未决条件或未就绪的确认不能证明移交完成。

## 结算、资产与访问

结算沿用成本与付款主账，区分已发生、承诺、剩余预计、结算单、开票、付款条件和实际收款。固定总价、按工时和混合计费按[项目配置](../delivery-orchestrator/assets/templates/delivery-profile.md)记录费率、币种、封顶和验收/付款差异；估计成本或预计收入不能冒充财务事实、确认收入或现金到账。外包、采购、差旅和内部工时按稳定事项 ID 去重，暂估转结算修订原事项。

缺少财务主账、结算凭据或仍有已知差异时，保持 `settlement.state=open`。工具核验登记结构与引用，不能代替财务对账；不能仅为通过门槛声明 reconciled。

资产交还逐项引用实际文件、代码/制品、环境、账号、许可证、设备和受控访问记录，记录接收人、版本、范围、撤销或归还动作及收据。资源行跨修订保留，实际释放时更新为 released 并附证据；不得删除 retained 行来解除义务。密码、token、私钥和个人敏感信息只引用受控位置，不复制到收尾材料。客户模板优先保留原格式；当前映射工具绑定实际 JSON 字段规格，仅准备本地 JSON 草稿，客户专用 Word 版式仍需另行排版并回读。

## 复盘、归档与完成

复盘事实来自已完成的计划、工时、成本、风险、变更、质量、验收和质保记录，区分事实、判断和建议；归档索引只登记真实存在且可打开的文件/引用、版本、哈希、可见范围、保留期限和替代关系。组合项目审查与系统交换属于总控支持视图，不复制项目主账；多项目只汇总当前 UTC 提取日的当前快照，分币种报告；显式提供跨项目人员身份和共享容量，不能以同名人员或项目容量简单相加代替。任务、代码、财务和文档交换须把本地候选、外部执行和确认收据分开登记；收据绑定 operation_id、external_id 与 payload_sha256。工具不发送网络请求、不自动回写业务主账，模拟来源不能证明真实执行。

真实收尾的 as_of 不得晚于当前 UTC 日期，不能以未来截止日宣称质保提前结束。已关闭义务/质保事项重新打开须保留稳定 ID、correction_reason 和证据；历史记录不得删除。

发送前核对目标系统和任务的实际接收范围；`audience=internal` 只是本地映射配置，不证明外部权限。普通飞书任务只同步必要履约状态，不附内部费率、财务明细或整个项目目录。

完成前回读所有收尾门、剩余义务、结算差异、资产/访问收据、复盘结论和归档文件；任何未读材料、权限不足、版本漂移或第三方未确认都进入报告待决清单及对应开放记录。Envelope 的 `status=ready` 只表示底稿可用；`snapshot.gates[ID].ready` 要求全部解除条件通过。两者都不认证客户身份、证据真实性或财务执行。

## 模板

使用 `../delivery-orchestrator/assets/templates/closure-warranty.md`、`closure-obligations.csv`、`warranty-items.csv`、`archive-index.csv`；客户模板映射、项目配置、多项目审查和系统交换使用同目录中的 `customer-template-mapping.md`、`delivery-profile.md`、`portfolio-review.md`、`system-exchange.md` 及其 CSV 台账。每次任务仍需绑定项目、目标、输入版本、执行范围、输出位置、完成证据、未决问题和下游影响；本 Skill 不代替验收、财务审批或外部系统实际执行。
