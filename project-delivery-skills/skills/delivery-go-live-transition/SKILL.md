# 上线与切换

先读[共享产物契约](../delivery-orchestrator/references/artifact-contract.md)与[软件实施契约](../delivery-orchestrator/references/software-delivery.md)。输入是有效测试/UAT 结论、候选发布版本、环境与接口/迁移设计、培训与运维准备、上线窗口、授权和回滚前提；输出上线方案、准入检查、执行记录、回滚记录、观察期结果和移交缺口。

## 处理

上线前按 `environment`、`build_ref` 和需求范围检查测试/UAT、设计/变更版本、备份可恢复、迁移核对、账号/权限、监测告警、值守、客户通知、依赖就绪、窗口和授权。每项准入写 criterion、owner、evidence_ref、状态和未决项；缺证据保持 blocked/conditional，不用“已准备”代替确认。执行记录区分计划步骤、实际时间、执行人、命令/工具结果摘要、业务核对和异常；不把部署流水线绿灯、文件存在或模拟切换当成生产成功。

回滚方案明确触发条件、停止点、备份/恢复引用、数据补偿、责任人、通知和成功判定，并在实际执行后记录是否触发、结果、遗留风险和观察期。计划、授权、实际切换、业务确认、观察期和移交分别登记。没有可用自动检查时由 Agent 逐项复核版本、证据、授权和结果，列出 `unchecked`，不隐含执行生产动作。

## 主责与完成

本 Skill 维护发布准入、切换和回滚记录；测试维护质量结论，接口/迁移维护数据证据，培训移交维护接收资产，里程碑 Skill 维护客户确认。完成要求准入范围明确、候选 build 精确、授权和窗口可回读、切换结果与业务核对记录完整、失败路径已处置或接受、观察期和遗留项有责任人。`ready` 不等于上线授权、生产切换成功、稳定运行或验收通过。

任何生产写入、切换、回滚、通知或外部共享都必须基于已有任务授权；本 Skill 不擅自执行未授权动作。发布版本或前提变化时保留原记录，生成候选准备/执行版本并由总控更新有效引用。

## 模板

使用 `../delivery-orchestrator/assets/templates/go-live-transition.md` 和 `release-readiness.csv`。CSV 初始只有机器表头和空白行；实际执行证据必须在项目中按精确版本保存和回读。
