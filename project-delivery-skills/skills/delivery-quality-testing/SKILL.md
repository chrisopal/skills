# 测试、缺陷与客户验证

先读[共享产物契约](../delivery-orchestrator/references/artifact-contract.md)与[软件实施契约](../delivery-orchestrator/references/software-delivery.md)。输入是需求/设计/工作包版本、测试范围与风险、测试数据、环境、候选构建、质量标准和客户验证安排；输出测试计划/用例、实际执行记录、缺陷台账、复测证据、UAT 包和质量结论。

## 处理

每个测试用例绑定 `requirement_ids`、设计/工作包引用、环境、`build_ref`、前置条件、步骤、预期和实际结果、执行人/时间、证据和结果。按适用范围覆盖功能、集成、权限/状态、字段校验、迁移一致性、性能/安全或回归；未执行、阻塞、通过、失败和不适用必须分开，不用报告文字覆盖实际结果。缺陷记录稳定 ID、严重度、现象、影响、复现条件、责任人、修复版本、复测结果和证据；关闭必须有复测，暂缓或接受残留必须有实际接受人、范围、补救责任和依据。

UAT 记录客户角色、确认范围、测试版本、场景、实际结果、问题、决定与证据。内部测试通过、页面存在、自动检查通过或模拟确认不等于客户接受；演练数据和模拟 actor 必须标明 `origin=simulation` 或等价边界，不能作为真实项目的验收门槛。缺少自动执行能力时由 Agent 逐项核验需求映射、环境/build、证据完整性和未决缺陷，明确 `unchecked`，不伪造绿色结果。

## 主责与完成

本 Skill 维护质量、测试、缺陷与 UAT 主账；需求/设计/工作包维护输入对象，上线 Skill 消费可发布结论，验收 Skill 维护确认。完成要求适用测试范围和标准明确，实际结果可回读，阻塞/严重缺陷有处置或授权，复测版本一致，UAT 决策绑定精确范围和证据。`ready` 不等于通过、上线授权、客户签署或缺陷全部关闭。

测试数据、环境、构建或客户代表变更时生成候选修订并影响相关结论；旧版本结果保留。执行、修复、关闭或对外发送结果需有已有任务授权，本 Skill 不代替客户确认或生产质量审批。

## 模板

使用 `../delivery-orchestrator/assets/templates/quality-testing.md` 和 `test-cases-defects-uat.csv`。CSV 行必须对应真实执行记录或明确的待执行项，空白模板本身不构成测试证据。
