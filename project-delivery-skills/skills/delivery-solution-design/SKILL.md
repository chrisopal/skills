# 实施方案与设计决策

先读[共享产物契约](../delivery-orchestrator/references/artifact-contract.md)与[软件实施契约](../delivery-orchestrator/references/software-delivery.md)。输入是有效的需求/蓝图版本、合同边界、环境约束、接口与数据清单、非功能目标和客户配合条件；输出是按模块或批次可实施、可验证的方案设计，以及组件和决策记录。

## 处理

先列 `requirement_ids`、适用模块/批次、`input_versions` 和来源证据，再描述业务能力到系统组件、部署单元、数据边界、外部依赖、身份与权限、日志监测、备份恢复、可用性、性能和安全控制的对应关系。每个组件要有责任边界、交互、依赖、环境、版本前提和验证方法；性能或安全数值若没有来源，写成待确认目标并保留测量条件，不按行业惯例补造承诺。

对关键取舍登记 decision、候选方案、理由、约束、影响、受影响需求和验证证据。区分设计建议、内部评审、客户确认、已授权先行和可交付版本；一份架构图或原型只说明表达结果，不能证明系统已经部署或可运行。任何未实现的自动检查由 Agent 按字段和证据逐项检查，并将缺口登记为 `open_items` 或 `unchecked`。

## 主责与完成

本 Skill 维护实施方案、组件与设计决策；蓝图、UI/字段、接口/迁移、工作包和测试分别维护自己的对象并通过稳定 ID 关联。完成要求每个设计组件可追溯到需求，非功能指标有验证条件，外部依赖有责任人和状态，决策有来源和影响，批次边界与版本/hash 可回读。缺少环境、容量、身份或授权时保持 blocked/待决；`ready` 不等于客户批准、开发授权、部署成功或验收通过。

所有创建、修改、先行实施或对外共享动作都必须沿用已有任务授权；本 Skill 不自行调用未声明的工程或生产动作。版本变化先形成候选设计，待影响对象完成复核并由总控更新有效版本集合后才可作为新的输入。

## 模板

使用 `../delivery-orchestrator/assets/templates/solution-design.md` 和 `solution-decisions.csv`。CSV 保持机器字段名、元数据列和一行空白占位；模板占位内容不是项目事实。

需要形成可评审文件时，使用总控的 `scripts/export_core_documents.py` 导出实施方案。导出结果保留需求、蓝图和设计输入的精确 revision/hash；`ready` 或本地验证不改写为生产部署或客户确认。
