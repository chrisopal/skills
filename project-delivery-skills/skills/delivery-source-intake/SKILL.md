# 来源材料接收

先读[共享产物契约](../delivery-orchestrator/references/artifact-contract.md)。输入是项目目录和待接收原件；输出为 `source` 产物、`evidence` 底稿、定位信息和未读范围。来源登记只证明快照与哈希，不证明内容已经理解。

## 处理

`source` 命令只保存原件快照和哈希，不自动解析或转录。逐个保存原件，不覆盖同名文件；记录原始名称、路径、大小、时间、`sha256`、来源人/渠道和保密范围。由 Agent 或现有解析能力读取 PDF/DOCX/XLSX/图片/邮件并记录页码、表名、行列或附件；录音只有拿到实际转录才建立语义记录，否则登记“待转录”，不能从文件名猜会议内容。建立 `evidence` 条目，保留原文、定位、读取状态和可定位时间段。

## 覆盖与版本

输出 `source` 快照与（在实际读取后）`evidence` 底稿；必须列出已读取页/工作表/附件/时间段、解析失败、扫描页 OCR 状态和未读范围。下游只引用精确 `artifact_id`、`revision`、`sha256` 和 locator；新源版本不会自动替换既有有效产物，引用漂移需触发复核。

## 完成与未知

当原件快照可回读、覆盖记录完整且每个缺口有责任人/下一步时完成。损坏、权限不足、扫描不可读、说话人不明或缺转录均保留未知并阻塞依赖它的语义结论。`ready` 不等于审核/确认；本 Skill 不解释合同、不生成客户确认。

## 模板与主责

使用 `../delivery-orchestrator/assets/templates/template-field-guide.md` 了解字段口径。来源主账由本 Skill 维护，其他 Skill 只能提交带来源版本的候选证据。
