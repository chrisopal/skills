# 培训与运维移交

先读[共享产物契约](../delivery-orchestrator/references/artifact-contract.md)与[软件实施契约](../delivery-orchestrator/references/software-delivery.md)。输入是有效方案/UI/接口/上线版本、受众与职责、运行手册要求、培训计划、资产清单、访问边界、支持流程和客户确认安排；输出培训内容与记录、能力检查、用户/运维资产清单、接收记录和开放事项。

## 处理

按 audience/role 说明目标能力、前置知识、培训主题、演示/练习、异常处理、competency_check、讲师、日期、出席证据和未参加人员补训。出席、材料发送或演示完成不等于掌握；能力结论需有练习/问答/操作观察或客户约定的其他证据，并注明适用版本和范围。用户手册、管理员手册、运维手册、架构/接口说明、监测告警、备份恢复、常见故障、支持升级和版本说明都要记录精确资产引用、可见范围和维护责任。

移交逐项记录 asset_id/type/ref、接收人和角色、范围、访问状态、接收证据、有效版本、保密边界、续期/维护责任和 open_items。密码、token、私钥等凭据不得写入材料；只引用受控的访问移交记录。原型、模拟演练和模拟签收只能证明演练或内容准备，不等于真实培训掌握、运维接管、生产访问或客户验收。缺少自动检查时由 Agent 检查受众覆盖、资产版本、接收范围和开放事项，并保留 `unchecked`。

## 主责与完成

本 Skill 维护培训、能力验证与运维移交记录；设计/上线/测试维护输入版本，验收 Skill 维护客户确认，质保/收尾工作在后续技能范围内。完成要求每类受众有能力目标和证据，资产已按版本读回，接收人/角色和范围清楚，访问不泄露凭据，遗留事项有 owner/due/处理路径。`ready` 不等于用户掌握、运维接收、生产授权或质保结束。

编写、发布、培训、移交或授予访问的动作都需要已有任务授权；本 Skill 不自行发送外部材料或开通生产权限。版本变更先修订候选资产/培训记录，回读受影响工作包、测试和上线引用，再由总控激活。

## 模板

使用 `../delivery-orchestrator/assets/templates/training-handover.md` 和 `training-handover.csv`。CSV 为机器可读空白台账，实际接收证据和访问记录必须留在受控项目位置。
