# 页面字段、权限与状态设计

先读[共享产物契约](../delivery-orchestrator/references/artifact-contract.md)与[软件实施契约](../delivery-orchestrator/references/software-delivery.md)。输入是有效需求、流程/蓝图、角色、数据字典、接口约束、方案版本和批次范围；输出页面与交互规格、字段字典、权限/状态矩阵和可测试的异常场景。

## 处理

每个页面、操作和状态绑定 `requirement_ids` 与流程 ID，说明入口/出口、角色、可见按钮、前置条件、成功结果、失败恢复、提示文案、审计事件和待确认项。每个字段至少定义业务含义、类型、长度/精度/单位、必填、默认、枚举、唯一性、校验、显隐规则、读写权限、数据来源、计算规则、接口映射、敏感性及异常展示。权限必须回答“谁在什么状态能做什么”，状态转换要写进入/退出条件、拒绝与恢复路径。

原型、截图和效果图只作为设计表达或评审证据；它们不是 working software、接口连通、权限生效或客户确认的证据。原型链接和版本需要可回读，实际实现、测试和客户验证由对应版本记录。若缺少角色授权、规则来源或字段口径，保留未知并由 Agent 检查覆盖，不能用默认权限或通用字段替代。

需要可视化界面或原型时，先读取并使用 `enterprise-ui-design` Skill，统一企业蓝色、排版、导航、表格和状态表达；遵守客户已有设计约束并记录映射。技能缺失时明确报告依赖，不能静默换风格。

## 主责与完成

本 Skill 维护页面、字段、权限和状态设计对象；需求、蓝图、方案、接口、工作包和测试各自维护主账，并通过 ID 引用。完成要求每个关键需求有页面/字段/权限/状态落点，每个状态动作有角色和结果，每个字段约束可实施，异常与验收场景可复现，确认范围精确到模块/版本/hash。效果图可读、内部评审通过、客户审阅、有条件确认和全部确认分别登记；`ready` 不表示功能已完成。

涉及创建原型、修改设计、先行开发或对外提供页面材料时，只在已有任务授权和适用的 UI 工具能力范围内执行。候选修订不得覆盖有效设计；变更完成后由总控复核引用并激活新版本。
