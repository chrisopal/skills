# 实施工作包

先读[共享产物契约](../delivery-orchestrator/references/artifact-contract.md)与[软件实施契约](../delivery-orchestrator/references/software-delivery.md)。输入是有效需求、方案/UI/接口设计、计划基线、资源与环境条件、依赖和迭代范围；输出工作包任务卡、版本/构建引用、完成记录、交付证据及未完成项。

## 处理

每个工作包使用稳定 `plan_work_package_id`，记录范围、`requirement_ids`、`design_refs`、责任人与参与者、依赖、环境、计划/实际日期、剩余工作、风险/变更引用和完成规则。完成规则要能被证据验证，例如构建产物、代码/配置引用、接口联调记录、页面字段实现、测试结果或交付物读回；“开发中”“合并代码”“负责人说完成 90%”都不能单独关闭业务工作包。`build_ref` 与 `evidence_refs` 必须指向精确版本/环境，外部工程系统只作为执行证据来源，冲突要登记核对。

工作包应先核对设计版本、依赖、授权范围和预计返工；设计缺口、第三方未就绪、构建不可读或证据缺失时保持 blocked，并拆出处理动作。区分工程完成、内部评审、测试可用、客户验证和里程碑确认；模拟构建、演练交付或模拟确认只能作为标注清楚的证据，不能升级为真实完成。没有对应运行能力时，由 Agent 检查引用、字段、状态和证据一致性，并列出未检查范围。

## 主责与完成

本 Skill 维护工作包与交付记录；计划 Skill 维护总计划，设计 Skill 维护设计主账，测试 Skill 维护质量/缺陷，验收 Skill 维护客户确认。完成要求范围和输入版本明确、依赖已满足或有授权、完成规则已满足、构建/交付证据已读回、剩余项有责任人与期限。`ready` 不等于代码可用、部署成功、测试通过或验收通过。

创建/派发/修改工作包及触发工程动作必须有已有任务授权；本 Skill 不声称自动完成代码、配置或第三方交付。版本或需求变化先形成候选工作包修订，旧有效引用保留，影响由总控统一回读后生效。

## 模板

使用 `../delivery-orchestrator/assets/templates/work-package.md` 和 `work-packages.csv`。CSV 只提供元数据和空白行，实施记录需绑定真实来源和版本。
