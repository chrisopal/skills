# Intake

Use intake to turn a vague request into a bounded delivery track.

## Capture

- Product or system name
- Business goal and failure cost
- Primary users and secondary stakeholders
- Current process or current system
- In scope and out of scope
- Deadline, release target, and constraints
- Required output: research only, design only, prototype, development, or full delivery

## Default Assumptions

When answers are missing, proceed with explicit assumptions if the choice is reversible. Mark them as `Assumption` and keep them in the open-question list.

Ask before proceeding only when the missing information changes architecture, data ownership, compliance posture, payment/legal exposure, or destructive production behavior.

## Output Shape

Use this structure in `00-intake.md`:

- Summary
- Goal
- Users
- Current state
- Scope
- Constraints
- Deliverables
- Assumptions
- Open questions
