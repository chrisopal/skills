# 业务契约驱动的 UI 验收

每轮先确定四类来源：业务需求/领域规则、API/Schema、权限与状态机、UI 设计规范。记录文件路径和稳定规则 ID/operationId/JSON Pointer；外部规范记录版本和章节。后端当前行为只是观察结果，不自动成为正确答案。来源缺失、冲突、服务端未实现时登记缺口并标 BLOCKED，不由模型补造长度、费率、权限、阈值或状态转换。

## 四维检查

每个控件实例的 checks 必须映射到 business、interaction、display、layout 四个维度，各维度使用独立检查 ID，可以引用同一操作证据。无关维度在独立范围清单保留明确的 N/A 检查及理由，不允许直接省略。页面整体以 kind=page 的控件实例验收，至少有一条适用 layout 检查，以覆盖控件之间的对齐与布局。

| 维度 | 从契约提取 | 实际检查 |
|---|---|---|
| business | 字段类型、必填、nullable、枚举、范围、精度、长度单位、跨字段关系、权限、状态机 | 合法值、非法类型、上下界及边界外、必填/空值、后端拒绝、角色和状态差异；写入后独立回读 |
| interaction | 事件、前置条件、联动、加载、幂等、取消、返回与持久化规则 | 点击前后状态、重复点击、失焦、重开、切换选择、取消再开、保存失败重试、刷新；每个不同业务分支各有 check ID |
| display | 原始值与显示值映射、数值/文本、单位、日期时区、脱敏、条件显隐、空状态 | 0 与空不混淆；数值精度/千分位不改变提交值；编号前导零保留；长文本截断/换行/完整内容可达；错误提示和状态文字正确 |
| layout | 宽度/最小宽度、对齐基准、间距、字号/字重/行高、主题、断点、溢出策略 | 同组标签/输入框/按钮对齐，表头与内容及数字列对齐；窄屏、长中文/英文、错误出现后不遮挡/重叠/丢失；键盘焦点及弹层可达 |

布局使用真实浏览器 bounding box、computed style、可见区域和截图综合断言。允许误差来自设计 token/渲染环境并写明，不硬编码所有控件统一宽度。截图相似度不能单独证明功能正确。文本长度按契约区分字节、字符或字素；Schema maxLength 与产品文字计数不一致时澄清，不猜测。

## 分支与范围

建立“角色 × 业务状态 × 数据条件 × 操作”的适用分支清单。优先业务关键、权限、持久化和已知缺陷路径，其他组合按等价类及边界选择并解释依据，不机械枚举所有笛卡尔积。不同动作结果必须分开记录，不能一个 click PASS 覆盖全部按钮状态。

共享组件变化：组件契约检查 + 每个受影响页面实例的绑定/权限/局部样式检查；共享证据可引用，但不能删除实例集成检查。页面清单由路由、源代码与实际界面交叉核对，不能只让执行脚本自报范围。需要缩减已批准范围时记录原因和任务，不删失败项提高通过率。

## 以工时字段为例

这里只说明如何选用例，不规定产品工时上下限：
- 从字段 Schema 和领域规则取得单位、小数位、上下界、空值政策，生成上下界内/等于/外的用例。
- 验证文本误输、粘贴、步进、清空、0、小数的失焦与回显；显示舍入不得静默改变保存值。
- 从实际状态机取得草稿/提交/审批后的编辑能力；无权时既不能操作，也不能产生成功写入。
- 验证字段、单位、错误提示和相邻输入框对齐，长错误提示及窄屏不遮挡保存。
- 实际提交并核对请求字段、服务端结果、独立 GET 和刷新后的显示。

每条结果携带 preconditions、contractRefs、步骤、预期、实际及证据。发现规则不一致时分别记录前端/后端/规范的差异，不能任意选一方作为标准。
