# 组件留白与间距均衡

适用于所有页面整体、子页面、Tab、列表工具栏、表单、分组、弹窗、抽屉及动态反馈。目标是让相邻独立组件有可辨认的空隙，同层同类关系保持均衡；不是把所有距离设成相等，也不是在每个 DOM 节点之间插入空白。

## 先确认空间责任与依据

- 使用宿主项目的 Blueprint、语义 Token 与组件契约；存在 enterprise-ui-design 时沿用其空间规范，不另造统一像素阈值。
- 兄弟组件之间由父布局 gap 或已有 Stack/Inline 负责；边框、分隔线到内容由所属容器 padding 负责。分别测量，不能以按钮组 gap 通过代替工具栏上下留白。
- 相关内容组内距离应小于或等于组间距离，一级区块应有可辨认分隔。同层同类使用同一间距档位；均衡不是机械左右对称，也不要求文字基线的光学校准完全相同。
- 连续表格单元格、分段控件、相邻 Tab 边框、编辑器画布等按设计可以拼接。记录组件、适用状态、契约与内部可读留白；不能把零间距一概免责，也不能强制拆开本应连续的组件。
- 没有明确 Token 时，仍可确认贴边、粘连、遮挡等可观察缺陷；对具体目标尺寸的规范符合性标 BLOCKED，建议尺寸明确标成建议。

## 必须逐上下文分配的检查

| ID | 实际检查与判定 |
|---|---|
| SPACE-01 | 独立组件和容器边缘之间有留白。测标题→工具栏、工具栏按钮→上下分隔线、工具栏→表格、表格→分页、表单字段→操作、弹窗标题→正文→页脚。非设计拼接的可见边缘相贴或间距不足以区分组件即 FAIL；无重叠不等于通过。 |
| SPACE-02 | 同层同类间距均衡。记录同组按钮的相邻距离、工具栏上下 inset、同类字段的横/纵 gap 及同族页面差异；对照 Token/组件约定解释差异，识别单侧 padding、默认 margin、空反馈节点造成的偏差。对称布局的两侧应一致，非对称布局按其契约核对，不用跨产品固定误差值。 |
| SPACE-03 | 组内、组间及区块间的节奏可辨。标题与所属内容保持关联，不因过大空白割裂；独立卡片/任务组不粘连，不因父 gap 与子 margin 叠加产生无意空洞。布局应同时满足可读密度和任务关系。 |
| SPACE-04 | 换行后仍有横向和纵向留白。桌面与390px、详情侧栏展开、长标签、多行筛选和错误出现时，实际测 row-gap 与 column-gap、首末行 inset；不能只测第一行或桌面。控件不得贴住相邻行或容器边界。 |
| SPACE-05 | 状态改变后留白仍成立。打开/关闭条件区域、切换 Tab、加载→有数据/空/错误、校验反馈出现/消失后，检查新增组件、空节点和隐藏内容是否压掉或重复占用间距。共享组件证据不能代替每页实例。 |
| SPACE-06 | 间距不损害可达性。实际键盘聚焦边缘控件并检查焦点环、粘性列、弹层及滚动裁切；不为增加空白把主要操作挤出容器或用缩小字号、隐藏功能补偿。 |
| SPACE-07 | 详情的标题/状态/字段组/叙述/局部错误/恢复分别有空间归属。量首末标签、值和动作到容器四边的距离、标签/值对齐及网格换行；长叙述整行仍对齐，无 dd 默认缩进、单侧 inset 或嵌套 padding 意外偏移。必须看有数据状态，非仅空表。 |
| SPACE-08 | 空态水平居中于所属内容区，纵向留白符合宿主 Empty/Result 或区块契约；量内容区/空态 bounding boxes 和上下左右 inset，明确排除标题/工具栏。桌面/390px 浅深、加载/空/失败和恢复后分别检查，无贴外框、全页错误居中、过大固定高度或按钮焦点裁切；无规格时缺陷与建议分开。 |

## 表格与 Tab 回归步骤

- **SPACE-10 表格内容组居中**：准备同一行内“多行文字＋展开/收起动作”、单行标识、状态标签及另一短行；普通数据表正文默认垂直居中，水平仍按文本/数值/状态列语义。读取行与各完整内容组的 bounding boxes（文字与动作分离时取两者联合框；不要测撑满高度的包装层）。记录 `deltaY = (group.top + group.bottom - row.top - row.bottom) / 2`，逐列比较绝对值与开测前记录的宿主容差；没有容差时仍记录偏差和截图，对精确数值符合性标 BLOCKED。检查富内容层是否顶部对齐、动作是否被排除，不能只断言 td 的 computed vertical-align。可编辑网格/打印等例外须有 Blueprint 的具体列、状态和理由，不泛化豁免普通表格。
- **SPACE-11 Tab 与区段留白**：记录 `firstControl.top - tabStrip.bottom`，Tab 底边取实际可见条带/分隔线，首控件取切换后第一个可见查询或操作控件，不能取空包装层。再量查询→工具栏/表格、工具栏上下 inset 及按钮内部 gap，分别对照语义 Token 和唯一责任方；内部按钮 gap 通过不能替代区段间距通过。列出父 gap、面板 padding、子 margin 的实际贡献，检查漏配和重复叠加。
- 两项均在桌面与390px、浅/深主题执行，并覆盖展开/收起、Tab 切换、查询隐藏/显示及筛选换行的适用状态。保留原失败与修复后同一数据的测量、截图和可复跑断言。共享修复按使用页面清单复测；不能用单行空表或 CSS 搜索代替混合内容实测。

## 证据与交付

每个页面必须有整体布局实例，并为可见相邻组件组记录适用 SPACE 检查、稳定定位、空间责任方、Token/规格引用、主题、视口、数据/交互状态、bounding boxes、computed padding/gap/margin 及实际截图。读取渲染几何，不能仅检索源码中存在 gap/padding。

截图必须实际查看；用几何定位问题，用截图判断组件关系。自动扫描、无溢出、可点击、对比度或构建通过都不能抵消已观察到的贴边/不均衡。截图裁剪无法提供视口或缩放信息时注明未知，不直接由图片像素推算 CSS 值。

整应用走查的分母来自独立路由及子上下文清单。共享工具栏缺陷可合并为一个根因，但报告须列出所有受影响页面实例；无法进入的页面和未触发状态保留 BLOCKED/NOT_RUN。不得仅检查示例截图所在页就宣布其他页面通过。

问题单须列页面/状态、实际距离和规范依据、影响、共享或局部修复位置及复测条件。修复须经用户授权；复测原失败页面、同组件全部使用页、相关换行/条件状态，保留原失败证据。
