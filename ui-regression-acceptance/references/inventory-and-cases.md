# 范围盘点与用例设计

## 从源码清单走到真实页面

1. 查路由注册、布局/菜单、页面组件、复用组件的页面绑定、权限和特性开关；记录文件与组件/字段位置。路由懒加载、动态注册、无菜单的详情/编辑入口、深链接、标签页和浮层都进入候选清单。源码只能说明候选范围。
2. 以实际角色/状态进入候选页面，用可访问树/DOM 对照控件；打开标签页、抽屉、弹窗和条件区域后再次盘点。运行时独有控件补查其渲染来源；源码候选不可达要保留并解释原因，不能当作不存在。保留盘点日志/截图到 `discovery.runtimeEvidence`，记录源码候选与运行差异的处理依据。
3. 页面身份是业务上下文，不只是 URL。`orders.list`、`orders.edit-dialog` 可以共用 URL，分别有页面 ID、入口、前置数据和整体布局实例。参数化详情路由按模板盘点，按实际影响绑定/权限/布局的数据等价类选择实例；不能把同 URL 的不同业务状态混成一次点击。
4. 范围清单与执行结果分开；完整结构见 [evidence.md](evidence.md)。`pages/controls` 的 `sourceRefs` 指向实际源码/规格位置；定位采用可访问名称或稳定业务标识，表格行限定具体记录 ID。重复行等价分组时在盘点证据中记录分组依据、代表数据及例外，不能把不同页面的组件实例合并。
5. 发现缺页、缺控件或契约缺失时，保留候选与未测项。未知控件无法完成盘点的页面设 `inventoryComplete=false`；已有预期检查记 BLOCKED。不要用空控件清单或一条通用 click 替代未完成的盘点。每页 `kind=page` 实例承担跨控件布局、焦点顺序等适用检查；静态页面同样测可读性和布局。

整应用可以分批执行；单批只能报告本批结论。最终汇总以整应用冻结清单为分母，核对所有批次版本、角色/状态/主题/视口和未测项。应用、契约或构建发生变化时，记录影响分析；未经复核的旧证据不计当前通过。

### 没有运行环境时的交付

交付 `inventory-plan.md` 和具体用例即可，执行标 NOT_RUN，结论 INCOMPLETE；不要伪填 URL、浏览器、版本或执行证据来消除门禁提示。计划至少列出下表；已知页面/控件/检查数量不包含尚未知的子范围，单独列出未知范围与解除阻断条件。

| 页面上下文 | 来源/入口 | 已知控件与检查 | 未知/不可达范围 | 状态与下一前提 |
|---|---|---|---|---|
| orders.edit-dialog | Orders.vue#dialog；行 Edit | 编号、数量、保存及各维度用例 | 运行时附加字段、实际定位 | NOT_RUN：需运行应用及角色数据 |
| admin.audit | routes.js#audit；admin+开关 | 页面整体候选 | Audit 组件未提供，子控件数量未知 | BLOCKED：需组件、开关与授权角色 |

如项目需要预建 JSON，页面保持 `inventoryComplete=false`、`discovery.reconciled=false`，未知值留空，结果保留 NOT_RUN/BLOCKED；在盘点日志中按页面列出未知子范围及原因。此时校验器返回 INCOMPLETE 和缺失运行信息是预期结果，不是产品缺陷。不得把“已知候选有结果”称为完整控件覆盖。

## 从控件类型转成具体断言

先判断业务语义：手机号、证件号、邮编、带前导零的编号通常是文本；输入框外观或 HTML `type` 不能决定类型是否合理。控件类型、可编辑性、选项来源、默认值和规则各自对照需求/API/状态机。来源冲突或缺少上下界时记录 BLOCKED 与 `missingContracts`，不要自行设计产品约束。

为每个字段建立“规则引用 → 适用条件 → 输入/步骤 → 预期 UI、请求和回读”的检查。以下按实际契约分配，不能让一条“边界通过”代替多个不同结果：

| 范围 | 用例选择 |
|---|---|
| 文本 | 必填空值、空白、null/缺省，长度 0/1、上限及上限外；中文/英文、粘贴、换行和去空格策略；长度单位按字符/字素/字节契约；编号前导零、特殊字符的存储与安全显示。 |
| 数字/金额 | 最小/最大值及邻近合法/非法值，0、负值、允许的小数位与多一位、步长、超大值；误输文本及产品支持的负号/指数/分隔符；输入、显示舍入、提交和回读一致。不要把组件自动裁剪非法值当成业务规则正确。 |
| 日期/区间 | 最早/最晚及边界外、相等/逆序、跨月/闰日；产品支持的时区和日期-only 语义；默认、清空、取消和联动限制。 |
| 选择类 | 枚举值和标签正确，非首项/换项/清空/不存在或已停用选项；远程加载失败/重试、长选项、搜索、级联；快速切换 A→B 时晚到 A 响应不得覆盖 B，不能保存陈旧关联 ID。 |
| 跨字段与行 | 单字段合法但组合非法、条件必填/显隐/禁用、合计/精度/互斥；不同记录相同字段名但数据不同，验证编辑及行操作命中正确对象、无串值。 |
| 权限与状态 | 按实际角色和草稿/提交/审批等状态列出可见、可编辑、可执行分支；读权限不代表写权限。隐藏/只读/禁用后的 UI 操作不得成功写入。 |
| 主业务流程 | 至少串联创建或编辑→校验→提交→详情/列表→刷新/重新进入→独立服务端回读；验证实际业务状态、关联对象和副作用。取消不能误保存，失败后可重试，重复操作的结果符合幂等规则。 |

网络错误和延迟可用现有浏览器能力模拟，但检查 ID/前置条件和证据注明 SIMULATED；模拟失败恢复只能证明该前端分支。成功保存检查要用真实后端及独立回读。收集本轮新增 console/pageerror 和失败请求，关联操作与实际影响；先区分预期业务拒绝、既有环境噪声和产品异常，不机械将每个 4xx 都判为缺陷。

## 把视觉规范落到可测规则

存在 `enterprise-ui-design` 或项目自己的设计系统时，读取当前规范、token 和目标页面设计，记录路径/版本/规则位置；样式值从该来源获取，不复制一套固定宽度、色值或间距。没有规范时，遮挡/不可读/不可达等可观察缺陷仍可检查；“符合指定设计规范”保持 BLOCKED，区分可用性结论与规范符合性。

- 页面/容器/文本基准线、内边距归属、分组间距、表头及数字列对齐、内容宽度和密度；防止嵌套重复内边距。
- 按 [组件留白与间距均衡](component-spacing.md) 逐实例分配 SPACE-01～06；组件间 gap 与容器 padding 分别验收，边缘相贴、同层失衡及换行后缺少行距不能以“无溢出”通过。
- 字体/字号/字重/行高、数字单位/格式、按钮层级及可识别性；前景/背景颜色与对比度按项目采用的标准量化，禁用/错误/选中/hover/focus 状态分别检查。对比度通过不能替代整体可访问性结论。
- 页面、表格内滚动、固定/粘性区域、弹窗/抽屉/下拉的遮挡与层级；长标签、长错误、空/加载/错误态和条件区域展开后仍能读、能到达动作。
- 按项目支持范围验证桌面/窄屏、主题、密度与浏览器缩放/文字放大；支持键盘的控件能获得焦点、读懂标签/错误、操作并合理返回焦点。无障碍名称通过可访问树核对，不能仅看截图。

每个视觉检查写具体预期与来源，用实际几何、computed style、截图查看和键盘操作组合验证；容差来自设计与渲染环境。多个维度可以共享一次操作与证据，但检查 ID、预期和实际结论分别记录。
