# 质量验收

设计图和所选模式的最终成品各看一次。记录的是实际检查行为，不能因为脚本返回 passed 就填视觉通过。

## 设计图

沿用 consulting-ppt-image 的七个 review 字段，但 `visual_style` 对照本项目锁定的 theme，而非其旧墨绿色专属说明。检查单页、准确原文/数字、证据/概念标签、字号/对比、页码、关系连线、主题。典型失败：中文乱码、数据增加、缺节点、装饰压住文本、各页风格漂移。

## editable：重建与最终稿

| 维度 | 判定依据 |
|---|---|
| 内容 | 原稿逐字/逐数比对，尤其专名、单位、符号、图表系列、来源与限定语 |
| 视觉 | 源图/渲染并排或叠加检查；构图、主视觉、层级、边界、字体、换行、色彩 |
| 可编辑 | 文本框和结构对象真实存在；图片是独立素材；无隐藏小字/透明字冒充重建 |
| 整稿 | 顺序/范围/页数、跨页主题和字号、前后逻辑、备注与图表说明 |
| 可用性 | 实际打开；在副本中修改文字与结构对象、保存重开，检查没有残影/损坏 |

代表页必须验证重建后的效果。最终整稿查看全稿缩略图，再逐页放大读文字；密集架构、表格、图表和人物图片页重点检查。不能用单个全稿相似度阈值掩盖重要错字或缺失箭头。

`editppt page build` 的 `preview.png` 使用 Pillow 近似绘制，适合快速检查对象位置，不能证明 Office 中的字体和换行正确。至少用 PowerPoint 或 LibreOffice 实际打开／导出最终 PPTX，并检查实际渲染。字体必须使用当前宿主可解析的字体名称；发现替代字体、换行或字形异常时，回到页 manifest 修正后重新 build、record、finalize。不要仅调整预览字体来掩盖 PPTX 的字体问题；记录实际使用的应用和未测试的平台。

阻断交付：内容错误、缺页、不可读、重复底图、要求可编辑的结构被整块截图、明显素材变形、尚未完成必需素材分离。允许记录的差异：轻微字体替代/阴影差异，前提是不损害可读性、意义和用户明确的视觉要求。

## image：每页整图成稿

图片版每页须为一张已选原图，顺序、完整/部分范围、备注与 handoff 一致。整图可替换，图中文字和结构不能单独编辑；不做原生文本或结构对象验收，也不以缺少这些对象判失败。

打开实际 PPTX，查看全稿缩略图及逐页渲染，检查缺页、裁剪、拉伸、留边、遮挡、分辨率和文字可读性。将渲染与选定原图比对；原图有错字、错数、缺箭头或错误概念标签时，先改原图并重新登记、审阅、选版、交接和导出，不能靠备注补救。验证副本可替换整图并保存重开，但这不证明图片内部可编辑。

同一主题的图片版验收仅覆盖图片路径，不推定可编辑重建质量。代表页也须经过真实图片版导出与渲染检查，再扩大批次。

## 机器检查的范围

- `verify-handoff`：核对当前原稿、主题、选版、顺序、内容文件与图片哈希；同时检查转换载体的页数、原图、备注和画布/比例/裁剪。
- `audit-pptx`：用于 editable，检查页数、逐页原生文本、备注和已知整页原图哈希。它不检测重编码底图、所有隐形文字、文字对比、完整图表数值或像素保真，仍需 editppt 结构验证和实际渲染检查。
- `audit-images`：用于 image，先验证 handoff，再核对图片成稿标题及完整/部分标记、页数、每页恰好一张图片、原图字节与顺序、备注、画布、几何位置、比例、裁剪与翻转。它不识别图片内的文字/数字是否正确，也不证明实际应用中的渲染可读性。

两种成稿审计都返回 `visual_acceptance: false`。`export-images` 会自动运行图片审计，但导出成功仍不等于视觉验收。转换载体标题不是图片成稿标题，不能直接拿转换输入冒充最终交付。

交付说明区分：机器通过 / 已视觉查看 / 已编辑或替换整图并保存重开 / 用户业务验收。写清输出模式和实际应用，未执行的一项写明未执行，不自动替用户确认。
