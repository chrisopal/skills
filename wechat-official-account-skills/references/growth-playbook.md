# 智能体架构笔记增长策略参考

基于 2026-07-01 到 2026-07-30 的公众号后台趋势导出，供 `wechat-topic-planner`、`wechat-article-writer`、`wechat-daily-pipeline`、`wechat-industrial-ai-imagepost-pipeline` 复用。

## 已验证数据结论

- 月总阅读约 `3683`，日均约 `123`，7 月 30 日单日阅读比 7 月 1 日高约 `68.9%`。
- 流量来源强依赖推荐流：`推荐`约占全部阅读来源的 `63%`。
- `搜一搜`占比约 `2%`，说明搜索沉淀还弱，关键词与主题资产仍需补。
- 单篇集中度很高：《怎么从 0 到 1 配一个设备知识库智能体》约占全部文章阅读的 `55%`。前 4 篇文章累计吃掉约 `81.5%`。
- 已验证有效的内容形态不是“泛工业 AI 资讯”，而是：
  - `真实公司 / 真实流程 / 真实结果 / 清晰业务代价`
  - 一篇文章只打一个明确流程对象
  - 读者能马上代入自己的预算、验收、交付或使用问题

## 结构性判断

这不是一个“没有增长”的号，而是一个“增长结构仍偏单一”的号。

当前问题不是写不出可读内容，而是：

1. 还在吃旧爆文红利，新文章接力能力不足。
2. 推荐流已经有信号，但搜索和稳定订阅打开还没形成第二曲线。
3. `从 0 到 1` 方法文有效，但已经出现模板感，不能继续当默认发动机。
4. 朋友圈更偏好强判断、强态度、强冲突的评论判断文；推荐流更偏好具体场景的方法文或案例文。

## 默认增长策略

默认把账号内容拆成两条线：

### 1. 增长主线

目标：拿推荐流、沉淀搜索标签、形成行业定位。

优先形态：

- 真实案例复盘
- 阶段总结
- 客户决策文
- 少量方法拆解

优先标签：

- `设备智能体`
- `设备知识库`
- `设备维修智能体`
- `故障诊断`
- `点检`
- `工单`
- `MES`
- `运维`
- `质量`
- `排产`

### 2. 扩散副线

目标：拿朋友圈、聊天会话、转发讨论。

优先形态：

- 强判断评论文
- 一组案例背后的阶段结论
- 客户常见误判
- 预算、验收、二期投资、供应商选择

关键词不是重点，冲突和态度更重要。

## 四周默认排期

当没有更强用户指令时，优先按下面的四周混排执行。

### 第 1 周

- 主文：真实案例复盘
  - 方向：设备、维修、点检、故障、工单
  - 目标：吃推荐流，沉淀 `设备智能体` 相关标签
- 配套日报/贴图：围绕同类案例做素材池，不单独承担增长目标

### 第 2 周

- 主文：阶段总结
  - 方向：一组真实案例里，哪些工业 AI 已经进入主流程，哪些还停在 demo
  - 目标：提高转发和朋友圈讨论

### 第 3 周

- 主文：客户决策文 / 失败复盘
  - 方向：POC 跑通后为什么不批第二笔预算；为什么现场没人用；为什么供应商方案难验收
  - 目标：拉近老板、数字化负责人、交付负责人

### 第 4 周

- 主文：方法拆解
  - 方向：只允许做 1 篇 `从 0 到 1`，且必须绑定明确流程对象
  - 目标：承接搜索和咨询转化

默认比例：

- `真实案例复盘 50%`
- `阶段总结 30%`
- `方法拆解 20%`

不允许连续两篇主文都使用 `怎么从 0 到 1 配一个……`。

## 下一阶段优先选题池

优先从这些方向继续深挖：

1. 设备知识库 / 设备维修 / 故障诊断
2. 过程内质检 / 返工 / 质量逃逸
3. 老系统长出智能体：MES / ERP / PLM / SCADA / APS / WMS
4. 订单处理 / 工单处理 / 采购确认 / 售后协同
5. 预算、验收、二期投资、供应商选择

如果题目不落到这些流程对象之一，就要怀疑它会不会重新滑回“泛 AI 资讯”。

## 标题策略

### 已验证更有效的标题抓手

优先顺序：

1. 具体公司或具体对象
2. 具体流程
3. 具体结果或业务代价
4. 最后才是抽象判断

### 推荐流主标题模板

- `怎么从 0 到 1 配一个<设备/维修/质检/工单/排产>智能体`
- `<具体流程>为什么总在<某节点>出问题：怎么从 0 到 1 配一个<场景>智能体`
- `<公司名>把<具体流程>交给 AI 后，<结果>`
- `<结果数字>背后，<公司名>先改的是哪段流程`

注意：

- `从 0 到 1` 只在最近 4 篇主文没有同题型时使用。
- 结果数字和具体流程优先于大词判断。

### 朋友圈 / 转发标题模板

- `客户一口气要做 7 个智能体，我看完发现：……`
- `做了 20 年企业服务，我看 <对象>：……`
- `POC 跑通了，为什么老板还是不批第二笔预算`
- `同样叫 <某方案>，为什么一种能进真流程，另一种只能停在演示`
- `企业开始上智能体，最容易先做错的不是模型，而是……`

注意：

- 这类标题要更直接，但也要有具体对象，不要写成空泛感慨。

### 搜索型标题模板

- `设备知识库智能体怎么做，先看 1 个真实流程`
- `设备维修智能体怎么落地，先把这 4 类资料接起来`
- `工单处理智能体怎么做，哪些步骤必须人工确认`
- `MES 怎么长出智能体，不是先接大模型，而是先接流程和权限`

注意：

- 搜索型标题不追求最强推荐率，追求未来可持续检索。
- 关键词要自然，不要堆词。

## 渠道写法差异

### 推荐流

重点：

- 第一屏就要出现具体流程对象
- 标题和前 300 字要让微信容易判断读者画像
- 优先具体公司、具体流程、具体代价

适合：

- 真实案例复盘
- 场景型方法文
- 带结果数字的流程改造文

不适合：

- 大而泛的行业点评
- 只有概念没有流程对象的架构文

### 朋友圈

重点：

- 要有态度、冲突和可转述判断
- 标题可以比推荐流更“像人说话”
- 正文前两段要先讲这件事为什么值得转发讨论

适合：

- 评论判断文
- 阶段总结
- 客户误判 / 供应商选择 / 预算决策

### 聊天会话

重点：

- 让老粉觉得“这篇值得转给别人”
- 正文要更快进入观点
- 可以接受相对更强的专业表达，但仍要落流程

适合：

- 具体问题拆解
- 行业案例判断

### 搜一搜

重点：

- 标题和开头固定埋稳定关键词
- 文章内部要反复出现自然同义词：设备、维修、工单、点检、运维、故障、MES
- 方法文比判断文更容易吃搜索

## 选题过滤器

默认拒绝这些题：

- 只是“工业 AI 趋势”但没有流程对象
- 只是“某公司发布了某产品”但没有工作流变化
- 又一篇沿用同样 `从 0 到 1` 七步结构的方法文
- 先定义术语，再编一个工厂场景来套解释
- 没有明确读者对象，不知道是给老板、IT、交付还是运维看的

## 复盘指标

每次新主文至少看这几项：

1. 总阅读
2. 推荐流占比
3. 分享率
4. 收藏率
5. 朋友圈拉动
6. 是否自然沉淀了一个搜索标签

如果一篇文章：

- 推荐起不来
- 分享弱
- 收藏弱

就不要按同样题型继续连续复用。

如果一篇文章：

- 推荐一般
- 但朋友圈或聊天会话强

说明它更适合走“评论判断文 / 阶段总结”方向，而不是继续逼它承担主增长任务。

## 执行提醒

- 日报和贴图的价值主要是素材池、活跃度和案例归档，不要默认把它们当成增长主文。
- 主文要优先服务“谁正在付代价、项目改了哪段工作、结果怎么验收、客户为什么继续投”。
- 不要让 `从 0 到 1` 变成语言模板；它只是一个历史上验证过一次的强格式，不是全部增长答案。
