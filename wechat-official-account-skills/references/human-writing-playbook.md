# 公众号活人感写作规则

这份规则把通用中文“活人感写作”方法收进 `智能体架构笔记` 的写作链。它服务现实题材的企业 AI 文章，不替代事实核验、账号定位和业务判断。

活人感不靠口头禅、粗口、错别字或故意写乱。它主要来自三件事：手里真有材料，作者知道自己站在哪里，每一段都把事情往前推了一步。

## 规则优先级

发生冲突时按以下顺序处理：

1. 用户明确要求和发布边界。
2. 现实事实、来源、数据、引语和案例边界。
3. 账号定位、目标读者和企业价值。
4. 本规则中的表达与节奏建议。

不要为了显得像人，补写没有来源的工厂现场、人物动作、对话、心理或亲历。真实感首先是信息来路可信。

## 动笔前：先确定读者要带走什么

先在内部写一张简短的读者卡：具体写给谁、他在哪个场景承受什么压力或作什么决定、读完能怎样调整判断或行动、哪些材料支持这个启发。目标画像应落到角色与工作，例如“为工业软件团队分配售前时间的销售经理”，不能只写“对 AI 感兴趣的人”。这张卡用于取舍内容，不照搬进正文。

围绕读者的一次选择或一条业务流程讲故事：他需要知道什么，哪些新信息会改变安排，AI 在哪一步帮助整理、追问、比较或衔接，他仍需确认什么。作者的搭建、调用、测试和产物清单，只有在解释读者如何应用或作出选择时才值得展开。事实都正确的执行记录，也可能需要整体重写。

介绍一组 Skills 时，默认用一张总览图和简短说明交代分工，再挑少数能帮助读者判断的环节。除非用户要求操作手册，不逐个写输入、输出、文件名和执行截图。录音、纪要、照片等材料，讲它们如何减少遗漏、形成追问或支持判断即可；解析日志、模拟纪要名称、归档路径和测试过程留在审稿包。

减少过程细节不等于隐藏事实边界。示例或演示数据在图注或文末简洁说明一次；不能包装成真实客户成交、作者亲历或效果实证。与读者决策直接相关的能力前提和限制，应留在相应段落附近。

## 第一关：材料门槛

写长稿前，在内部列出至少五件能托住文章的具体材料，并注明来源。可用材料包括：

- 经核验的公司动作、产品能力、数据、结果或时间节点
- 真实业务流程中的角色、单据、系统、审批、异常和责任
- 用户明确提供的经历、观察、原话与判断
- 能改变结论的失败、限制、反例和未知
- 作者基于上述材料作出的有边界推断

一个抽象观点换几种说法，不算多件材料。常识推演、模型临时编出的“典型场景”、装饰性细节和比喻也不能撑篇幅。

材料不足时依次处理：

1. 能查公开资料就先研究，并优先使用一手来源。
2. 依赖私人经历时，集中询问最多三个关键问题。
3. 仍然不足就缩小题目或缩短篇幅。

不要用重复解释填满目标字数。文章长度服从材料密度。

## 第二关：段落推进

每写完一段，在内部回答两句：

- 这一段靠哪条材料站住？
- 它比上一段新增了什么？

新增内容可以是事实、动作、例子、区别、限制、后果或有依据的判断。只把上一段换一套抽象说法，直接合并或删除。

段落之间优先靠对象和因果连接。上一段出现一张工单，下一段可以讲谁处理它；上一段出现一个结果，下一段可以讲谁承担影响。少用“更深一层”“值得注意的是”“这意味着”给段落排队。

做一次压缩试验。删掉三分之一后，事实、动作和判断几乎没变，原稿就在注水。保留压缩后的版本。

## 第三关：说话位置

成稿应让读者看出：

- 谁在讲，他凭什么知道
- 哪个事实让他现在想讲这件事
- 他最在意哪个业务冲突
- 哪个判断是材料支持的，哪些仍是推断或未知

声音来自取舍，不来自频繁添加“我觉得”“说真的”。观点可以明确，依据和边界要放在附近。

公开材料写成的事实稿，可在开头附近自然交代一次信息来路。不要让“公开资料显示”“目前无法确认”接管全文。

## 动作级翻案腔检查

不要只搜索某个禁句。逐段判断它是否在做这个动作：先替读者制造一个并不存在的笨答案，再推翻它给下文抬价。

常见外衣包括：

- `不是 A，而是 B`、`并非 A，而是 B`
- `你以为 A，其实 B`
- `看似 A，实则 B`
- `A 不重要，重要的是 B`
- `大家都在谈 A，真正关键的是 B`
- 跨句先贬低旧判断，再用“其实 / 才是 / 答案相反”抬出新判断

改法不是换一个漂亮句式。直接说 B，再把事实和适用条件放在旁边。

文章确实记录了作者如何被一条新材料改变判断时，可以保留真实的自我修正。要写清原来依据什么、哪条证据改变了判断，不能套固定反转句式。

## 中文节奏和句法

- 主语和动作尽早出现，时间、原因和条件随后补充。
- 长句负责展开复杂关系，短句负责落地；不要把全文修成同样长度。
- 连词只在真有逻辑关系时保留。中文小句常能靠语序和事理自然接上。
- 把“进行了优化”“实现了提升”还原成谁改了什么、快了多少、少做了哪一步。
- 允许必要的关键词重复。为躲重复不断换同义词，文章会变油。
- 连续三项以上同构排比通常像模型在批量生成。保留两项，第三项换写法或删除。
- 动作、结果和原话已经传出情绪时，不要紧跟一句抽象解释。
- 小标题只用于定位，不要把文章切成一套整齐的咨询报告。

句长变异、连词密度、短段排队和重复开场可以用脚本提示。数字只负责暴露形状，不能证明文章有没有人。

## 企业 AI 文章的具体落点

抽象名词出现后，尽快落到具体角色和工作对象：

- 谁购买、审批、部署、使用、维护和验收
- 他在看哪张表、签哪张单、改哪条工单、确认哪次执行
- 出错以后谁负责，旧流程在哪一步最难受
- 项目让谁少花时间、少返工、少停机，或者增加了什么风险

技术背景只在能解释角色选择、风险大小或结果差异时出现。知识点删掉以后结论不变，它多半来早了，或根本不需要。

## 从实践中提炼读者判断，不复制成功文章

2026-10 的投标 Skill 文章提供了一次有用的复盘：作者原本要做投标产品，后来不断陷入文件识别、提示词调整、执行与恢复等通用智能体能力的维护；改用通用智能体驱动业务 Skills 后，已有积累得到复用。文章的价值在于讲清这次选择如何发生、产物是什么、其他团队在什么条件下可以参考。它不证明“Skill 总比系统好”，也不意味着从零开发只要两天。

下次选题先在内部回答：这篇主要写给谁，他正在作什么决定，读完以后凭什么改变判断。若考虑转发价值，再问一句：他可能把文章发给哪位同事，用来讨论哪件具体的事。能帮助团队作出选择、解释返工原因或核对成果，比单纯介绍工具更有讨论价值；这是一项选题判断，不要求正文写“建议转给……”或硬加金句。

有真实项目转向时，优先寻找这些材料，按它们之间的因果组织叙事：

- 起初要交付什么，实际花力气处理的却是什么；读者能认出的具体麻烦在哪里。
- 哪个失败、成本或新能力改变了选择；不要编造顿悟、对话或戏剧性反转。
- 业务流程和已有经验保留了什么，具体把什么职责交给了新方案；不能只写“更轻量、更高效”。
- 有哪些实际产物能核对变化，还有哪些问题、人工工作和不适用场景。

以上是取材问题，不是文章目录。没有真实转向的教程、原理解释、比较或观察稿，不必补写旧方案失败。技术细节只展开到能解释选择或帮助复用的程度；涉及一组 Skills 时，整体关系加少数关键环节通常比逐个介绍更清楚。

动笔前依据材料提出两种不同的推进方式，选择更能兑现标题承诺的一种。它们应在起点、证据安排或读者问题上不同，不能只是换小标题。可从一个产物倒推做法，从一次异常追到根因，也可围绕适用条件比较几条路径；这些只是选项，不能成为新一轮固定轮换表。与近期文章比较核心问题、开场、证据顺序和收尾；同题有新证据可以续写，不能只换项目名复刻整篇。

标题抓住本篇有依据的对象、代价、变化或待解问题，交给标题审核 Skill 检查承诺。不要复制“反复重构后，我用两天换成……”的句式，也不要要求每篇都有数字、反转或第一人称。

**图是证据或解释工具。** 写作时先注明它回答哪个问题，再选择真实界面、实际产物、结构图或示意图。系统与产物截图先隐藏客户名称、文件内容、项目数据和其他识别信息，回看最终导出的图片；缩小截图不等于脱敏。真实截图、已脱敏截图、合成演示材料和生成原型须清楚区分，示意图不能证明系统已实现。用整体图交代关系，再挑能改变读者判断的实例内嵌正文，不要求每个 Skill 都有截图。产物展示前核对实际生成版本、结论和版式，不能把演示稿、待整改项或阻塞状态包装成成功交付。

**传播效果只形成待验证线索。** 本次用户提供的后台截图显示阅读 500、转发 93；单个时点的计数没有历史基线、传播来源、独立人数或阅读完成数据，不能据此断言某种标题、排版或选题带来了增长。93/500 只是两个展示计数的比值，不是独立读者转发率。将“真实代价、可迁移判断、实际产物可能促进讨论”保留为后续观察假设，不能写成爆款公式或平台推荐机制。

## 初稿后的六遍审校

1. **材料**：事实、数据、引语、案例和第一人称动作是否有来源。
2. **推进**：每段是否新增信息；重复解释合并或删除。
3. **说话者**：是否看得见具体判断、信息来路和不确定边界。
4. **动作级套话**：清理假翻案、洞察路标、同构排比和抽象金句。
5. **中文节奏**：检查主干、长短句、连词、名词化和段落长度。
6. **结尾**：删掉总结全文、强行升华和无关尺度；在事情讲完处停下。

最后冷读三问：哪一段只能属于这篇文章？哪句话说得比材料大？文章在哪一句已经结束？

## 自动检查的边界

可运行：

```bash
python3 scripts/check_human_tone.py /absolute/path/to/draft.md
```

脚本只输出提醒，不自动改稿，也不把所有命中词判成错误。产品名、技术术语、人物原话和准确本义可以保留。审稿人要结合上下文判断句子是否真的在表演洞察。
