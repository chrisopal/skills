# 公众号排版、配图与产品视觉系统

适用账号：智能体架构笔记

适用品牌/产品：慧新 / 工业 AI 与智能体架构相关产品、官网、管理后台、演示材料和内容资产。

本文件是公司级视觉源规范。当前微信公众号配图已经形成的纸面感、工程感、墨绿/深灰/少量橙色配色，不再只作为内容栏目风格，而是作为公司和产品 UI 的默认视觉语言。后续产品界面、官网、PPT、销售材料、案例图、工作台原型和文章配图都应从这里取 token、布局语法和禁用项。

## Visual Positioning

视觉语言应像一份可收藏、可复述、可落地的工程架构笔记：

- 内容优先，少装饰。
- 纸面感、工程感、可收藏。
- 有清晰层级、编号、注释块、细线分隔。
- 统一使用墨绿、深灰、白底、少量橙色强调。
- 看起来像真实产品团队在解释系统、流程和业务判断，而不是通用科技海报。

公司级关键词：

- `engineering paper`：白底、细线、编号、注释、清晰网格。
- `operator console`：像企业工作台一样克制、可信、可扫描。
- `architecture note`：模块、箭头、层级和判断优先。
- `warm industrial intelligence`：工业 AI 的理性与人的判断并存，不冷冰冰炫技。

## Shared Visual Grammar

所有 `imagegen` 配图、产品 UI 和对外材料共用同一套视觉语法，不因单篇文章、单个页面或单份材料随意漂移：

- 白底或近白底，保留纸面感，不做海报式重背景。
- 深灰主文字、墨绿主结构、橙色只用于纠偏、风险、控制流或重点提醒。
- 节点、卡片、箭头、细分隔线、工程注记优先；装饰性插画、人物和赛博特效禁用。
- 图中文字以中文为主，短标签优先，尽量 4-6 个核心节点，不做密集表格。
- 封面、痛点链路、方案架构、价值闭环、工作台原型都应让人一眼看出来自同一个栏目系统。
- 产品 UI 不做大面积品牌色铺底；品牌感来自结构、留白、线条、标签、编号和少量强调色。
- 如果需要引入蓝/青色，只能作为软件系统、接口、数据通道的辅助色，不能取代墨绿主结构。

统一 prompt 骨架：

> 白底专业技术信息图 / 架构图风格，服务于微信公众号「智能体架构笔记」，纸面感、工程感、深灰、墨绿、少量橙色，中文文字清晰可读，模块卡片、细线箭头、分层结构、简洁现代，不要人物，不要赛博朋克，不要复杂背景。

### Company / Product Palette

公司和产品 UI 以 `Ink / Green / Soft / Line / Orange` 为主，不再默认使用高饱和蓝紫科技风。已有慧新 PPT/方案材料中的青蓝和亮绿可以保留为二级产品色，但必须服务于系统结构和 AI 能力提示。

| Role | Token | Hex | UI Usage |
| --- | --- | --- | --- |
| Page Background | Paper | `#fbfcfa` | 产品页、后台、官网主体底色 |
| Surface | White | `#ffffff` | 卡片、表格、弹窗、输入区 |
| Surface Soft | Soft | `#f6f8f6` | 筛选区、摘要区、空状态、说明块 |
| Text Primary | Ink | `#1f2933` | 标题、正文、表格主字段 |
| Text Secondary | Muted | `#64716b` | 描述、帮助文字、次级字段 |
| Border | Line | `#dfe8e3` | 分割线、卡片边框、表格线 |
| Brand Primary | Green | `#1f5b45` | 主按钮、导航选中、关键路径、编号 |
| Brand Strong | Green Dark | `#12372a` | 一级标题、顶部品牌条、深色文字强调 |
| Accent / Warning | Orange | `#d97732` | 风险、控制点、转折判断、待处理状态 |
| Product Data | Tech Teal | `#4295b6` | 数据流、接口、系统连接线，限量使用 |
| AI Value | Fresh Green | `#a8d86b` | AI 能力、价值增益、正向状态，限量使用 |

比例：

- `70%` 白 / 近白 / 浅灰绿背景。
- `20%` 深灰文字、线框和结构。
- `8%` 墨绿主结构。
- `2%` 橙色或青蓝/亮绿点缀。

禁用：

- 大面积蓝紫渐变、深色赛博背景、霓虹光效。
- 一屏内同时出现多种高饱和强调色。
- 把橙色当成普通装饰色；橙色只用于提醒、风险、控制点和关键判断。

### CSS Design Tokens

产品 UI 默认以这些 CSS 变量作为语义 token：

```css
:root {
  --hx-bg-paper: #fbfcfa;
  --hx-bg-soft: #f6f8f6;
  --hx-surface: #ffffff;
  --hx-ink: #1f2933;
  --hx-muted: #64716b;
  --hx-line: #dfe8e3;
  --hx-green: #1f5b45;
  --hx-green-dark: #12372a;
  --hx-orange: #d97732;
  --hx-teal: #4295b6;
  --hx-fresh-green: #a8d86b;
}
```

UI 状态映射：

- Primary action：墨绿底 `#1f5b45` + 白字。
- Secondary action：白底 + 墨绿文字 + `#dfe8e3` 边框。
- Destructive / risk：不使用大红铺底，优先橙色文字、左边框或轻背景提醒。
- Success / AI value：少量 `#a8d86b`，不能变成荧光主色。
- Data / integration：少量 `#4295b6`，用于数据流和系统接口，不用于主 CTA。

## Typography

微信公众号正文使用系统字体栈：

```css
-apple-system, BlinkMacSystemFont, Helvetica Neue, PingFang SC,
Hiragino Sans GB, Microsoft YaHei, Arial, sans-serif
```

字号：

- 正文：16px / 1.86-1.9
- 摘要：15px / 1.75
- 二级标题：20px / 1.52
- 文章内标题：25px / 1.38
- 标签与编号：12-13px

产品 UI 字体同样使用系统字体栈，优先保证中文可读性和跨端一致性，不强依赖外部 Web Font。

产品 UI 字号：

- Page title：24-30px / 1.35 / 700
- Section title：18-22px / 1.45 / 700
- Card title：15-17px / 1.45 / 650
- Body：14-16px / 1.65 / 400
- Table：13-14px / 1.55 / 400
- Caption / Meta：12-13px / 1.45 / 400
- Metric：28-40px / 1.1 / 700

文字规则：

- 业务判断用短句，不用口号。
- 标题先说对象或结果，不用抽象大词堆叠。
- UI 按钮不超过 6 个汉字，表格列名优先 2-5 个汉字。
- 重要数字可以放大，但不要使用负字距或夸张 display 字体。

## Product UI System

产品界面应像一张可操作的工程笔记，而不是营销落地页。优先支持扫描、比较、过滤、确认和复盘。

### Layout

- 主体使用浅纸色背景，内容区使用白色 surface。
- 常规后台使用左侧导航 + 顶部上下文栏 + 主工作区。
- 工作区优先 12 列网格，内容最大宽度按场景控制，不做无意义居中窄版。
- 卡片圆角 `6-8px`，不要使用大圆角胶囊风。
- 边框优先 `1px #dfe8e3`，阴影只做 4-8% 黑色轻阴影；能用线框表达就不用厚投影。
- 页面 section 不套 section 卡片；卡片只用于重复对象、表格容器、弹窗和明确工具面板。

### Core Components

| Component | Visual Rule | Notes |
| --- | --- | --- |
| Navigation | 白底或浅纸底，选中项墨绿左线/底线 | 不用大面积深色侧栏作为默认 |
| Toolbar | 细线分隔 + 紧凑控件 | 适合筛选、批量动作、视图切换 |
| Card | 白底、细边框、6-8px 圆角 | 只放一个明确对象或任务 |
| Table | 高密度、浅分隔线、悬停浅绿底 | 企业后台默认首选表格而非卡片瀑布 |
| Form | 标签左/上清晰，错误提示橙色 | 不用只有 placeholder 的输入框 |
| Badge / Chip | 墨绿描边或浅绿底 | 用于状态、行业、阶段、角色 |
| Timeline / Flow | 编号 + 箭头 + 注释块 | 用于 AI 工作流、审批、交付路径 |
| Diagram | 模块、层级、连接线、反馈回路 | 保持可编辑结构，不贴一张图糊住 |
| Empty State | 轻量线性图 + 下一步动作 | 不用情绪化插画或夸张人物 |

### Interaction

- Hover 只改变边框、底色、文字色或轻阴影，不做明显缩放。
- Focus 必须可见，默认使用墨绿 outline 或浅绿 focus ring。
- Loading 用骨架屏或进度条，少用大面积品牌动画。
- 对危险操作使用确认弹窗和橙色风险提示，不用恐吓式红色大块。
- 工作台类页面默认支持搜索、筛选、排序、批量选择、详情抽屉和审计记录入口。

### Product Page Patterns

首批产品/官网页面优先复用这些模式：

1. `问题 -> 系统结构 -> 工作流 -> 结果证据`：适合解决方案页。
2. `角色入口 -> 任务列表 -> AI 建议 -> 人工确认 -> 系统动作`：适合工作台。
3. `数据源 -> AI 分析 -> 控制点 -> 输出物 -> 复盘`：适合企业 AI 产品。
4. `现状痛点 -> 方案抓手 -> 实施路径 -> 价值指标`：适合销售材料和案例页。

## Brand Geometry

当前公众号配图的模块卡片、箭头、编号和注释块是主视觉语言。若使用慧新既有斜切条 / parallelogram 几何，可作为公司识别线索，但不要喧宾夺主。

使用方式：

- 斜切条用于页眉细线、流程节点的右上角切片、标签底纹或阶段连接。
- 架构图节点优先矩形/圆角矩形；斜切只做品牌识别，不改变阅读效率。
- 图标使用统一线性风格；能用模块、箭头、数据流表达时，不要堆通用图标。
- Logo 只放在封面、页脚、官网导航或正式材料固定位置；日常 UI 不用反复贴 logo。

## Cross-Media Rules

### Website / Landing

- 首页第一屏应直接呈现产品或解决方案对象，不做抽象渐变 hero。
- 背景白/近白，主视觉使用真实产品界面、架构信息图或流程图。
- H1 写产品/方案类别或直接 offer，价值说明放副标题。
- CTA 使用墨绿主按钮，辅助 CTA 使用白底描边。
- 信任感来自案例、流程、证据和可视化系统结构，不来自夸张科技视觉。

### SaaS / Admin UI

- 默认是信息工作台，不是宣传页。
- 高密度但有秩序：表格、筛选器、状态 chip、详情抽屉、审计日志。
- 首页仪表盘只保留真正需要每日看的指标，不做“假数据大屏”。
- AI 输出必须配控制点：来源、置信、人工确认、下一步动作、回放记录。

### PPT / Sales Material

- 延续白底高密度信息表达。
- 蓝/青色可以用于系统结构，但墨绿仍是判断与关键路径。
- 架构页必须可编辑，模块、标签、连接线和层级不应被位图替代。
- 一页只讲一个主判断，复杂系统拆成多页架构/流程/价值闭环。

### WeChat / Image Post

- 公众号继续作为公司视觉系统的内容试验场。
- 新图形样式先在配图中验证可读性，再沉淀为 UI 组件或产品页模式。
- `工业AI日报` fullcard 是案例解释模板，也可迁移为官网案例页和销售材料单页。

## HTML Components

### Article Header

- 浅灰绿背景 `#f6f8f6`
- 1px 边框 `#dfe8e3`
- 顶部 5px 墨绿线
- 小标签：`AGENT ARCHITECTURE NOTE`
- 标题 + 摘要

### Section Heading

每个二级标题使用：

- 顶部分隔线
- `SECTION 01` 小标签
- 20px 墨绿标题

### Lists

不要使用原生 `<ul>` / `<li>`。

原因：微信编辑器和预览里容易出现空 bullet、间距失控、断行难看。

替代方案：

- 每个列表项渲染成独立浅底编号块。
- 左侧使用 `01`、`02`、`03`。
- 用 `section/span` 组合，而不是 `<ul>/<li>`。

### Quote / Key Question

- 左侧 4px 橙色线
- 浅橙背景
- 用于关键问题、判断或转折

### Footer

固定栏目签名：

> 智能体架构笔记，持续记录这一轮 AI 技术从能力走向系统、从演示走向企业真实流程。

## Cover Image

封面图默认通过宿主智能体配置的 `imagegen` 工具生成 raster bitmap，并优先让 `imagegen` 直接生成完整中文标题。`imagegen` 是默认主路径，不是可选项。不要默认用手写 PIL/SVG/HTML 画封面或大面积叠字，除非 `imagegen` 不可用、反复失败、无法产出可用结果，或用户明确要求确定性图形。

首页封面优先解决“停下来看一眼”的问题，不在封面里讲完整方案。详细解释放正文插图，不要把封面做成缩小版架构白皮书。

封面统一方向：

- 白底专业技术架构图风格
- 标题优先 10-18 字，尽量一眼能读完
- 只保留 1 个核心画面或 3-5 个模块
- 可以保留 1-2 个结果数字或短 badge，但不要大段 bullet 说明
- 分层结构、节点、箭头、连接线、笔记感元素
- 中文标题区域留白
- 深灰、墨绿、少量橙色
- 不要人物、赛博朋克、复杂背景、强蓝紫渐变
- 标题优先直接由 `imagegen` 生成，不默认走本地大面积叠字
- 不要在封面里同时塞入大段说明、底部能力表、长 bullet 列表、过多边框分区

首页封面简化优先级：

1. 标题先被读懂
2. 一眼看懂主题是什么流程/场景
3. 再用很少的数字或结果增强点击欲望

推荐封面骨架：

- 左侧大标题 + 1 行副标题
- 右侧单条流程 / 3 卡片结构 / 1 个核心示意图
- 角落放 `10周上线`、`90%自动通过` 这类短结果标签

推荐尺寸：

- 微信封面横图：900x383
- 方图备份：500x500

## Inline Illustrations

正文插图默认通过宿主智能体配置的 `imagegen` 工具生成统一风格 raster bitmap。插图的内容 brief 由写作 skill 给出，排版 skill 负责把 brief 转成 imagegen prompt、保存图片，并优先要求 `imagegen` 在图中直接生成短中文标签。

适合图型：

- 流程图：从输入到决策到行动到复盘
- 分层图：模型层、上下文层、工具层、流程层、治理层
- 对比图：demo vs 上线、工具调用 vs 权限边界
- 案例路径图：业务场景 -> AI 能力 -> 人类确认 -> 系统动作 -> 指标

图内文字要短，优先 4-6 个节点，不做密集表格。

生成原则：

- 优先让宿主 `imagegen` 直接生成完整信息图，包括短中文标题和节点标签。
- 本地脚本只做裁切、压缩、格式整理或极少量修正，避免大面积叠字造成视觉割裂。
- 如果需要保留在图中的中文，必须人工或脚本复核文字准确性。
- 不使用纯代码绘制的占位图作为最终插图；代码绘图只适合流程验证，或在 `imagegen` 不可用/不可用结果时兜底。
- 图片保存到项目工作区，例如 `assets/wechat/`，不能只留在 imagegen 默认目录。
- 每次 `imagegen` 调用后，必须立刻执行一次导出/记录动作；在 `/Users/guojiexie/content-mgmt`，默认命令是 `python3 scripts/persist_imagegen_output.py --target assets/wechat/<slug>-<role>-imagegen.png --record assets/wechat/imagegen-manifest.jsonl`。

推荐文章内图组合：

- 案例深度文：优先从 `痛点链路图 / 方案架构图 / 工作台或原型图 / 价值闭环图` 里选 2-4 张
- 技术解释文：优先 `分层图 / 对比图 / 流程图`
- 轻量短文：没有明确认知门槛时可只保留封面

## Daily Image-Post Fullcards

`工业AI日报` 的图片消息卡片是主要阅读载体，不是正文配图。每张 9:16 fullcard 必须像一页可收藏的工程案例笔记，信息密度要高于普通封面。当前优先参考 `OnLogic` 和 `SINTRONES` 样式：顶部标题，绿色公司/行业标签，图例链路，中央大幅方案拆解图，底部四条解释栏。

固定结构：

- 顶部：品牌/公司名 + 短标题，标题大但不要挤压主体。
- 公司/地区与行业标签：绿色 chip 或描边标签，例如 `Sage｜美国 / 英国`、`ERP / 制造分销 / AI决策`。
- 图例链路：4 个模块箭头，展示最短路径，例如 `运营数据 -> AI洞察 -> 人工审批 -> 经营决策`。
- 中央方案图：全卡最大区域，使用系统框、设备图标、流程箭头、虚线反馈回路和小注释，讲清端到端方案如何运转。
- 底部解释栏：四条横栏，固定为 `做了什么`、`方案抓手`、`业务价值`、`我的判断`，每条左侧用绿色图标块，右侧用 1-2 行解释。
- 可选核心要点：最底部一条橙色星标或提示栏，仅在信息复杂时使用。

视觉约束：

- 保持白底纸面感，细线分隔、编号、注释块和模块箭头。
- 主色只用深灰、墨绿、少量橙色；橙色用于风险、控制点或价值强调。
- 中央方案图可以使用拟物的设备、芯片、仪器、软件界面小图标，但必须服务于流程解释。
- 禁止 logo、水印、人物、装饰性拼贴、无意义工厂插画、假仪表盘、复杂背景和大面积渐变。
- 文字优先级：标题清楚，中央图解释方案，底部四栏完成判断；不要做成只有文字块的模板。
- 如果中央方案图无法说明端到端路径，或者底部四栏太空泛，必须重做。

## Asset Persistence And Naming

最终交付给草稿 API 的图片必须是仓库内真实文件，不是宿主缓存引用。

- 最终路径优先放在 `assets/wechat/`
- 如果宿主 `imagegen` 先写到 `$CODEX_HOME/generated_images/...`，必须复制到项目目录后再继续
- 如果本次会话只暴露了内联结果或会话记录，必须把选中的图片解码/导出到项目目录
- 建议同时写一份持久化记录，至少包含 `session_id / call_id / prompt / target`；在 `/Users/guojiexie/content-mgmt`，默认记录文件是 `assets/wechat/imagegen-manifest.jsonl`
- 命名保持文章 slug + 图型后缀，便于后续复用和审稿追踪
- 推荐命名：
  - `<slug>-cover-imagegen.png`
  - `<slug>-pain-chain-imagegen.png`
  - `<slug>-architecture-imagegen.png`
  - `<slug>-value-loop-imagegen.png`
  - `<slug>-workbench-imagegen.png`

## QA Rules

- 公司/产品 UI 是否使用本文件的 `--hx-*` token 或等价语义 token。
