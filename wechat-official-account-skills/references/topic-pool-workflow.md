## 状态机

只使用下列状态：

- `BACKLOG`
- `SELECTED`
- `RESEARCHING`
- `DRAFTING`
- `READY_LOCAL`
- `DRAFT_SAVED`
- `PUBLISHED`
- `PAUSED`
- `ARCHIVED`

正常流转：

`BACKLOG -> SELECTED -> RESEARCHING -> DRAFTING -> READY_LOCAL -> DRAFT_SAVED -> PUBLISHED`

证据要求：

- `READY_LOCAL`：本地 Markdown/HTML 已完成。
- `DRAFT_SAVED`：必须存在微信 `media_id`，并完成 `draft/get` 回读。
- `PUBLISHED`：必须有用户确认、公众号后台已发布记录或文章公开链接。
- 不允许仅凭文件名、文章日期或接口提交响应推断更高状态。

## 选题前查询

1. 读取本地主索引。
2. 如果 Get笔记能力可用，读取知识库 `0QWLW1Kn` 中的主索引笔记并核对标题、`topic_id` 和状态。
3. 使用 `topic_id`、近似标题、公司/案例名和核心问题四类键去重。
4. `PUBLISHED`、`DRAFT_SAVED`、`READY_LOCAL`、`DRAFTING` 的相同主题默认不可重新立项；如为续篇，必须使用新的 `topic_id` 并说明增量问题。
5. 优先从 `SELECTED` 和 P0 `BACKLOG` 中选择，不要每次都绕过选题池重新生成一批标题。

## 状态回写

每次回写至少保留：

- `topic_id`
- 实际标题
- 状态
- 更新时间
- 本地稿路径（如有）
- 微信 `media_id`（如有）
- 发布链接和发布时间（如有）
- 阅读、分享、推荐、点赞、评论（如有）
- 事实证据或审核文件路径

状态变化时：

1. 精确定位原 `topic_id`，只修改对应记录。
2. 更新本地主索引。
3. 使用 Get笔记 `/note/update` 更新主索引笔记 `1917527569583477584`，不要新建重复笔记。
4. 通过 `/knowledge/notes?topic_id=0QWLW1Kn` 回查主索引仍在知识库中；必要时再读取笔记详情确认正文已更新。
5. 只有本地和 Get笔记都成功时，才能报告“选题池已同步”。

## 失败处理

- Get笔记鉴权、网络或限流失败：保留本地更新，并在记录旁写明 `sync_pending`、失败时间和原因；下次运行优先重试同步。
- 本地与 Get笔记冲突：不要凭“更新时间更晚”自动覆盖。先核对微信草稿回读、发布后台或用户确认等外部证据，再合并状态。
- 无法确认是否发布：最多标为 `DRAFT_SAVED`，明确写“未确认发布”。
