# 证据与草稿门

## 证据等级

| 等级 | 示例 | 可以支持的写法 |
|---|---|---|
| 用户需求 | 用户指定观点、期望、目标 | “本文要验证……” |
| 公开来源 | 官方文档、官方仓库、原始公告 | “官方公开能力包括……” |
| 操作截图 | 真实工具中的一步动作或结果 | “在该步骤中实际看到……” |
| 产物 | PPTX、HTML、图片、导出文件 | “已生成文件……” |
| 回读 | 重新打开、API get、结构检查、目标应用验证 | “已验证可打开/可读取/已保存……” |

高等级结论必须由同等级证据支持。不能用“文件存在”支持“文件可用”，不能用“接口返回成功”支持“草稿内容正确”。

## 截图检查

每张公开截图逐项确认：

- 对应一个明确步骤或验收点
- 主体可读，裁切后仍保留必要上下文
- 个人昵称、头像、手机号、邮箱、账号 ID 已隐藏
- 密钥、令牌、Cookie、文件系统隐私路径未出现
- 红色报错、失败状态、未保存提示已经判断
- 若错误影响结论，已修复并重做截图
- 若错误只是不应公开的旁支信息，内部原图保留，公开副本脱敏
- 箭头、框线和标注指向准确
- 标注没有遮住按钮、状态或关键数值
- 文件名区分 `raw` 与 `public`

不要覆盖原始证据。公开图另存，例如：

```text
assets/wechat/<slug>-step-03-raw.png
assets/wechat/<slug>-step-03-public.png
```

## 真实场景验收

至少满足：

1. 每个关键步骤状态为 `passed`。
2. 每个步骤有可定位的 `evidence_ids`。
3. 每条验收标准状态为 `passed`。
4. 至少有一张公开前已检查的操作截图。
5. 至少有一项产物或回读证据。
6. 长文至少有五条已验证材料。
7. 失败、限制和未验证边界已记录。

不同产物使用不同回读方式：

| 产物 | 最低回读 |
|---|---|
| PPTX / DOCX / PDF | 用目标应用或解析器重新打开，检查关键页/对象 |
| HTML | 浏览器打开，检查移动端、资源、链接和残留 |
| 图片 | 查看最终分辨率，逐图视觉检查 |
| API 对象 | 调用 get/list 读取服务端对象 |
| 异步任务 | 读取终态，不以启动成功代替完成 |
| 微信草稿 | `draft/get` 回读标题、摘要、封面、正文和图片 |

## 写作前 Gate

运行 `--phase evidence`。失败时：

- 可以继续补研究和操作记录
- 可以保留文章大纲
- 不得写“已验证”“实测成功”“端到端完成”
- 不得把文章作为完整实战草稿保存到微信

## 微信预检

保存前检查：

- 当前出口 IP 已加入白名单
- 凭据只从安全环境读取
- 已知 `media_id` 时使用更新
- HTML 无 Markdown 链接残留
- HTML 无本地文件路径
- HTML 无个人信息或错误残留
- 封面和正文图已上传或可被微信访问
- 草稿内容无 `<ul>/<li>` 原生列表
- 人味审稿和最终审稿均通过

外部 GitHub 等链接可能被微信正文过滤。正文使用干净项目名，把 URL 保留在本地来源清单和审计包。除非 `draft/get` 确认链接仍可用，不要向用户承诺可点击。

## 草稿回读 Gate

调用草稿接口后：

1. 记录返回值和 `media_id`。
2. 等异步命令真正结束。
3. 调用 `draft/get`。
4. 比对标题、摘要、封面、正文图片和正文关键段。
5. 保存回读 JSON。
6. 更新 topic pool 为 `DRAFT_SAVED`。
7. 运行 `--phase draft`。

只有第 7 步通过，才报告：

> 已保存草稿，未发布。

若新增接口可能成功但回读失败，先查草稿列表和服务端对象，再决定是否重试。不要盲目再次新增。

## 时间压力规则

截止时间不改变证据等级。时间不足时按顺序缩减：

1. 缩小真实场景
2. 缩短文章
3. 减少非必要配图
4. 停在 `READY_LOCAL`

不能缩减：

- 真实回读
- 截图隐私检查
- 结论与证据对应
- 最终审稿
- `draft/get`
