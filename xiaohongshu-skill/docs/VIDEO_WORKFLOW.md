# 视频发布清单

已有成片、封面和发布文案时，将它们放在一份 JSON 清单中。保留作品已有叙事和视觉选择；发布工具不负责改写标题、删改正文或另选热门话题。

## 准备与恢复

复制 `examples/video-manifest.json`，填入实际账号与内容，将视频和封面放到对应路径。`account` 是创作者中心显示的账号名称，用于填写前核对。没有封面时可省略 `cover`。

```bash
uv run python -m scripts publish-video --manifest /path/to/job.json --preflight
uv run python -m scripts publish-video --manifest /path/to/job.json --headless=false
```

预检检查可读文件、必填项、话题格式、正文长度和定时时间，不打开浏览器。首次准备上传一次视频、设置封面、填写正文、保存草稿。相同清单再次运行时恢复已保存草稿。`--resume-draft` 可显式恢复完整标题相同的唯一草稿；不存在或重名时停止，不重新上传猜测。

支持旧参数方式：

```bash
uv run python -m scripts publish-video --title "路上怎样改变了一个人？" --content "正文" --video /path/to/video.mp4 --cover /path/to/cover.png --account "账号显示名称" --headless=false
```

旧参数方式没有清单的持久化重复提交保护，重复任务推荐使用清单。`--upload-timeout 600` 控制最长处理等待时间；成功信号出现即继续，不固定等满十分钟。

## 公开提交

先向用户展示账号、标题、正文、视频、封面与可见范围。用户明确授权后运行同一清单：

```bash
uv run python -m scripts publish-video --manifest /path/to/job.json --auto-publish --headless=false
```

授权只适用于这条笔记。不要用真实账号公开发布测试笔记来证明代码可用。已明确授权的同一次提交不重复询问。

用户通过客户端手动发布后，在本地记录：

```bash
uv run python -m scripts publish-video --manifest /path/to/job.json --record-published
```

命令不会操作账号，仅记录用户报告并阻止后续提交。线上是否公开可见、审核是否通过、视频是否能播放，需要另行读回验证。

## 状态与恢复边界

| 状态 | 含义 | 下一步 |
| --- | --- | --- |
| `preflight_ready` | 本地清单检查通过 | 可准备草稿 |
| `draft_saved` | 已保存浏览器本地草稿 | 可恢复后核对 |
| `confirmed` | 观察到平台提交成功信号 | 不再提交，必要时检查线上笔记 |
| `submitted_unconfirmed` | 已提交，结果无法确认 | 查看线上状态，禁止自动重试 |
| `recorded_published` | 用户报告已手动发布 | 不再自动提交 |
| `failed` / `error` | 输入、账号或页面条件未满足 | 查看具体错误，不能称为准备完成 |

清单旁的 `.state.json` 记录摘要、账号和任务状态。权威账本保存在当前 profile 目录下的 `publish-jobs/<指纹>.json`，按内容加锁；复制或重命名清单不会绕过已发布记录。默认 profile 位于 `~/.xiaohongshu/`，命名 profile 位于其 `profiles/<名称>/`。这些记录不保存认证信息。指纹包括标题、正文、标签、账号、profile、可见范围、定时、原创声明及视频/封面完整文件哈希。素材修改后必须新建清单并重新核对；文件位置变化但内容相同不影响指纹。

提交前写入 `submission_started`。如果浏览器崩溃，即使没有收到成功返回，也不能自动重试。准备过程异常时恢复原草稿；若实际上没有保存草稿，先检查草稿箱，在确认没有目标草稿且从未点击提交后处理本地状态。遗留锁也只能在确认原进程已结束后移除。不要将这些本地状态文件加入公共仓库。

## 页面适配与验证

当前适配包含新版发布控件、明确的视频上传状态、Tiptap 正文、独立封面编辑器以及精确标题草稿恢复。保存草稿通过 Chromium 协议识别闭合 shadow root 内的精确保存按钮，不能识别时停止，禁止按按钮位置猜测。自定义封面必须在编辑器中完成图片解码，保存后预览来源也必须发生变化。默认标签以普通 `#话题` 文本追加，不声称绑定平台话题实体。不要选取与内容无关的推荐话题，也不要自动添加平台活动。

草稿的视频远程预览可能与上传时的本地预览表现不同。预览加载失败不证明文件损坏；文件大小、文件头或上传成功也不证明线上播放正常。保留错误信息，避免自动反复上传。

验证用单元测试和本地浏览器页面覆盖关键操作；真实账号测试必须单独授权。公开发布及发布后播放未经实测时，应明确报告尚未验证。

## 本次设计取舍

- 保留原有浏览器和 JSON CLI，在原实现上修复实际失败路径，避免引入第二套发布服务。
- 用现有 Playwright 定位与有截止时间的条件等待替代逐字输入和固定长等待。
- 清单只负责输入与任务状态，页面交互继续归发布模块；不把账号凭据放进内容项目。
- 出错时报告具体阶段；恢复草稿和重新上传是不同操作，不能相互静默替代。
